## Definition

**Time Complexity** measures **how the running time of an algorithm grows as the input size (N) increases.**

> **Think:** It doesn't measure **actual seconds**, it measures **how work grows** when the input becomes larger.

---

# Why Time Complexity?

Suppose two programs solve the same problem.

Program A

```text
N = 100      → 0.001 sec

N = 1,000    → 0.01 sec

N = 10,000   → 0.1 sec
```

Program B

```text
N = 100      → 0.001 sec

N = 1,000    → 1 sec

N = 10,000   → 100 sec
```

Even though both work, **Program A scales much better**.

Time Complexity helps us compare algorithms independent of hardware or programming language.

---

# Big O Notation

Big O describes the **Worst-Case Time Complexity**.

Example

```cpp
for(int i = 0; i < n; i++)
{
    cout << i;
}
```

Runs **N** times.

Time Complexity

```text
O(N)
```

# O(2ᴺ)

Every problem creates **two more problems**.

Example

Naive Fibonacci

```cpp

}
```


Time


Very slow.

# Rules to Calculate Time Complexity

## Rule 1: Ignore Constants

```cpp
for(int i = 0; i < 2*n; i++)
```

Time

```
O(2N)
```

Simplify

```
O(N)
```

---

## Rule 2: Ignore Smaller Terms

```
O(N² + N + 100)
```

Largest term dominates.

Final

```
O(N²)
```

---

## Rule 3: Sequential Loops → Add

```cpp
for(...)
```

```cpp
for(...)
```

Time

```
O(N + N)
```

Final

```
O(N)
```

---

## Rule 4: Nested Loops → Multiply

```cpp
for(...)
{
    for(...)
    {

    }
}
```

Time

```
O(N × N)

=

O(N²)
```

---

## Rule 5: Different Variables

```cpp
for(i = 0; i < n; i++)
```

```cpp
for(j = 0; j < m; j++)
```

Time

```
O(N + M)
```

Nested

```cpp
for(i = 0; i < n; i++)
{
    for(j = 0; j < m; j++)
    {

    }
}
```

Time

```
O(N × M)
```

# Common Interview Questions

### Q1. What is Big O?

A notation that describes how an algorithm's running time grows as the input size increases, typically focusing on the worst case.

---

### Q2. Why ignore constants?

Because Big O measures **growth rate**, not exact execution time. As `N` becomes very large, constants become insignificant.

---

### Q3. Difference between `O(N)` and `O(log N)`?

- `O(N)` processes every element.
    
- `O(log N)` repeatedly reduces the problem size (usually by half), making it much faster for large inputs.
    

---

### Q4. Which is faster: `O(N log N)` or `O(N²)`?

`O(N log N)`.

Example for `N = 1000`:

- `N log₂N` ≈ **10,000**
    
- `N²` = **1,000,000**
    

---

### Q5. Why is Binary Search `O(log N)`?

Because each comparison eliminates **half of the remaining search space**.

---

### Q6. Can two `O(N)` algorithms have different speeds?

Yes. Big O ignores constants. One algorithm may perform 2N operations and another 100N operations, but both are still `O(N)`.

# Interview Summary

- **Time Complexity** measures how an algorithm's running time grows with input size.
    
- **Big O** usually represents the **worst-case** complexity.
    
- Ignore **constants** and **lower-order terms** when analyzing Big O.
    
- Sequential loops **add** complexities; nested loops **multiply** them.
    
- Recognize common patterns:
    
    - Array access → `O(1)`
        
    - Binary Search → `O(log N)`
        
    - Single traversal → `O(N)`
        
    - Nested loops → `O(N²)`
        
    - Merge Sort → `O(N log N)`
        
- The goal in interviews is often to improve from a higher complexity (e.g., `O(N²)`) to a lower one (e.g., `O(N log N)` or `O(N)`).
