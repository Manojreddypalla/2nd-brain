## Definition

**Recursion** is a technique where a **function calls itself** to solve a problem by breaking it into smaller subproblems.

> **Think:** "Instead of solving the whole problem, solve one small part and let the same function solve the rest."

---

# Why Use Recursion?

- Natural solution for hierarchical problems
    
- Simplifies complex algorithms
    
- Used extensively in:
    
    - Trees
        
    - Graphs
        
    - Divide & Conquer
        
    - Dynamic Programming
        
    - Backtracking
        

---

# Structure of Recursion

Every recursive function has **2 essential parts**:

### 1. Base Case

Stops the recursion.

### 2. Recursive Case

Calls itself with a smaller problem.

---

## Example

```cpp
int fact(int n)
{
    if(n == 0)
        return 1;       // Base Case

    return n * fact(n - 1); // Recursive Case
}
```

---

# How Recursion Works Internally

Example

```cpp
fact(3)
```

Call Stack

```text
main()
   │
fact(3)
   │
fact(2)
   │
fact(1)
   │
fact(0)
```

Now returns

```text
fact(0) = 1

fact(1) = 1 × 1 = 1

fact(2) = 2 × 1 = 2

fact(3) = 3 × 2 = 6
```

Output

```text
6
```

---

# Stack Memory Visualization

Each recursive call gets **its own stack frame**.

```text
Top
──────────────
fact(0)
──────────────
fact(1)
──────────────
fact(2)
──────────────
fact(3)
──────────────
main()
Bottom
```

As functions finish, the stack is popped.

# Recursive Thinking

Instead of asking:

> "How do I solve the entire problem?"

Ask:

> "Can I solve one step and trust recursion to solve the remaining smaller problem?"

This mindset is the key to recursion.

---

# Base Case Importance

Without a base case:

```cpp
void fun()
{
    fun();
}
```

The function never stops.

Result

```text
Stack Overflow
```

---

# Stack Overflow

Every recursive call consumes stack memory.

Too many calls:

```text
main()

↓

fun()

↓

fun()

↓

fun()

↓

fun()

↓

...
```

Eventually

```text
Stack Overflow Error
```

---

# Tail Recursion

Recursive call is the **last statement**.

```cpp
void print(int n)
{
    if(n == 0)
        return;

    cout << n;

    print(n - 1);
}
```

Some compilers may optimize tail recursion into iteration.

---

# Non-Tail Recursion

Work remains **after** the recursive call.

```cpp
void print(int n)
{
    if(n == 0)
        return;

    print(n - 1);

    cout << n;
}
```

Cannot generally be optimized into a loop.

---

# Direct vs Indirect Recursion

## Direct

Function calls itself.

```cpp
fun()
{
    fun();
}
```

---

## Indirect

Functions call each other.

```cpp
A()
{
    B();
}

B()
{
    A();
}
```

# Common Mistakes

## Missing Base Case

```cpp
fun(n)
{
    fun(n - 1);
}
```

Infinite recursion.

---

## Wrong Base Case

```cpp
if(n == 1)
```

But function reaches

```text
n = 0
```

Unexpected behavior.

---

## Problem Not Getting Smaller

Wrong

```cpp
fun(n);
```

Correct

```cpp
fun(n - 1);
```

Each recursive call must move **closer to the base case**.

# Common Interview Questions

### Q1. What is recursion?

A function calling itself to solve a problem by reducing it into smaller subproblems.

---

### Q2. What is the base case?

The stopping condition that prevents infinite recursion.

---

### Q3. Why does recursion cause stack overflow?

Each recursive call creates a new stack frame. If recursion doesn't stop (or is too deep), the call stack exceeds its limit.

---

### Q4. Difference between recursion and iteration?

- Recursion uses the call stack.
    
- Iteration uses loops.
    
- Iteration is generally more memory-efficient, while recursion can be more intuitive for recursive structures like trees.
    

---

### Q5. What is tail recursion?

A recursive function where the recursive call is the last operation performed.

---

### Q6. When should recursion be preferred?

When the problem is naturally recursive, such as:

- Trees
    
- Graph DFS
    
- Divide & Conquer
    
- Backtracking

# Interview Summary

- Recursion solves a problem by reducing it into smaller instances of itself.
    
- Every recursive function must have a **base case** and a **recursive case**.
    
- Each recursive call creates a **new stack frame**.
    
- Understand the flow using the **call stack**, not just the code.
    
- Missing or incorrect base cases lead to **stack overflow**.
    
- Tail recursion may be optimized by the compiler; non-tail recursion generally cannot.
    
- Learn to visualize **recursion trees** and **call stacks**—they are asked frequently in interviews.
    
- Many advanced topics (Trees, DFS, Backtracking, Divide & Conquer, DP) are built on recursion.
