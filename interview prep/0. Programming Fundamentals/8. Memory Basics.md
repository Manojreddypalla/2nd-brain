## Definition

**Memory** is the storage used by a program to hold **variables, objects, functions, and instructions** while it is running.

> **Think:** Memory is like a workspace where your program stores and retrieves data.

---

# Why Learn Memory?

Almost every interview topic depends on memory:

- Variables
    
- Functions
    
- Arrays
    
- Pointers
    
- References
    
- Linked Lists
    
- Trees
    
- Graphs
    
- Dynamic Programming
    
- Operating Systems
    

Understanding memory makes advanced topics much easier.

---

# Memory Layout of a Program

```text
High Address
────────────────────────
|       Stack          | ← Function Calls, Local Variables
────────────────────────
|         ↓            |
|     Free Memory      |
|         ↑            |
────────────────────────
|        Heap          | ← Dynamic Memory (new/malloc)
────────────────────────
| Data Segment         | ← Global & Static Variables
────────────────────────
| Code (Text Segment)  | ← Program Instructions
────────────────────────
Low Address
```

---

# Code Segment (Text Segment)

Stores:

- Program instructions
    
- Compiled machine code
    

Example

```cpp
int add(int a, int b)
{
    return a + b;
}
```

The instructions for `add()` are stored in the **Code Segment**.

Characteristics:

- Read-only
    
- Exists for entire program
    

---

# Data Segment

Stores:

- Global variables
    
- Static variables
    

Example

```cpp
int x = 10;

static int y = 20;
```

These exist from program start until program termination.

---

# Stack Memory

Stores:

- Local variables
    
- Function parameters
    
- Return addresses
    
- Function call information
    

Example

```cpp
void fun()
{
    int x = 5;
}
```

`x` is stored on the **stack**.

---

## Stack Visualization

```cpp
int main()
{
    int a = 10;

    fun();
}
```

```text
Top
──────────────
fun()

x = 5
──────────────
main()

a = 10
──────────────
Bottom
```

After `fun()` returns

```text
Top
──────────────
main()

a = 10
──────────────
Bottom
```

The stack frame of `fun()` is automatically removed.

# Heap Memory

Stores dynamically allocated memory.

Example

```cpp
int *ptr = new int(10);
```

Memory

```text
Stack                  Heap

ptr  ───────────────► 10
```

The pointer lives on the **stack**.

The actual integer lives on the **heap**.

---

# Stack vs Heap

|Stack|Heap|
|---|---|
|Automatic allocation|Manual allocation|
|Fast|Slower|
|Limited size|Larger size|
|Auto deallocation|Must free manually|
|Function variables|Dynamic objects|

---

# Dynamic Memory Allocation

Allocate memory during runtime.

```cpp
int *p = new int;
```

Array

```cpp
int *arr = new int[100];
```

Free memory

```cpp
delete p;

delete[] arr;
```

---

# Why Dynamic Memory?

Use when the size is not known at compile time.

Example

```cpp
int n;

cin >> n;

int *arr = new int[n];
```

---

# Pointer Basics

A pointer stores the **address** of another variable.

```cpp
int x = 10;

int *p = &x;
```

Memory

```text
Address      Value

1000         x = 10

2000         p = 1000
```

---

## Operators

Address-of

```cpp
&x
```

Returns memory address.

---

Dereference

```cpp
*p
```

Returns value stored at the address.

---

Example

```cpp
int x = 10;

int *p = &x;

cout << *p;
```

Output

```text
10
```

---

# References

A reference is another name (alias) for the same variable.

```cpp
int x = 10;

int &r = x;
```

Memory

```text
x
▲
│
r
```

No new memory is created for the referenced object.

---

# Pointer vs Reference

|Pointer|Reference|
|---|---|
|Stores address|Alias to variable|
|Can be nullptr|Cannot be null|
|Can change target|Cannot be reseated|
|Needs `*` to access|Used like normal variable|

---

# Null Pointer

A pointer pointing to nothing.

```cpp
int *p = nullptr;
```

Always initialize pointers to avoid undefined behavior.

---

# Dangling Pointer

Pointer refers to memory that is no longer valid.

```cpp
int *p = new int(5);

delete p;

// p is now dangling
```

Good Practice

```cpp
delete p;

p = nullptr;
```

---

# Memory Leak

Memory allocated but never released.

```cpp
int *p = new int(10);

// delete missing
```

Every call leaks memory.

Correct

```cpp
delete p;
```

---

# Wild Pointer

An uninitialized pointer.

Wrong

```cpp
int *p;

*p = 10;
```

`p` contains an unknown address.

Correct

```cpp
int *p = nullptr;
```

---

# Smart Pointers (Modern C++)

Modern C++ avoids manual memory management.

```cpp
unique_ptr<int> p = make_unique<int>(10);
```

Advantages:

- Automatic cleanup
    
- No memory leaks
    
- Exception safe
    

Common types:

- `unique_ptr`
    
- `shared_ptr`
    
- `weak_ptr`
    

---

# Heap vs Stack Example

```cpp
void fun()
{
    int x = 10;

    int *p = new int(20);
}
```

Memory

```text
Stack

x = 10

p ─────────────┐
               │
               ▼
Heap         20
```

When `fun()` ends

- `x` is destroyed.
    
- `p` is destroyed.
    
- Heap memory **remains allocated** unless `delete` is called.
    

This causes a **memory leak**.

# Common Interview Questions

### Q1. Difference between Stack and Heap?

|Stack|Heap|
|---|---|
|Automatic|Manual|
|Faster|Slower|
|Limited|Larger|
|Auto cleanup|Requires `delete` (or smart pointers)|

---

### Q2. What is a Memory Leak?

Memory allocated on the heap that is never released, making it unavailable for reuse.

---

### Q3. What is a Dangling Pointer?

A pointer that points to memory that has already been freed or gone out of scope.

---

### Q4. Difference between Pointer and Reference?

- Pointer stores an address and can be reassigned.
    
- Reference is an alias to an existing object and cannot be reseated.
    

---

### Q5. Why use Dynamic Memory?

When the amount of memory required is only known at runtime.

---

### Q6. Why are Smart Pointers preferred?

They automatically manage memory, reducing memory leaks and making code safer.

---

### Q7. Where are Global Variables stored?

In the **Data Segment**.

---

### Q8. Where are Local Variables stored?

On the **Stack**.

# Time & Space Complexity

|Operation|Time|Space|
|---|---|---|
|Stack allocation|`O(1)`|`O(1)`|
|Heap allocation (`new`)|`O(1)` average*|`O(1)`|
|`delete`|`O(1)` average*|`O(1)`|
|Pointer access|`O(1)`|`O(1)`|

> *The actual allocator implementation can make heap allocation/deallocation more expensive in some cases, but they're typically treated as constant-time for interview discussions.

---

# Interview Summary

- A program's memory is divided into **Code**, **Data**, **Heap**, and **Stack** segments.
    
- **Stack** stores local variables and function call information; it is automatically managed.
    
- **Heap** stores dynamically allocated memory and must be managed manually (or with smart pointers).
    
- A **pointer** stores an address; a **reference** is an alias to an existing variable.
    
- Understand `&` (address-of) and `*` (dereference).
    
- Know the difference between **null pointers**, **wild pointers**, and **dangling pointers**.
    
- Always release heap memory with `delete` (or better, use **smart pointers** in modern C++).
    
- Memory concepts are the foundation for linked lists, trees, graphs, STL containers, and many system-level interview questions.
