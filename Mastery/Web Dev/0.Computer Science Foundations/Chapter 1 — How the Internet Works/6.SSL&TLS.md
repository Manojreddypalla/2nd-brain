# SSL / TLS

> **Interview Importance:** ⭐⭐⭐⭐⭐
> 
> **One-line definition:** SSL/TLS are cryptographic protocols that **secure communication between a client and a server**.

---

# Full Forms

**SSL** = **Secure Sockets Layer**

**TLS** = **Transport Layer Security**

> **Important:** SSL is **obsolete**. Modern websites use **TLS**, but people still casually say "SSL certificate."

---

# Why Do We Need SSL/TLS?

Imagine sending your ATM PIN.

Without TLS

```text
You
   │
1234
   │
Internet
   │
Server
```

Anyone intercepting the traffic could potentially read it.

With TLS

```text
You
   │
A9F7X82K...
   │
Internet
   │
Server
```

Only the intended server can decrypt the data.

---

# What Problems Does TLS Solve?

TLS provides three essential security properties:

## 1. Confidentiality 🔒

Only the client and server can read the data.

Example:

- Passwords
    
- Credit card numbers
    
- API tokens
    

---

## 2. Integrity ✅

Ensures data isn't modified while traveling.

Example:

```text
Original

Pay ₹100
```

Attacker changes it to

```text
Pay ₹100000
```

TLS helps detect this kind of tampering.

---

## 3. Authentication 🪪

The browser verifies that it is talking to the real server.

Example:

```text
Browser

↓

Is this really github.com?

↓

Certificate Verified

↓

Continue
```

This helps prevent impersonation attacks.

# What is a Certificate?

A certificate is a **digital identity card** for a website.

It contains:

- Website name
    
- Public key
    
- Expiration date
    
- Certificate Authority (CA)
    
- Digital signature
    

Example:

```text
Certificate

Website: github.com

Issued By:

Let's Encrypt
```

The browser uses this to verify the server's identity.

---

# What is a Certificate Authority (CA)?

A **Certificate Authority** is a trusted organization that issues digital certificates.

Examples:

- Let's Encrypt
    
- DigiCert
    
- GlobalSign
    
- Sectigo
    

Browsers already trust many well-known CAs.

---

# Public Key & Private Key

TLS uses **asymmetric cryptography**.

```text
Server

Public Key
      │
Shared with everyone
      │
Private Key
      │
Secret
```

- **Public Key** → Encrypt or verify.
    
- **Private Key** → Decrypt or sign.
    

Only the server has the private key.

---

# Symmetric vs Asymmetric Encryption

## Asymmetric Encryption

- Two keys (public + private)
    
- More secure for exchanging secrets
    
- Slower
    

Used during the **TLS handshake**.

---

## Symmetric Encryption

- One shared secret key
    
- Very fast
    
- Used after the handshake
    

This is how most of the actual web traffic is encrypted.

# Cybersecurity Connection

TLS helps protect against:

- Packet sniffing
    
- Credential theft
    
- Man-in-the-Middle (MITM) attacks
    
- Session hijacking
    
- Data tampering in transit
    

It does **not** protect against vulnerabilities in the application itself, such as SQL injection or XSS.

# Interview Questions

### What is SSL?

**SSL (Secure Sockets Layer)** is the original protocol for securing web communication. It has been replaced by TLS.

---

### What is TLS?

**TLS (Transport Layer Security)** is the modern protocol that encrypts communication between clients and servers and authenticates the server using digital certificates.

---

### What is the difference between SSL and TLS?

|SSL|TLS|
|---|---|
|Older protocol|Modern replacement|
|Deprecated|Current standard|
|Insecure by today's standards|More secure and efficient|

---

### Why does HTTPS use TLS?

Because HTTP alone doesn't encrypt data. TLS adds encryption, integrity checks, and server authentication.
