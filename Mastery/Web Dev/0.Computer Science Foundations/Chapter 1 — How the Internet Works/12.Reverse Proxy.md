# Reverse Proxy

> **Interview Importance:** ⭐⭐⭐⭐⭐
> 
> **One-line definition:** A **Reverse Proxy** is a server that sits **in front of one or more backend servers**, receives client requests, and forwards them to the appropriate backend.

---

# Full Form

**Reverse Proxy**

- **Proxy** → Acts on behalf of someone else.
    
- **Reverse** → Acts on behalf of the **server**, not the client.
    

---

# First, What is a Proxy?

There are two types:

```text
Client ←→ Proxy ←→ Internet
```

This is a **Forward Proxy**.

```text
Client ←→ Reverse Proxy ←→ Server
```

This is a **Reverse Proxy**.

Remember:

- **Forward Proxy** hides the **client**.
    
- **Reverse Proxy** hides the **server**.
    

---

# Why Do We Need a Reverse Proxy?

Suppose your website has one backend server.

```text
Browser

↓

Node.js Server
```

Everyone directly accesses your backend.

Problems:

- No SSL handling
    
- No caching
    
- No compression
    
- Backend is directly exposed
    
- Hard to route traffic
    

---

# Solution

Place a Reverse Proxy in front.

```text
Browser

↓

Reverse Proxy

↓

Node.js
```

Now clients only know the Reverse Proxy.

They never talk directly to the backend.

---

# Real Flow

```text
Browser

↓

Reverse Proxy

↓

Backend Server

↓

Response

↓

Reverse Proxy

↓

Browser
```

The browser thinks it's talking to one server.

The Reverse Proxy quietly forwards everything.

---

# Real Example

Suppose your website has:

```text
/api

↓

Node.js
```

and

```text
/images

↓

Image Server
```

The Reverse Proxy routes requests.

```text
Browser

↓

Reverse Proxy

├── /api → Node.js

└── /images → Image Server
```

The browser still visits only:

```text
example.com
```

# Common Uses

## 1. SSL Termination ⭐

Instead of every backend handling HTTPS:

```text
Browser

↓

HTTPS

↓

Reverse Proxy

↓

HTTP

↓

Backend
```

The Reverse Proxy handles encryption.

Backends receive plain HTTP inside the trusted network.

---

## 2. Routing

```text
/api

↓

Backend A
```

```text
/auth

↓

Backend B
```

```text
/images

↓

Storage Server
```

One domain.

Many services.

---

## 3. Load Balancing

Reverse proxies like **Nginx** can distribute traffic.

```text
Reverse Proxy

↓

Server A

↓

Server B

↓

Server C
```

---

## 4. Caching

Suppose many users request:

```text
logo.png
```

Instead of asking the backend every time:

```text
Reverse Proxy

↓

Returns Cached File
```

Faster.

---

## 5. Compression

The Reverse Proxy can compress responses before sending them to clients, reducing bandwidth usage.

---

## 6. Security

Backend servers are hidden.

Clients only know:

```text
example.com
```

Not:

```text
10.0.0.15
```

# Reverse Proxy vs Load Balancer

This is a favorite interview question.

|Reverse Proxy|Load Balancer|
|---|---|
|Forwards requests to backend servers|Distributes traffic across servers|
|Can handle SSL, caching, compression, routing|Focuses on balancing traffic|
|May forward to one or many servers|Usually forwards to many servers|

Many products (like Nginx) can perform **both** roles.

---

# Reverse Proxy vs Forward Proxy

|Forward Proxy|Reverse Proxy|
|---|---|
|Represents the client|Represents the server|
|Client configures it|Server owner configures it|
|Used for privacy, filtering|Used for scalability, security, routing|

# 🧠 The Most Important Difference

Students often confuse these three:

```text
User
 │
 ▼
CDN
"Can I serve a cached copy?"

 │
 ▼
Load Balancer
"Which backend server should receive this request?"

 │
 ▼
Reverse Proxy
"I'll receive the request, apply SSL/routing/caching rules, and forward it."

 │
 ▼
Application Server
```

## Easy Memory Trick

- **CDN** → **Closest copy**
    
- **Load Balancer** → **Chooses the server**
    
- **Reverse Proxy** → **Front door of your backend**
    

---

## ⭐ Interview Tip

In small applications, **one Nginx server can act as both a Reverse Proxy and a Load Balancer**.

For example:

```text
Internet
    │
    ▼
Nginx
 ├── Terminates HTTPS
 ├── Routes /api to Backend A
 ├── Routes /auth to Backend B
 ├── Caches static files
 └── Load balances between multiple instances
```

So these concepts are **different responsibilities**, but a single piece of software can often perform several of them simultaneously.
