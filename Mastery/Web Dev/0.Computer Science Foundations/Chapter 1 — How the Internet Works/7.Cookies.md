# Cookies

> **Interview Importance:** ⭐⭐⭐⭐⭐
> 
> **One-line definition:** A **cookie** is a **small piece of data stored by the browser** that helps websites remember information about a user across multiple HTTP requests.

---

# Full Form

**Cookie** has **no full form**. It's simply called an **HTTP Cookie** or **Web Cookie**.

---

# Why Do We Need Cookies?

Remember:

> **HTTP is Stateless.**

That means:

```text
Request 1 → Server
Response 1

Request 2 → Server

Server doesn't automatically remember Request 1.
```

Without cookies, every request would look like it came from a completely new user.

Cookies solve this problem.

---

# Real-Life Example

Imagine a hotel.

Without cookies:

```text
You

↓

Room Service

↓

"Who are you?"
```

Every time.

With cookies:

```text
You

↓

Room Card

↓

"Oh, Room 205."
```

The room card acts like a cookie.

```text

↓

↓

```

The browser handles this automatically.

---

# Example

First request:

```http
GET /
```

Server responds:

```http
Set-Cookie:

sessionId=abc123
```

Browser stores:

```text
sessionId=abc123
```

Next request:

```http
GET /profile

Cookie:

sessionId=abc123
```

The browser automatically includes the cookie.

# Cookie Lifetime

## Session Cookie

Deleted when the browser closes.

Example:

```text
Login

↓

Close Browser

↓

Cookie Gone
```

---

## Persistent Cookie

Has an expiration date.

Example:

```text
Remember Me

↓

Expires After

30 Days
```

---

# Cookie Attributes (Important)

## HttpOnly

```text
JavaScript

↓

Cannot Read Cookie
```

Protects against some XSS attacks.

---

## Secure

Cookie is sent **only over HTTPS**.

---

## SameSite

Controls when cookies are sent across different websites.

Helps reduce CSRF attacks.

Common values:

- Strict
    
- Lax
    
- None
    

---

## Expiry

Determines how long the cookie lives.

# Cybersecurity Connection

Cookies are frequent security targets.

Common attacks:

- Cookie theft
    
- Session hijacking
    
- XSS
    
- CSRF
    

That's why attributes like **HttpOnly**, **Secure**, and **SameSite** are important.

---

# Cookies vs Sessions

|Cookies|Sessions|
|---|---|
|Stored in browser|Stored on server|
|Small amount of data|Larger user state|
|Browser sends automatically|Server retrieves using Session ID|
|Can persist after browser closes|Usually end when session expires|

**Important:** A cookie often contains only a **Session ID**, while the actual user information is stored in the session on the server.

# Interview Questions

### What is a cookie?

A small piece of data stored by the browser and automatically sent with future requests to the same website.

---

### Why are cookies needed?

Because **HTTP is stateless**, cookies allow websites to remember users and preferences across requests.

---

### Where are cookies stored?

In the user's browser.

---

### Are cookies secure?

They can be, when configured with:

- Secure
    
- HttpOnly
    
- SameSite
    

and used over HTTPS.

# 💡 Mental Model

Think of cookies as a **claim ticket** at a coat check.

```text
You arrive

↓

Give your coat

↓

Receive Ticket (Cookie)

↓

Come Back Later

↓

Show Ticket

↓

Get Your Coat
```

The **ticket isn't the coat**.

Similarly:

- The **cookie isn't your user data**.
    
- It often just contains a **Session ID** that tells the server which user session belongs to you.

### 🧠 One key idea to remember

**Cookies do not log you in.** They **help the browser identify you**. The server decides whether the cookie represents a valid, authenticated user. That's why the next topic—**Sessions**—fits perfectly: cookies identify the session, while the session stores the user's authenticated state.
