# gRPC

> **Interview Importance:** ⭐⭐⭐⭐☆
> 
> **One-line definition:** **gRPC** is a **high-performance Remote Procedure Call (RPC) framework** that allows one application to call functions on another application as if they were local functions.

---

# Full Form

**gRPC = gRPC Remote Procedure Calls**

> Originally, **gRPC** stood for **Google Remote Procedure Call**.
> 
> Today, the official meaning is simply **gRPC** (a recursive acronym: _gRPC Remote Procedure Calls_).

It was developed by Google.

---

# First Understand the Problem

Suppose you have two services.

```text
User Service

Order Service
```

The User Service needs user details.

With REST:

```text
User Service

↓

HTTP GET /users/101

↓

JSON

↓

User Service receives data
```

Lots of HTTP and JSON parsing.

---

# What is RPC?

RPC means:

> **Call a function on another computer as if it were a normal function.**

Example:

Instead of:

```http
GET /users/101
```

You write:

```cpp
User user = GetUser(101);
```

Looks like a local function.

Actually:

```text
Your Program

↓

Network

↓

Remote Server

↓

Executes GetUser()

↓

Returns Result
```

This is why it's called **Remote Procedure Call**.

# What are Protocol Buffers?

Instead of JSON:

```json
{
   "id":101,
   "name":"Manoj"
}
```

gRPC sends binary data.

```text
101001010101001...
```

Much smaller.

Much faster.

This binary format is called **Protocol Buffers (Protobuf)**.

---

# Why is gRPC Faster?

### REST

```text
JSON

↓

Large

↓

Need Parsing
```

### gRPC

```text
Binary

↓

Small

↓

Fast Parsing
```

Advantages:

- Smaller messages
    
- Lower bandwidth
    
- Faster serialization/deserialization
    
- Lower CPU usage

# Streaming (Huge Feature)

REST

```text
Request

↓

Response

↓

Done
```

gRPC supports streaming.

Client streaming:

```text
Client

↓↓↓

Server
```

Server streaming:

```text
Client

↑↑↑

Server
```

Bidirectional streaming:

```text
Client

⇄⇄⇄

Server
```

This makes gRPC excellent for real-time systems.

# REST vs GraphQL vs gRPC

|REST|GraphQL|gRPC|
|---|---|---|
|Many endpoints|Usually one endpoint|Remote function calls|
|JSON|JSON|Protocol Buffers (binary)|
|Human-readable|Human-readable|Not human-readable|

# Interview Questions

### What is gRPC?

A high-performance RPC framework that enables applications to call remote functions efficiently.

---

### What transport does gRPC use?

HTTP/2.

---

### What serialization format does gRPC use?

Protocol Buffers (Protobuf).

---

### Is gRPC faster than REST?

Generally **yes** for service-to-service communication because it uses HTTP/2 and compact binary serialization.

---

### Can browsers call gRPC directly?

Not traditional gRPC in most cases.

Browsers typically use REST, GraphQL, or **gRPC-Web**, which is designed to work with browsers.

## 🧠 Easy Memory Trick

- **REST** → "I access **resources**."
    
- **GraphQL** → "I ask for **exactly the fields** I need."
    
- **gRPC** → "I call a **remote function** as if it were local."
    

### When to use which?

- 🌐 **REST** → Most public web APIs and standard web applications.
    
- 📱 **GraphQL** → Frontends needing flexible data fetching.
    
- ⚡ **gRPC** → High-performance communication between backend services and microservices.
    

This comparison is a very common interview topic because it tests whether you understand **why** each technology exists, not just what it is.
