# Sessions

> **Interview Importance:** ⭐⭐⭐⭐⭐
> 
> **One-line definition:** A **session** is **server-side storage** that keeps information about a user between multiple HTTP requests.

---

# Full Form

**Session** has **no full form**.

---

# Why Do We Need Sessions?

Remember:

> **HTTP is Stateless**

```text
Request 1

↓

Server

↓

Response

Request 2

↓

Server

↓

"Who are you?"
```

The server forgets everything after sending a response.

Sessions solve this problem.

---

# Real-Life Example

Imagine visiting a hospital.

First visit:

```text
Reception

↓

Creates Patient File

↓

Gives Token #125
```

Next visit:

```text
Show Token #125

↓

Reception Finds Your File

↓

Doctor Knows Everything
```

The **patient file** is the **session**.

The **token** is like the **session ID stored in a cookie**.

# Next Request

```text
Browser

↓

Cookie

sessionID=ABC123

↓

Server

↓

Find Session ABC123

↓

User Found

↓

Response
```

The browser **doesn't send your user data**.

It sends only the **Session ID**.

# What is Stored in a Session?

Example:

```text
Session ID

↓

User ID

↓

Username

↓

Role

↓

Shopping Cart

↓

Permissions
```

All of this stays on the **server**.

# Session Storage

Common places:

- RAM
    
- Redis
    
- Database
    
- Memory Cache
    

Large applications often use Redis because it's fast and shared across servers.

# Logout

When you log out:

```text
Delete Session

↓

Delete Cookie

↓

Logged Out
```

The server removes the session, so the Session ID no longer works.

---

# Session Timeout

Sessions don't last forever.

Example:

```text
Login

↓

Inactive

30 Minutes

↓

Session Destroyed
```

If you return after the timeout, you'll need to log in again.

---

# Cookies vs Sessions

|Cookies|Sessions|
|---|---|
|Stored in browser|Stored on server|
|Small amount of data|Can store more user information|
|Browser manages storage|Server manages storage|
|Usually stores Session ID|Stores actual user state|

# Why Not Store Everything in Cookies?

Imagine storing:

```text
Username

Role

Permissions

Balance

Password
```

inside a cookie.

Problems:

- User could potentially inspect or tamper with it (unless protected).
    
- Cookies have size limits.
    
- Sensitive information should remain on the server.
    

Instead:

Browser

```text
SessionID=ABC123
```

Server

```text
ABC123

↓

Everything Else
```

Much safer.

# Cybersecurity Connection

Sessions are security-sensitive.

Common attacks:

- Session Hijacking
    
- Session Fixation
    
- Session Replay
    

Best practices:

- Use HTTPS.
    
- Use Secure and HttpOnly cookies.
    
- Regenerate Session IDs after login.
    
- Expire inactive sessions.

# Interview Questions

### What is a session?

A session is server-side storage that keeps user-specific information between multiple HTTP requests.

---

### Where is the session stored?

On the **server**.

---

### What is stored in the browser?

Usually only the **Session ID** inside a cookie.

---

### Why are sessions needed?

Because HTTP is stateless, sessions allow the server to remember authenticated users and other user-specific data.

# 💡 Mental Model

Think of a **hotel**:

```text
Reception

↓

Creates Room

↓

Gives Key Card
```

- **Room** = Session (stored by the hotel/server)
    
- **Key Card** = Session ID (stored in your browser cookie)
    

The hotel doesn't write all your booking details on the key card. The key card simply identifies which room (session) belongs to you.

## 🧠 Cookies + Sessions Together (The Most Important Concept)

This is the relationship many beginners miss:

```text
User Logs In
      │
      ▼
Server Creates Session
      │
      ▼
Session Stored on Server
      │
      ▼
Server Generates Session ID
      │
      ▼
Session ID Sent as Cookie
      │
      ▼
Browser Stores Cookie
      │
      ▼
Future Requests Automatically Include Cookie
      │
      ▼
Server Uses Session ID
      │
      ▼
Finds User Session
      │
      ▼
User Stays Logged In
```

**Remember this rule:**

- 🍪 **Cookie = "Who should I look up?"** (contains the Session ID)
    
- 🗂️ **Session = "Here's all the user's information."** (stored on the server)
    

This cookie → session relationship is one of the most frequently asked concepts in web development interviews.
