# Load Balancer

> **Interview Importance:** ⭐⭐⭐⭐⭐
> 
> **One-line definition:** A **Load Balancer** distributes incoming client requests across multiple servers so that no single server becomes overloaded.

---

# Full Form

**Load Balancer**

- **Load** → Incoming traffic/requests
    
- **Balancer** → Distributes that load evenly
    

---

# Why Do We Need a Load Balancer?

Imagine your website has **only one server**.

```text
           10,000 Users
                │
                ▼
         ┌────────────┐
         │  Server A  │
         └────────────┘
```

Problems:

- ❌ High CPU usage
    
- ❌ Slow responses
    
- ❌ Server crash
    
- ❌ Website goes down
    

---

# Solution

Instead of one server:

```text
              Users
                │
                ▼
        ┌────────────────┐
        │ Load Balancer  │
        └────────────────┘
           │      │      │
           ▼      ▼      ▼
      Server A Server B Server C
```

The Load Balancer shares the work.

---

# Real Example

Suppose:

1000 users open Netflix at the same time.

Without Load Balancer:

```text
1000 Users

↓

Server A

💥 Crash
```

With Load Balancer:

```text
1000 Users

↓

Load Balancer

↓

333 → Server A

333 → Server B

334 → Server C
```

Now every server handles only part of the traffic.

Step 1

```text

```

↓

```text

```

↓

```text
Load Balancer chooses server
```

↓

Step 4

```text

```

↓

```text

```

# Common Load Balancing Algorithms

## 1. Round Robin ⭐

Most common.

```text
Request 1 → Server A

Request 2 → Server B

Request 3 → Server C

Request 4 → Server A

Request 5 → Server B
```

Everyone gets turns.

---

## 2. Least Connections

Chooses the server with the fewest active connections.

```text
Server A → 120 Users

Server B → 40 Users

↓

Choose Server B
```

---

## 3. Least Response Time

Chooses the fastest server.

---

## 4. IP Hash

The same client IP is sent to the same server.

Useful for applications needing session affinity.

---

# Health Checks

Suppose:

```text
Server A

💥 Crashed
```

Load Balancer continuously checks:

```text
Are you alive?
```

If the server doesn't respond:

```text
Remove Server A

↓

Send traffic only to B and C
```

This increases availability.

# Load Balancer vs Reverse Proxy

Many beginners confuse these.

|Load Balancer|Reverse Proxy|
|---|---|
|Distributes traffic across multiple servers|Forwards requests to backend servers|
|Focuses on scalability and availability|Often handles SSL, caching, compression, routing|
|Can perform health checks|May also perform load balancing (e.g., Nginx)|

**Note:** Software like **Nginx** and **HAProxy** can act as both a reverse proxy and a load balancer.

---

# Load Balancer vs CDN

|CDN|Load Balancer|
|---|---|
|Caches and serves content close to users|Distributes requests among servers|
|Improves global delivery speed|Prevents backend overload|
|Usually handles static content|Handles application traffic|

# Interview Questions

### What is a Load Balancer?

A device or software that distributes incoming requests across multiple servers.

---

### Why use a Load Balancer?

- High availability
    
- Better scalability
    
- Prevent server overload
    
- Fault tolerance
    

---

### What happens if one server crashes?

The load balancer detects the failure through health checks and stops sending requests to that server.

---

### Can a Load Balancer perform SSL termination?

Yes.

It can decrypt HTTPS traffic and forward HTTP or HTTPS traffic to backend servers, depending on the architecture.

# 💡 Mental Model

Imagine three supermarket checkout counters.

Without a load balancer:

```text
100 Customers

↓

Counter 1

Huge Queue
```

Counters 2 and 3 are empty.

With a load balancer:

```text
100 Customers

↓

↓

Counter 1

Counter 2

Counter 3
```

The queue manager directs customers to the next available counter, keeping the workload balanced.

## 🧠 One Important Connection

It's easy to confuse **CDN**, **Load Balancer**, and **Reverse Proxy**.

Think of them like this:

```text
User
  │
  ▼
CDN
"Do I already have a cached copy?"
  │
  ▼
Load Balancer
"Which backend server should handle this request?"
  │
  ▼
Reverse Proxy
"Forward this request internally to the correct application."
  │
  ▼
Application Server
```

That's the mental model many engineers use:

- **CDN** → Brings content closer to users.
    
- **Load Balancer** → Chooses **which server** should handle the request.
    
- **Reverse Proxy** → Stands in front of backend servers and forwards requests, often adding features like SSL termination, routing, and caching.
