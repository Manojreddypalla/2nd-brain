# HTTP vs HTTPS

> **One-line definition:**
> 
> - **HTTP** = Transfers web data.
>     
> - **HTTPS** = HTTP secured with **TLS encryption**.
>     

---

# What is HTTP?

**HTTP (HyperText Transfer Protocol)** is the protocol browsers use to communicate with web servers.

Example:

```text
Browser
    │
HTTP Request
    │
Server
```

It defines **how requests and responses are exchanged**.

Example request:

```http
GET /index.html HTTP/1.1
Host: example.com
```

---

# What is HTTPS?

**HTTPS (HyperText Transfer Protocol Secure)** is simply:

```text
HTTP
   +
TLS Encryption
=
HTTPS
```

The communication is encrypted before it travels over the network.

---

# Why HTTPS Exists

Imagine logging into a website.

Without HTTPS:

```text
Username: manoj
Password: mypassword
```

Anyone intercepting the traffic on an insecure network could potentially read it.

With HTTPS:

```text
8F2A91D9AB72...
```

The intercepted data is encrypted and unreadable without the proper keys.

---

# HTTP vs HTTPS

|HTTP|HTTPS|
|---|---|
|Full Form: HyperText Transfer Protocol|HyperText Transfer Protocol Secure|
|Not encrypted|Encrypted using TLS|
|Port **80**|Port **443**|
|Less secure|Secure|
|No identity verification|Server authenticated using certificates|

# What Gets Encrypted?

HTTPS encrypts:

- Login credentials
    
- Payment information
    
- API requests
    
- Cookies
    
- Form data
    
- JSON responses
    

This protects the contents of the communication while it's traveling across the network.

---

# Is Everything Hidden?

Not completely.

An observer can usually still see things like:

- The destination IP address
    
- The fact that you're using HTTPS
    
- The amount of data transferred
    

But they **cannot read the encrypted request or response contents**.

# Cybersecurity Connection

HTTPS helps defend against:

- Credential theft
    
- Session hijacking
    
- Packet sniffing
    
- Data tampering during transit
    

It is a fundamental part of securing web communication.

---

# Interview Questions

### What is the difference between HTTP and HTTPS?

HTTP transfers web data without encryption.

HTTPS uses **TLS** to encrypt communication and authenticate the server.

---

### Does HTTPS use HTTP?

Yes.

HTTPS is **HTTP running over a secure TLS connection**.

---

### Which port does HTTPS use?

**443**

HTTP uses **80**.

---

### Is HTTPS enough to make a website secure?

**No.**

HTTPS protects **data in transit**. It does **not** automatically protect against:

- SQL Injection
    
- XSS
    
- Weak passwords
    
- Vulnerable server-side code
    
- Poor authentication logic
    

Those require secure application design.

# 💡 Mental Model

Think of sending a letter:

### HTTP

```text
You

↓

Open Postcard

↓

Mail Carrier

↓

Anyone can read it

↓

Recipient
```

### HTTPS

```text
You

↓

Locked Envelope

↓

Mail Carrier

↓

Carrier can deliver it

↓

Only recipient can open it
```

The mail system (HTTP) is the same—the difference is that HTTPS wraps the message in a **secure, encrypted envelope (TLS)** before sending it.
