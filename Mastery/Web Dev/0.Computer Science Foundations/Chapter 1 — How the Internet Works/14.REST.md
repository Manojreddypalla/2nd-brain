# REST (Representational State Transfer)

> **Interview Importance:** ⭐⭐⭐⭐⭐
> 
> **One-line definition:** REST is an **architectural style** for designing web APIs where clients interact with **resources** using standard HTTP methods.

---

# Full Form

**REST = Representational State Transfer**

Don't worry about memorizing the words.

Just remember:

> **REST is a set of rules for designing APIs.**

---

# First, What is an API?

Suppose your frontend wants user information.

```text
React

↓

Backend API

↓

Database
```

The frontend **doesn't access the database directly**.

It talks to an API.

---

# Why REST?

Imagine every company designed APIs differently.

GitHub:

```text
giveUser()
```

Amazon:

```text
fetchCustomer()
```

Netflix:

```text
loadPerson()
```

It would be chaos.

REST provides a **common pattern**.

---

# REST Thinks in Resources

Everything is a **resource**.

Examples:

```text
/users

/products

/orders

/posts

/comments
```

Notice:

REST APIs use **nouns**, not verbs.

✅ Good:

```text
/users
```

❌ Bad:

```text
/getUsers
```

---

# CRUD Operations

REST maps CRUD to HTTP methods.

|CRUD|HTTP Method|
|---|---|
|Create|POST|
|Read|GET|
|Update|PUT / PATCH|
|Delete|DELETE|

---

# Examples

## Read Users




## Update User

```http

```

---

## Delete User

```http

```

# JSON

REST usually exchanges data as JSON.

Example:

```json
{
  "id":101,
  "name":"Manoj"
}
```

---

# Stateless

REST is usually **stateless**.

Every request should contain everything the server needs.

Example:

```http
GET /profile

Authorization:

Bearer JWT
```

The server doesn't rely on remembering previous requests.

# GraphQL vs REST

REST:

```text
/users

/posts

/comments
```

Multiple endpoints.

GraphQL:

```text
/graphql
```

One endpoint.

Client specifies exactly what data it wants.

(You'll study GraphQL next.)

# Interview Questions

### What is REST?

REST is an architectural style for designing web APIs using HTTP methods and resources.

---

### Is REST a protocol?

❌ No.

REST is an **architectural style**.

HTTP is the protocol.

---

### What data format does REST use?

Usually JSON.

(It can also use XML or others, but JSON is the most common.)

---

### Why is REST stateless?

Each request should contain all the information needed to process it, without depending on previous requests.

## ⭐ The Most Important Concept

Many beginners think:

> **REST = API**

Not exactly.

The relationship is:

```text
HTTP
      │
      ▼
REST
      │
      ▼
API
```

- **HTTP** is the communication protocol.
    
- **REST** is a way of designing APIs using HTTP.
    
- **API** is the interface your application exposes.
    

So you can have:

- ✅ REST APIs
    
- ✅ GraphQL APIs
    
- ✅ gRPC APIs
    

They are all APIs, but they follow different designs or technologies.
