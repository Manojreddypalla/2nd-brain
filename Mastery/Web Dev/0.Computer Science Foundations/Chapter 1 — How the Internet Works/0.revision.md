# 1. Client–Server Architecture

## Definition

A computing model where a **Client** requests a service or resource and a **Server** processes the request and returns a response.

## Full Form

**Client** – Service Consumer  
**Server** – Service Provider

## Why was it created?

- To centralize data and services.
    
- To allow multiple users to access the same application.
    
- To separate frontend from backend logic.
    

## Problem it Solves

- Resource sharing
    
- Centralized management
    
- Scalability
    
- Security
    

## How It Works

```text
Client ----Request----> Server
Client <---Response---- Server
```

## Examples

- Browser → Web Server
    
- Mobile App → Backend API
    
- ATM → Bank Server
    
- ChatGPT → OpenAI Server
    

## Key Points

- Client initiates communication.
    
- Server waits for requests.
    
- Foundation of the Internet.
    

## Remember

> Client asks. Server answers.

## Related Topics

- HTTP
    
- REST
    
- Browser Journey

# 2. Request–Response Cycle

## Definition

The communication process where a client sends a request and the server processes it and returns a response.

## Full Form

None

## Why was it created?

To standardize communication between clients and servers.

## Problem it Solves

Provides a predictable communication model for web applications.

## Flow

```text
Client
   │
Request
   │
Server
   │
Processing
   │
Response
   │
Client
```

## Examples

- Loading a webpage
    
- Login request
    
- API request
    

## Key Points

- One Request → One Response
    
- Uses HTTP/HTTPS
    
- HTTP is Stateless
    

## Remember

Every webpage starts with a Request.

## Related Topics

- HTTP
    
- Browser Journey
    
- REST

# 3. Browser Journey

## Definition

The complete process from entering a URL until the webpage is displayed.

## Why was it created?

To efficiently locate, retrieve, and render web pages.

## Problem it Solves

Coordinates networking, security, and rendering into one seamless process.

## Complete Flow

```text
URL
 ↓
DNS
 ↓
TCP
 ↓
TLS
 ↓
HTTP Request
 ↓
Server
 ↓
HTTP Response
 ↓
HTML Parsing
 ↓
CSS & JS
 ↓
DOM
 ↓
Render
```

## Key Points

- Most common interview question.
    
- Combines networking + browser rendering.
    

## Remember

URL → DNS → TCP → TLS → HTTP → Render

## Related Topics

DNS, TCP/IP, HTTP, TLS

# 4. DNS

## Full Form

**Domain Name System**

## Definition

A distributed naming system that converts domain names into IP addresses.

## Why was it created?

Humans remember names better than IP addresses.

## Problem it Solves

Allows users to access websites using names instead of numeric IP addresses.

## Flow

```text
google.com

↓

142.xx.xx.xx
```

## Important Facts

- Port: **53**
    
- Distributed System
    
- Hierarchical
    
- Uses Cache
    

## Common Records

- A
    
- AAAA
    
- CNAME
    
- MX
    
- TXT
    

## Remember

DNS = Phonebook of the Internet.

## Related Topics

TCP/IP

## Problem it Solves

## Responsibilities

- Connection-Oriented
    
- Error Recovery
    

### IP

- Routing
    
- Packet Delivery

# 6. HTTP vs HTTPS

## Full Forms

HTTP → HyperText Transfer Protocol

HTTPS → HyperText Transfer Protocol Secure

## Definition

HTTP transfers web data.

HTTPS transfers encrypted web data using TLS.

## Why created?

HTTP

- Standard web communication
    

HTTPS

- Secure web communication
    

## Problem Solved

HTTPS protects against

- Packet Sniffing
    
- Data Tampering
    
- MITM attacks
    

## Comparison

|HTTP|HTTPS|
|---|---|
|Port 80|Port 443|
|No Encryption|TLS Encryption|
|Less Secure|Secure|

## Remember

HTTPS = HTTP + TLS

# 7. SSL / TLS

## Full Forms

SSL → Secure Sockets Layer

TLS → Transport Layer Security

## Definition

Protocols used to encrypt communication between client and server.

## Why created?

To secure data transmitted over networks.

## Problem Solved

- Eavesdropping
    
- MITM attacks
    
- Data Modification
    

## Provides

- Confidentiality
    
- Integrity
    
- Authentication
    

## Important

SSL is obsolete.

Modern websites use TLS.

## Remember

HTTPS works because of TLS.

Server-side storage that maintains user information across multiple requests.

## Why created?

To remember authenticated users.

## Problem Solved

Maintains user state.

## Stored Where?

Browser

```text
sessionId
```

Server

```text
User
Role
Cart
Permissions
```

Server stores Session.

# 10. JWT

## Full Form

JSON Web Token

## Definition

A digitally signed token used for authentication and authorization.

## Why created?

Stateless authentication.

## Problem Solved

No need for server-side session storage.

## Structure

```text
Header

Payload

Signature
```

## Important

- Payload is readable.
    
- Signature prevents tampering.
    
- Not encrypted by default.
    

## Never Store

- Password
    
- Credit Card
    
- Secrets
    

## Remember

JWT = Identity Card

## Problem Solved

- Reduced server load
    
- Global availability
    

## Stores

- CSS
    
- JS
    
- Videos
    
- Fonts
    

## Important

Cache Hit

Cache Miss

# 12. Load Balancer

## Definition

Distributes incoming requests across multiple servers.

## Why created?

Prevent server overload.

## Problem Solved

- Scalability
    
- High Availability
    
- Fault Tolerance
    

## Algorithms

- Round Robin
    
- Least Connections
    
- IP Hash
    

## Remember

# 13. Reverse Proxy

## Definition

A server that sits in front of backend servers and forwards requests.

## Why created?

Hide backend infrastructure and centralize request handling.

## Problem Solved

- SSL Termination
    
- Routing
    
- Caching
    
- Compression
    
- Security
    

## Common Software

- Nginx
    
- HAProxy
    
- Traefik
    
- Envoy
    

## Remember

Reverse Proxy = Front Door of Backend.

- Notifications
    
- Live Dashboards

# 16. GraphQL

## Definition

A query language for APIs that lets the client request exactly the required data.

## Why created?

REST often over-fetches or under-fetches data.

## Problem Solved

- Over-fetching
    
- Under-fetching
    

## Operations

- Query
    
- Mutation
    
- Subscription
    

## Remember

Client decides the response.

# 17. gRPC

## Full Form

gRPC Remote Procedure Calls

## Definition

A high-performance RPC framework for communication between services.

## Why created?

Fast backend-to-backend communication.

## Problem Solved

REST overhead in microservices.

## Uses

- HTTP/2
    
- Protocol Buffers
    

## Best For

- Microservices
    
- Kubernetes
    
- AI Serving
    
- Internal APIs
    

## Remember

REST = Resources

gRPC = Remote Function Calls
