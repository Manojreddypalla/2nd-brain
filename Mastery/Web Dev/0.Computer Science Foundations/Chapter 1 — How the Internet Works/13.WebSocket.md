# WebSocket

> **Interview Importance:** ⭐⭐⭐⭐☆
> 
> **One-line definition:** **WebSocket** is a protocol that provides a **persistent, full-duplex (two-way) communication channel** between a client and a server.

---

# Full Form

**WebSocket**

(It doesn't expand into multiple words; the protocol itself is called **WebSocket**.)

---

# Why Do We Need WebSocket?

Remember HTTP:

```text
Browser

↓

Request

↓

Server

↓

Response

↓

Connection Ends
```

Every time you need new data:

```text
Request

↓

Response

↓

Closed
```

This is inefficient for real-time applications.

---

# Example Problem

Imagine WhatsApp.

Without WebSocket:

```text
Every 1 second

↓

"Any new messages?"

↓

"No"

↓

Connection Closed

↓

Repeat
```

This wastes bandwidth and adds delay.

---

# Solution: WebSocket

Create **one connection**.

Keep it open.

```text
Browser

══════════════

Server
```

Now both sides can send messages anytime.

# What is Full-Duplex?

Full-duplex means:

```text
Client

⇄

Server
```

Both can:

- Send
    
- Receive
    

At the same time.

---

# How Does WebSocket Start?

Interestingly...

It starts as an **HTTP request**.

```text
Browser

↓

HTTP Request

↓

Upgrade

↓

WebSocket
```

The browser asks:

> "Can we upgrade this HTTP connection to WebSocket?"

If the server agrees:

```text
HTTP

↓

WebSocket
```

Now the connection stays open.

# DevOps Connection

Reverse proxies like **Nginx** must be configured to support WebSocket connections because they remain open for a long time.

Load balancers also need to support long-lived connections.

# Cybersecurity Connection

WebSocket connections should also use encryption.

```text
ws://
```

Normal WebSocket

```text

```

Secure WebSocket (uses TLS)

Always prefer **wss://** in production.

# HTTP vs WebSocket

|HTTP|WebSocket|
|---|---|
|Request → Response|Persistent connection|
|Client starts communication|Both client and server can send anytime|
|Connection usually closes after response|Connection stays open|
|Good for websites & REST APIs|Good for real-time apps|

# Interview Questions

### What is WebSocket?

A protocol that enables persistent, two-way communication between a client and a server.

---

### Why is WebSocket faster for chat?

Because it keeps one connection open instead of creating a new HTTP request for every message.

---

### Does WebSocket use TCP?

✅ Yes.

A WebSocket connection runs over TCP.

---

### Does WebSocket replace HTTP?

❌ No.

HTTP is still used for most web requests.

WebSocket is used when **real-time communication** is needed.

## ⭐ The Most Important Difference

Think of the three communication styles:

```text
HTTP
"Ask → Answer → Done"

↓

Polling
"Ask every second:
Anything new?"

↓

WebSocket
"Stay connected.
I'll tell you immediately when something happens."
```

### Easy Memory Trick

- **HTTP** → One conversation per request.
    
- **WebSocket** → One long conversation.
