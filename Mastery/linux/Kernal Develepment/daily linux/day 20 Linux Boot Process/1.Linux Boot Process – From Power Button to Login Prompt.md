# Linux Internals — Day 20

## Linux Boot Process

### 🎯 Goal

Understand what happens from pressing the **power button** until Linux gives you a **login screen/shell**.

```text
Power On
   ↓
BIOS / UEFI
   ↓
GRUB
   ↓
Linux Kernel
   ↓
initramfs
   ↓
systemd (PID 1)
   ↓
Services
   ↓
Login / Desktop
```

---

## 1. BIOS / UEFI

BIOS/UEFI is the **firmware** that runs before Linux.

### BIOS

**BIOS = Basic Input/Output System**

### UEFI

**UEFI = Unified Extensible Firmware Interface**

UEFI is the modern replacement for BIOS.

### What does it do?

When you press the power button:

```text
Power
 ↓
BIOS/UEFI
 ↓
Initialize basic hardware
 ↓
Find bootable device
 ↓
Start bootloader
```

It initializes things like:

- CPU
    
- RAM
    
- Storage devices
    
- Basic hardware
    

Then it searches for something bootable.

**Main idea:** BIOS/UEFI prepares the hardware and finds the bootloader.

---

# 2. GRUB — Bootloader

**GRUB = GNU GRand Unified Bootloader**

The Linux kernel exists as a file on disk, but it isn't running yet.

So something has to load it into RAM.

That's GRUB's job.

```text
GRUB
 ↓
Find Linux kernel
 ↓
Load kernel into RAM
 ↓
Load initramfs
 ↓
Pass kernel parameters
 ↓
Start kernel
```

GRUB also gives you the boot menu where you can choose:

- Linux
    
- Older kernels
    
- Recovery mode
    
- Another OS
    

### Kernel parameters

GRUB can pass information to the kernel, such as where the root filesystem is.

Check them with:

```bash
cat /proc/cmdline
```

**Main idea:** GRUB's job is to **load and start the Linux kernel**.

---

# 3. Linux Kernel

GRUB transfers control to the kernel.

Now Linux itself begins running.

The kernel initializes the core parts of the OS:

```text
Kernel
 ├── CPU
 ├── Memory management
 ├── Device drivers
 ├── Storage
 ├── Filesystems
 └── Process infrastructure
```

This connects directly to the Linux internals you've already learned.

For example:

```text
Memory → Kernel initializes memory management

Processes → Kernel provides process management

Devices → Kernel initializes drivers

Filesystem → Kernel prepares access to storage
```

But there's a problem.

Linux still needs to mount the real:

```text
/
```

root filesystem.

That's where **initramfs** comes in.

---

# 4. initramfs

**initramfs = Initial RAM Filesystem**

It's a small temporary filesystem loaded into RAM during boot.

Its main purpose is:

> Prepare everything necessary to mount the real root filesystem.

It may contain:

- Storage drivers
    
- Filesystem drivers
    
- LVM tools
    
- RAID tools
    
- Disk encryption tools
    

For example, if `/` is on an encrypted disk:

```text
Kernel starts
 ↓
initramfs starts
 ↓
Unlock encrypted disk
 ↓
Find root filesystem
 ↓
Mount /
```

After the real root filesystem is ready, the temporary initramfs environment is no longer needed for normal operation.

### Mental model

```text
initramfs = temporary toolkit

Real / = actual Linux filesystem
```

**Main idea:** initramfs helps Linux reach and mount the **real root filesystem**.

---

# 5. systemd — PID 1

Once the root filesystem is available, the kernel starts the first userspace process.

On most modern Linux distributions:

```text
systemd
```

gets:

```text
PID 1
```

Check it:

```bash
ps -p 1 -f
```

You should see systemd (sometimes via `/sbin/init`).

### Why PID 1?

Because systemd is the **first normal userspace process started by the kernel**.

Then systemd starts the rest of the system.

```text
Kernel
 ↓
systemd (PID 1)
 ├── Networking
 ├── Logging
 ├── SSH
 ├── Bluetooth
 ├── Other services
 └── Login/Display Manager
```

This connects to your earlier **process** topic:

```text
systemd PID 1
      ↓
other processes/services
```

---

# 6. systemd Targets

systemd uses **targets** to represent different system states.

Two important ones:

### multi-user.target

Normal multi-user system, typically without the graphical desktop.

Think:

```text
Terminal / Server
```

### graphical.target

Normal graphical system.

```text
Linux
 ↓
Services
 ↓
Display Manager
 ↓
Desktop
```

Check your default:

```bash
systemctl get-default
```

Desktop Linux will commonly return:

```text
graphical.target
```

---

# 7. Login

Finally, systemd starts the required login service.

You may get:

### Terminal

```text
login:
```

or a graphical login screen.

After authentication:

```text
Login
 ↓
User session
 ↓
Shell / Desktop
 ↓
Applications
```

Linux is now fully usable.

---

# Complete Boot Flow

This is the part worth remembering:

```text
Power Button
     ↓
BIOS / UEFI
Initialize hardware
     ↓
GRUB
Load kernel + initramfs
     ↓
Linux Kernel
Initialize CPU, memory, drivers, devices
     ↓
initramfs
Prepare and mount real /
     ↓
systemd
Starts as PID 1
     ↓
System Services
Networking, logging, etc.
     ↓
Login
     ↓
Shell / Desktop
```

# 💻 Commands

### Check current kernel

```bash
uname -r
```

`uname` → system information  
`-r` → kernel release

---

### Check PID 1

```bash
ps -p 1 -f
```

`-p 1` → select PID 1  
`-f` → full information

---

### Current boot logs

```bash
journalctl -b
```

`-b` → current boot.

Useful for seeing what happened while Linux was starting.

---

### Kernel messages

```bash
dmesg | less
```

Shows kernel messages such as:

```text
CPU detection
RAM
Storage
USB
Drivers
Network devices
```

---

### Boot time

```bash
systemd-analyze
```

Shows approximately how long boot stages took.

---

### Slow services

```bash
systemd-analyze blame
```

Shows services/units ordered by activation time.

Useful when investigating slow boot.

---

### Critical boot path

```bash
systemd-analyze critical-chain
```

Shows important dependencies that affected the boot path.

Think:

```text
A
↓
B
↓
C
↓
Login
```

If `B` is delayed, everything depending on it can also be delayed.

---

# 🧠 Important Questions

**What does BIOS/UEFI do?**  
Initializes basic hardware and finds the bootloader.

**Why do we need GRUB?**  
To load the Linux kernel and initramfs into memory and start the kernel.

**What does the kernel do?**  
Initializes core OS functionality such as memory, drivers, devices, processes and filesystems.

**Why is initramfs needed?**  
It provides the temporary environment needed to prepare and mount the real root filesystem.

**Why is systemd PID 1?**  
Because it is the first normal userspace process started by the kernel on systemd-based Linux.
