# TCP 3-Way Handshake & 4-Way Termination

## TCP Connection Lifecycle

TCP is a **connection-oriented protocol**.

A TCP connection has three main phases:

1. **Connection Establishment** → 3-Way Handshake
    
2. **Data Transfer**
    
3. **Connection Termination** → 4-Way Termination
    

---

# 1. TCP 3-Way Handshake

## Purpose

The **3-Way Handshake** establishes a reliable connection between a client and server before data transfer begins.

It confirms:

- Client can reach Server
    
- Server can reach Client
    
- Both sides agree on initial **Sequence Numbers**
    

## Flow

```text
Client                         Server
  |                              |
  | -------- SYN ------------->  |
  |                              |
  | <------ SYN + ACK ---------  |
  |                              |
  | -------- ACK ------------->  |
  |                              |
  |        ESTABLISHED           |
```

## Step 1 — SYN

**Client → Server**

```text
SYN
Seq = 100
```

- Client requests a connection.
    
- Client sends its Initial Sequence Number (ISN).
    

> "I want to connect."

---

## Step 2 — SYN-ACK

**Server → Client**

```text
SYN + ACK
Seq = 500
Ack = 101
```

- Server acknowledges the client's SYN.
    
- Server sends its own Initial Sequence Number.
    

> "I received your request, and I'm ready too."

---

## Step 3 — ACK

**Client → Server**

```text
ACK
Seq = 101
Ack = 501
```

Client acknowledges the server.

TCP state becomes:

```text
ESTABLISHED
```

Application data can now be transferred.

---

## Quick Memory

```text
SYN → SYN-ACK → ACK
```

Think:

```text
Request
   ↓
Accept + Request
   ↓
Accept
```

---

# 2. TCP 4-Way Termination

## Purpose

TCP termination safely closes an established connection.

TCP is **full-duplex**, meaning both sides can send data independently.

```text
Client --------> Server
Client <-------- Server
```

Therefore, each direction must be closed.

## Flow

```text
Client                         Server
  |                              |
  | -------- FIN ------------->  |
  |                              |
  | <------- ACK --------------  |
  |                              |
  | <------- FIN --------------  |
  |                              |
  | -------- ACK ------------->  |
  |                              |
  |           CLOSED             |
```

---

## Step 1 — FIN

**Client → Server**

```text
FIN
```

Client says:

> "I have finished sending data."

The client cannot send more application data, but it can still receive data.

---

## Step 2 — ACK

**Server → Client**

```text
ACK
```

Server acknowledges the FIN.

At this point:

```text
Client → Server  ❌
Server → Client  ✅
```

This is effectively a **half-closed connection**.

---

## Step 3 — FIN

**Server → Client**

When the server finishes sending its remaining data:

```text
FIN
```

Server says:

> "I am also finished sending."

---

## Step 4 — ACK

**Client → Server**

```text
ACK
```

Client acknowledges the server's FIN.

The TCP connection is now closed after the required state handling.

---

# Why 3-Way Handshake but 4-Way Termination?

## Connection Establishment

The server can combine:

```text
SYN + ACK
```

Therefore:

```text
SYN
 ↓
SYN + ACK
 ↓
ACK

= 3 steps
```

## Connection Termination

When the client sends `FIN`, the server may still have data to send.

Therefore the server first sends:

```text
ACK
```

and later:

```text
FIN
```

So normally:

```text
FIN
 ↓
ACK
 ↓
FIN
 ↓
ACK

= 4 steps
```

# Important TCP States

|State|Meaning|
|---|---|
|`LISTEN`|Server waiting for connections|
|`SYN_SENT`|SYN sent, waiting for SYN-ACK|
|`SYN_RECV`|SYN received|
|`ESTABLISHED`|Connection active|
|`FIN_WAIT_1`|FIN sent|
|`FIN_WAIT_2`|FIN acknowledged|
|`CLOSE_WAIT`|Peer closed; local application hasn't closed yet|
|`LAST_ACK`|Waiting for final ACK|
|`TIME_WAIT`|Waiting before completely removing connection|
|`CLOSED`|No connection|

# DevOps Troubleshooting

## Check TCP Connections

```bash
ss -tan
```

### `ss`

**Socket Statistics**

Used to inspect network sockets and TCP connection states.

Older alternative:

```bash
netstat -tan
```

Flags:

- `-t` → TCP
    
- `-a` → All sockets
    
- `-n` → Show numerical IP addresses/ports
    

---

## Common Problems

### Many `SYN_SENT`

```text
Client → SYN → Server
Client ← ??? ← Server
```

Client sent SYN but isn't receiving SYN-ACK.

Possible causes:

- Server down
    
- Firewall blocking traffic
    
- Wrong IP address
    
- Wrong port
    
- Routing/network problem
    
- Security Group / Network ACL issue
    

---

### Many `CLOSE_WAIT`

Remote side closed the connection, but the local application has not closed its socket.

Often indicates:

> Application/socket handling problem.

---

### Many `TIME_WAIT`

Many recently closed TCP connections.

Some `TIME_WAIT` connections are **normal**.

Large amounts may appear with:

- High traffic
    
- Short-lived connections
    
- Frequent HTTP connections
    
- Poor connection reuse

# DevOps Interview Points

**Why does TCP use a 3-way handshake?**

To verify bidirectional communication and synchronize sequence numbers.

**Why does TCP termination usually require 4 steps?**

Because TCP is full-duplex and each direction is closed independently.

**What does `SYN_SENT` indicate?**

The machine sent a connection request and is waiting for `SYN-ACK`.

**What does `CLOSE_WAIT` indicate?**

The remote side closed the connection, but the local application has not yet closed its socket.

**Is `TIME_WAIT` an error?**

No. It is a normal part of TCP connection termination, although unusually large numbers can become operationally relevant.
