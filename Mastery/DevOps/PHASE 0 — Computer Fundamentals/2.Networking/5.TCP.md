# Topic 5 — TCP (Transmission Control Protocol)

> **Interview Importance:** ⭐⭐⭐⭐⭐

# What is TCP?

## Full Form

**Transmission Control Protocol**

TCP is a **connection-oriented**, **reliable** transport layer protocol.

Think of TCP like a **registered courier service**.

```text
You send a package
        ↓
Courier confirms pickup
        ↓
Tracks every package
        ↓
Receiver signs after delivery
```

TCP works similarly.

---

# Why do we need TCP?

Suppose you're downloading a **2 GB Linux ISO**.

Without TCP:

```text
Packet 1 ✔
Packet 2 ✔
Packet 3 ❌ Lost
Packet 4 ✔
Packet 5 ✔
```

The downloaded file becomes corrupted.

TCP solves this by ensuring:

- Reliable delivery
    
- Correct order
    
- No missing packets
    
- Error detection
    
- Retransmission
    

---

# Where TCP is used

Almost every important Internet application:

- HTTP

- SMTP

- PostgreSQL
    
- Kubernetes API Server
    
- Docker Registry
    
- Git over HTTPS
    

If losing data is unacceptable, TCP is usually the right choice.

# TCP Characteristics

### 1. Connection-Oriented

Before sending data, TCP establishes a connection.

```text
Client
   │
   │  Connect
   ▼
Server
```

This happens using the **3-way handshake** (our next topic).

---

### 2. Reliable

Every packet has a **sequence number**.

Example:

```text
Packet 1

Packet 2

Packet 3

Packet 4
```

If Packet 3 is lost:

```text
1 ✔

2 ✔

3 ❌

4 ✔
```

TCP notices the missing sequence number and requests retransmission.

---

### 3. Ordered Delivery

Packets may arrive out of order.

Example:

```text
Sent

1
2
3
4
```

Network delivers

```text
1
4
2
3
```

TCP rearranges them before giving them to the application.

Application receives:

```text
1
2
3
4
```

---

### 4. Error Detection

Each TCP segment includes a **checksum**.

If data is corrupted:

```text
Packet

↓

Checksum fails

↓

Discard packet

↓

Request retransmission
```

---

### 5. Flow Control

Imagine:

```text
Fast Sender

↓

Slow Receiver
```

If the sender keeps transmitting at full speed, the receiver's buffer will overflow.

TCP prevents this by allowing the receiver to advertise how much data it can accept (the **receive window**).

---

### 6. Congestion Control

This is different from flow control.

Flow control protects the **receiver**.

Congestion control protects the **network**.

If routers become overloaded:

```text
Network Busy

↓

TCP automatically slows down
```

This helps prevent congestion collapse.

---

# TCP Segment Structure

Simplified:

```text
+---------------------------+
| Source Port               |
| Destination Port          |
| Sequence Number           |
| Acknowledgment Number     |
| Flags (SYN ACK FIN RST)   |
| Window Size               |
| Checksum                  |
| Data                      |
+---------------------------+
```

Important fields:

- Source Port
    
- Destination Port
    
- Sequence Number
    
- ACK Number
    
- Window Size
    
- Flags

# Common Interview Questions

### Why is TCP reliable?

Because it uses:

- Sequence numbers
    
- Acknowledgments
    
- Retransmissions
    
- Checksums
    
- Flow control
    
- Congestion control
    

---

### Difference between TCP and UDP?

|TCP|UDP|
|---|---|
|Connection-oriented|Connectionless|
|Reliable|Best effort|
|Ordered|Unordered|
|Retransmits lost packets|No retransmission|
|Slower|Faster|

---

### Why is TCP slower than UDP?

Because TCP performs:

- Connection establishment
    
- Acknowledgments
    
- Retransmissions
    
- Flow control
    
- Congestion control
    

UDP skips all of these for speed.

---

### Why does HTTP use TCP?

A web page cannot tolerate missing or corrupted data. TCP guarantees reliable, ordered delivery.

## Easy way to remember

Think of TCP as a **professional courier service**:

- 📦 Numbers every package (sequence numbers)
    
- ✅ Gets delivery confirmation (ACKs)
    
- 🔁 Resends lost packages (retransmission)
    
- 📋 Delivers in the correct order
    
- 🚦 Slows down when the road (network) is congested
