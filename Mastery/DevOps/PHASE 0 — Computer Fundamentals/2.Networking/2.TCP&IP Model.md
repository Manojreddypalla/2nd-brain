# TCP/IP Model (DevOps Edition)

## Intuition

The **OSI model** is like learning anatomy in biology.

The **TCP/IP model** is the actual human body.

In interviews, you'll hear people say:

> "The packet goes through the TCP/IP stack."

Almost nobody says

> "The packet goes through the OSI stack."

---

# Why does TCP/IP exist?

Imagine you want to send

```
Hello
```

from your laptop to a server.

Many questions arise:

- Which application sent it?
- Which computer should receive it?
- How does it travel across the Internet?
- What if the packet gets lost?

TCP/IP divides these responsibilities into layers.

---

# TCP/IP Layers

```
+----------------------+
| Application          |
+----------------------+
| Transport            |
+----------------------+
| Internet             |
+----------------------+
| Network Access       |
+----------------------+
```

Only **4 layers**, compared to OSI's 7.

---

# Layer 1 — Application Layer

Responsible for communication between applications.

Protocols:

- HTTP
- HTTPS
- SSH
- FTP
- DNS
- SMTP
- MQTT

Examples

```
Chrome
curl
Postman
Nginx
Docker Client
kubectl
```

DevOps examples

```
curl https://google.com

kubectl get pods

docker pull nginx
```

All of these begin at the Application Layer.

---

# Layer 2 — Transport Layer

Responsible for communication between applications.

Protocols

- TCP
- UDP

Responsibilities

- Reliability
- Packet ordering
- Error checking
- Ports

Example

```
Chrome

↓

TCP

↓

Server Port 443
```

---

# Layer 3 — Internet Layer

Responsible for

```
Finding the destination computer.
```

Protocol

```
IP
```

This is where routing happens.

Routers only care about

```
IP Address
```

Example

```
192.168.1.10

↓

142.250.xxx.xxx
```

---

# Layer 4 — Network Access Layer

Responsible for

Moving packets over the local network.

Protocols

- Ethernet
- WiFi
- ARP

Uses

- MAC Address
- Frames

---

# OSI vs TCP/IP

|OSI|TCP/IP|
|---|---|
|Application|Application|
|Presentation|Application|
|Session|Application|
|Transport|Transport|
|Network|Internet|
|Data Link|Network Access|
|Physical|Network Access|

Notice:

OSI's **Presentation** and **Session** layers don't exist separately in TCP/IP—they're effectively part of the Application Layer.

# Real Packet Journey

Suppose you run

```
curl https://example.com
```

Internally:

```
curl
(Application)

↓

HTTPS

↓

TCP

↓

IP

↓

Ethernet

↓

Wire

↓

Router

↓

Internet

↓

Server
```

At every layer, more information is added.

```
HTTP Data

↓

TCP Header

↓

IP Header

↓

Ethernet Header
```

This process is called **encapsulation**.

The server removes these headers in reverse order (**decapsulation**).

# Common Interview Questions

### Why is TCP/IP more important than OSI?

Because TCP/IP is the protocol suite actually used on the Internet, while OSI is primarily a conceptual model for understanding and troubleshooting networks.

---

### Which TCP/IP layer uses IP?

**Internet Layer.**

---

### Which TCP/IP layer uses TCP?

**Transport Layer.**

---

### Where does HTTP belong?

**Application Layer.**

---

### Where does Ethernet belong?

**Network Access Layer.**

---

# Quick Revision

|Layer|Protocols|Responsibility|
|---|---|---|
|Application|HTTP, HTTPS, DNS, SSH|User applications|
|Transport|TCP, UDP|Reliable communication, ports|
|Internet|IP|Routing packets between networks|
|Network Access|Ethernet, Wi-Fi, ARP|Local network communication|

---

## Mental Model

Think of the TCP/IP stack as a delivery system:

```
Application
"I wrote a letter."

↓

Transport
"I'll package it and track it."

↓

Internet
"I'll decide which city it goes to."

↓

Network Access
"I'll drive it to the next post office."
```

Each layer focuses on one job, making the whole system modular and scalable.
