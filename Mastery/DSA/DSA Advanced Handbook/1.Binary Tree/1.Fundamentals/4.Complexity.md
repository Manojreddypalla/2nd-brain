# 🌳 Binary Tree Fundamentals — Complexity

Understanding complexity helps you quickly estimate the efficiency of operations on a binary tree. In interviews and GATE, you're often asked:

- _What is the time complexity of searching in a binary tree?_
    
- _Why is a balanced tree faster than a skewed tree?_
    
- _How much space does recursion use?_
    

---

# Time Complexity vs Space Complexity

## Time Complexity

Measures **how much time** an algorithm takes as the number of nodes (`n`) increases.

Example:

```text
n = 10      → Fast
n = 1000    → Slower
n = 100000  → Much Slower
```

---

## Space Complexity

Measures **how much extra memory** an algorithm uses.

Memory comes from:

- Recursion stack
    
- Queue
    
- Stack
    
- Extra arrays/maps
    

---

# Basic Binary Tree Operations

Assume `n` = Number of nodes

|Operation|Time Complexity|
|---|--:|
|Visit a node|O(1)|
|Insert (general binary tree)|Depends on implementation|
|Delete (general binary tree)|Depends on implementation|
|Search|O(n)|
|Traversal|O(n)|

---

## Why Search is O(n)

Consider

```text
        A
       / \
      B   C
     / \
    D   E
```

Searching for **E**:

```text
A → B → D → E
```

Worst case:

You may visit every node.

```
Time = O(n)
```

Unlike a BST, a normal Binary Tree has **no ordering**, so you cannot eliminate half the tree during search.

# Space Complexity of BFS

BFS stores nodes in a queue.

Maximum queue size equals the **widest level**.

Worst case:

```
O(n)
```

Example

```text
          A
        /   \
       B     C
      / \   / \
     D  E  F  G
```

The queue may contain:

```
D E F G
```

Many nodes simultaneously.

---

# Important Observation

Most Binary Tree algorithms follow:

```
Visit each node exactly once

↓

Time = O(n)
```

The main difference lies in **space complexity**.

- DFS → Depends on tree height.
    
- BFS → Depends on tree width.

# 🌲 DFS vs 🌳 BFS (Overview)

Both are tree traversal techniques but explore the tree in different ways.

---

# What is DFS?

**Depth First Search** explores a branch as deeply as possible before backtracking.

Example

```text
        A
       / \
      B   C
     / \
    D   E
```

Preorder DFS

```
A → B → D → E → C
```

It keeps going deeper before returning.

---

# What is BFS?

**Breadth First Search** explores the tree **level by level**.

Example

```text
        A
       / \
      B   C
     / \
    D   E
```

BFS Order

```
A → B → C → D → E
```

It finishes one level before moving to the next.

# Why?

### DFS

When you go to a child, you need to **remember where you came from**.

A stack naturally supports this.

---

### BFS

Nodes are processed **in the order they are discovered**.

A queue naturally maintains that order.

# When to Use DFS

Choose DFS when you need:

- Height of a tree
    
- Diameter
    
- Path Sum
    
- Lowest Common Ancestor
    
- Maximum Path Sum
    
- Tree DP
    
- Recursive tree problems
    

DFS naturally solves problems where answers depend on **subtrees**.

---

# When to Use BFS

Choose BFS when you need:

- Level Order Traversal
    
- Zigzag Traversal
    
- Left View
    
- Right View
    
- Top View
    
- Bottom View
    
- Vertical Order
    
- Maximum Width
    

BFS naturally solves problems involving **levels**.

---

# Quick Comparison

|Feature|DFS|BFS|
|---|---|---|
|Full Form|Depth First Search|Breadth First Search|
|Explores|One branch completely|One level completely|
|Data Structure|Stack / Recursion|Queue|
|Time Complexity|O(n)|O(n)|
|Space Complexity|O(h)|O(n)|
|Best For|Recursive subtree problems|Level-based problems|
|Examples|Height, Diameter, LCA|Level Order, Views, Width|
