# 🌳 Binary Tree Fundamentals — Types of Binary Trees

Understanding the **types of binary trees** is one of the most important fundamentals for interviews, GATE, and competitive programming. Many problems explicitly mention a tree type (e.g., _Complete Binary Tree_ or _Balanced Binary Tree_), and the solution often depends on its properties.

---

# 1. Full Binary Tree

## Definition

A **Full Binary Tree** is a binary tree in which **every node has either 0 or 2 children**.

- No node has exactly one child.
    
- Every internal node has two children.
    
- Leaf nodes have zero children.
    

---

## Valid Example

```text
          A
         / \
        B   C
       / \ / \
      D  E F  G
```

Every node has either:

- 2 children (A, B, C)
    
- 0 children (D, E, F, G)
    

✅ Full Binary Tree

---

## Another Valid Example

```text
        A
       / \
      B   C
         / \
        D   E
```

A → 2 children

C → 2 children

B, D, E → 0 children

Still Full.

---

## Invalid Example

```text
        A
       /
      B
```

A has only **one child**.

❌ Not Full.

---

## Properties

- Every internal node has exactly two children.
    
- Nodes have degree **0 or 2 only**.
    
- Easy to recognize because there are **no single-child nodes**.
    

---

## Memory Trick

```text
Full

Either

0 children

OR

2 children

Never 1
```

---

# 2. Complete Binary Tree

## Definition

A **Complete Binary Tree** is a tree where:

1. Every level is completely filled **except possibly the last**.
    
2. The last level is filled **from left to right**.
    

---

## Valid Example

```text
          A
         / \
        B   C
       / \ /
      D  E F
```

Levels

```text
Level 1

A

Level 2

B C

Level 3

D E F
```

The last level is filled from left to right.

✅ Complete

---

## Another Valid Example

```text
          A
         / \
        B   C
       /
      D
```

Still Complete.

---

## Invalid Example

```text
          A
         / \
        B   C
         \  /
          E F
```

There is a gap on the left before E.

❌ Not Complete.

---

## Properties

- Last level may be incomplete.
    
- Filling always starts from the left.
    
- Used by **Heaps**.
    

---

## Memory Trick

```text
Complete

Fill

Left

↓

Right
```

Think of filling seats in a classroom.

---

# 3. Perfect Binary Tree

## Definition

A **Perfect Binary Tree** is a tree where:

- Every internal node has exactly two children.
    
- All leaf nodes are at the same level.
    

---

## Example

```text
          A
         / \
        B   C
       / \ / \
      D E F G
```

All leaves are on the last level.

Every internal node has two children.

✅ Perfect

---

## Invalid Example

```text
          A
         / \
        B   C
       /
      D
```

Leaves are at different levels.

❌ Not Perfect

---

## Properties

Height = h

Number of nodes

```text
2^h − 1
```

Number of leaf nodes

```text
2^(h−1)
```

---

## Memory Trick

```text
Perfect

Everything is completely filled.
```

---

# 4. Balanced Binary Tree

## Definition

A binary tree is **Balanced** if for every node,

```text
|Height(Left) − Height(Right)| ≤ 1
```

---

## Balanced Example

```text
          A
         / \
        B   C
       / \
      D   E
```

Height difference never exceeds 1.

✅ Balanced

---

## Another Balanced Example

```text
      A
     /
    B
```

Difference = 1

Still Balanced.

---

## Unbalanced Example

```text
      A
     /
    B
   /
  C
 /
D
```

Difference is much greater than 1.

❌ Not Balanced

---

## Why Important?

Searching becomes faster.

Balanced Trees include

- AVL Tree
    
- Red-Black Tree
    

---

## Memory Trick

```text
Balanced

Left Height

≈

Right Height
```

---

# 5. Degenerate Binary Tree

## Definition

A **Degenerate Binary Tree** is a tree where every node has only one child.

It behaves like a linked list.

---

## Example

```text
A
 \
  B
   \
    C
     \
      D
```

Every node has one child.

✅ Degenerate

---

## Another Example

```text
      A
     /
    B
   /
  C
 /
D
```

Also Degenerate.

---

## Properties

- Height = Number of nodes
    
- Worst-case searching
    
- Traversals become O(n)
    

---

## Memory Trick

```text
Degenerate

Tree

↓

Linked List
```

---

# 6. Skewed Binary Tree

A **Skewed Binary Tree** is a special case of a degenerate tree where every node leans entirely to one side.

---

## Left Skewed

```text
      A
     /
    B
   /
  C
 /
D
```

Every node has only a left child.

---

## Right Skewed

```text
A
 \
  B
   \
    C
     \
      D
```

Every node has only a right child.

---

## Properties

- Height = Number of nodes
    
- Worst-case recursion depth
    
- Worst-case search time
    

---

## Memory Trick

```text
Skewed

All Left

OR

All Right
```

---

# Relationship Between These Trees

## Full vs Perfect

```text
Perfect

↓

Always Full
```

Every Perfect Tree is Full.

But every Full Tree is **not** Perfect.

Example

```text
        A
       / \
      B   C
         / \
        D   E
```

Full

✔

Perfect

✘

---

## Perfect vs Complete

```text
Perfect

↓

Always Complete
```

Every Perfect Tree is Complete.

But every Complete Tree is not Perfect.

---

## Complete vs Full

Neither implies the other.

Example

Complete but not Full

```text
          A
         / \
        B   C
       /
      D
```

Example

Full but not Complete

```text
          A
         / \
        B   C
           / \
          D   E
```

---

## Degenerate vs Skewed

Every Skewed Tree is Degenerate.

Not every Degenerate Tree is strictly Left-Skewed or Right-Skewed.

Example

```text
      A
     /
    B
     \
      C
     /
    D
```

Every node has one child, so it's Degenerate, but it alternates directions, so it's neither Left-Skewed nor Right-Skewed.

---

# Comparison Table

|Type|Condition|Shape|Key Property|
|---|---|---|---|
|**Full**|Every node has 0 or 2 children|Any|No node has exactly one child|
|**Complete**|Last level filled left to right|Nearly full|Used in Heaps|
|**Perfect**|Full + all leaves at same level|Completely filled|Total nodes = (2^h - 1) (for height measured in levels)|
|**Balanced**|Height difference ≤ 1 at every node|Nearly symmetric|Efficient operations|
|**Degenerate**|Every node has exactly one child|Linked list|Worst-case height|
|**Skewed**|Degenerate leaning one side|Left or Right|Extreme imbalance|

# 🎯 Interview Questions

You should now be able to answer these quickly:

- ✅ What is the difference between a **Full** and a **Complete** Binary Tree?
    
- ✅ Why is every **Perfect** Binary Tree also **Full** and **Complete**?
    
- ✅ Can a tree be **Complete but not Full**? (Yes)
    
- ✅ Can a tree be **Full but not Complete**? (Yes)
    
- ✅ Can a tree be **Balanced but not Complete**? (Yes)
    
- ✅ What is the worst-case height of a **Degenerate** or **Skewed** Binary Tree? (Linear in the number of nodes, (O(n)))
