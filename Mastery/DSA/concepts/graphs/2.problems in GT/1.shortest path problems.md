# What is the Shortest Path Problem?

The **Shortest Path Problem** asks:

> Given a graph, find the minimum-cost path from one node (source) to another node (destination).

The "cost" can represent:

- Distance
- Time
- Money
- Fuel
- Network latency
- Number of edges (in unweighted graphs)

---

# Example

```
A ----3----> B ----4----> D ----5----> F
 \                              |
  \                             |
   6                            2
    \                           |
     > C --------11-----------> G
```

Suppose we want to go

```
Source = A

Destination = G
```

Possible paths

```
A → C → G

Cost = 6 + 11 = 17
```

```
A → B → D → G

Cost = 3 + 4 + 2 = 9
```

Shortest path

```
A → B → D → G

Cost = 9
```

# Important Terminology

## Source

The node where the journey starts.

Example

```
A
```

---

## Destination

The node where we want to reach.

Example

```
H
```

---

## Path

A sequence of connected vertices.

Example

```
A → B → D → G → H
```

---

## Path Cost

The sum of all edge weights.

Example

```
A → B → D

3 + 4 = 7
```

---

## Edge Weight

A value assigned to an edge.

It can represent

- Distance
- Time
- Cost
- Risk

Example

```
A --5--> B
```

Weight = 5

# Types of Graphs

## 1. Unweighted Graph

Every edge has equal cost.

Example

```
A ---- B

|

C
```

Every edge costs

```
1
```

Shortest path means

> Minimum number of edges.

---

## 2. Weighted Graph

Edges have different costs.

Example

```
A --2--> B

A --8--> C
```

Shortest path means

> Minimum total weight.

---

# Positive and Negative Weights

Positive Edge

```
A --5--> B
```

Negative Edge

```
A --(-3)--> B
```

Negative edges reduce total path cost.

Some algorithms cannot handle negative weights.

---

# Negative Cycle

A cycle whose total weight is negative.

Example

```
A → B = 3

B → C = -6

C → A = 1
```

Total

```
3 - 6 + 1 = -2
```

Since the cost decreases every loop,

you could keep going around forever and make the path cost smaller and smaller.

Therefore,

**there is no finite shortest path.**

---

# Categories of Shortest Path Problems

## Single Source Shortest Path (SSSP)

Find the shortest path from one source to every other vertex.

Example

```
Source = A

Find

A → B

A → C

A → D

A → E
```

Examples

- Dijkstra
- Bellman-Ford

---

## Single Pair Shortest Path

Find shortest path between

```
Source → Destination
```

Example

```
A → H
```

Examples

- A*
- Dijkstra

---

## All Pairs Shortest Path (APSP)

Find shortest paths

between every pair of vertices.

Example

```
A → B

A → C

B → D

C → A

...
```

Example Algorithm

- Floyd-Warshall

# Algorithms Used

## 1. BFS

Used for

```
Unweighted Graph
```

Idea

Every edge has equal cost.

So,

minimum edges = shortest path.

Time Complexity

```
O(V + E)
```

---

## 2. Dijkstra's Algorithm

Used for

```
Weighted Graph

Positive Weights Only
```

Idea

Always expand the currently closest node first.

Data Structure

```
Priority Queue (Min Heap)
```

Time Complexity

```
O((V + E) log V)
```

Cannot handle

```
Negative Edge Weights
```

---

## 3. Bellman-Ford Algorithm

Used for

```
Weighted Graph

Positive + Negative Weights
```

Idea

Relax every edge repeatedly.

Time Complexity

```
O(V × E)
```

Can detect

```
Negative Cycles
```

---

## 4. Floyd-Warshall Algorithm

Used for

```
All Pairs Shortest Path
```

Idea

Try every vertex as an intermediate node.

Time Complexity

```
O(V³)
```

Uses

```
Dynamic Programming
```

---

## 5. A* (A-Star)

Used for

```
Games

Robotics

GPS

Navigation
```

Idea

Use both

- Distance traveled
- Estimated distance to goal (Heuristic)

to reach the destination faster.

Usually faster than Dijkstra when the destination is known.

---

# Algorithm Selection Guide

| Graph Type | Algorithm |
|------------|-----------|
| Unweighted Graph | BFS |
| Weighted (Positive) | Dijkstra |
| Weighted (Negative Allowed) | Bellman-Ford |
| Detect Negative Cycle | Bellman-Ford |
| All-Pairs Shortest Path | Floyd-Warshall |
| Pathfinding in Games / Maps | A* |

# Mental Model 🧠

Imagine you're in a city.

```
Home

↓

Roads

↓

Office
```

Each road has a travel time.

```
Road A = 5 min

Road B = 20 min

Road C = 3 min
```

The shortest path problem asks:

> Which sequence of roads gets me to my destination with the minimum total cost?

The "cost" doesn't have to mean distance—it could be time, fuel, toll charges, or any measurable quantity.

---

# Key Takeaways

- A graph models connections between nodes.
- A path is a sequence of connected nodes.
- The shortest path minimizes the total path cost.
- Unweighted graphs use BFS.
- Positive weighted graphs use Dijkstra.
- Negative weights require Bellman-Ford.
- Floyd-Warshall solves all-pairs shortest paths.
- A* uses heuristics to efficiently find paths in games and navigation.
