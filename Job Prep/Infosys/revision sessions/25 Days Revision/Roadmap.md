# 🎯 Pattern Recognition Checklist

For every problem, train yourself to ask:

1. Is this an **Array** problem?
2. Can **Hashing** reduce nested loops?
3. Is the array **sorted**? → Binary Search or Two Pointers.
4. Looking for a **contiguous subarray/substring**? → Sliding Window or Prefix Sum.
5. Need the **largest/smallest K elements**? → Heap.
6. Exploring **choices**? → Recursion or Backtracking.
7. Is the data naturally **hierarchical**? → Tree.
8. Does it involve **connections or paths**? → Graph.
9. Are there **overlapping subproblems**? → Dynamic Programming.

This checklist is what experienced programmers mentally run through before they start coding.

## One final recommendation

Since we'll be working through this together, I suggest we don't just "finish topics." Instead, we'll treat each day like a deep-dive workshop:

- 🌟 Intuition first ("Why does this pattern exist?")
- 🐢 Brute-force solution
- ⚡ Optimized solution
- 🧠 Dry run with diagrams
- 💻 Clean C++ implementation
- 🔍 How to recognize this pattern in new problems
- 📝 End-of-day summary and revision sheet

That way, by the end of 25 days, you'll not only remember the algorithms—you'll understand _why_ they work and be much better at identifying the right approach when faced with a new problem.
