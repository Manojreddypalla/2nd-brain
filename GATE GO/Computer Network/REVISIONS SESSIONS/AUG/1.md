# 🌐 IP ADDRESSING + CLASSLESS + SUBNETTING — FULL REVISION

## 0. The Big Picture

Think of an IPv4 address as:

```
32-bit address
        ↓
+-------------------+-------------------+
|    Network part   |     Host part     |
+-------------------+-------------------+
```

The **network part** tells us:

> "Which network?"

The **host part** tells us:

> "Which device/interface inside that network?"

The entire evolution is basically:

```
Classful
   ↓
Fixed network/host boundary
   ↓
Wastage
   ↓
Classless / CIDR
   ↓
Explicit prefix length
   ↓
Subnetting
   ↓
Divide one network into smaller networks
   ↓
VLSM
   ↓
Different subnet sizes
   ↓
Routing table
   ↓
Longest Prefix Match
```

The lecture emphasizes that IP addressing has a **hierarchy**, similar to a postal address: broad location → smaller location → individual destination.

# 1. IPv4 Address

An IPv4 address is:

```
32 bits
```

Usually written as **four 8-bit octets**:

```
192.168.0.1
```

Each octet:

```
8 bits
```

Therefore:

```
8 + 8 + 8 + 8 = 32 bits
```

Example:

```
192       .168       .0        .1
11000000  .10101000  .00000000 00000001
```

So each octet ranges:

```
0 → 255
```

The lecture illustrates the conversion between dotted-decimal and 32-bit binary representation.

---

# 2. IP Address ≠ Host

Important conceptual point:

> An IP address identifies a **connection/interface**, not permanently the physical host.

If a device moves to another network, its IP address can change. Also, a device with multiple network connections can have multiple IPv4 addresses.

Think:

```
Host
 ├── Interface 1 → IP1
 └── Interface 2 → IP2
```

# 4. Classful Addressing

This is the **old addressing scheme**.

The 32-bit IPv4 address space was divided into:

```
Class A
Class B
Class C
Class D
Class E
```

The first few bits identify the class.

## Class identification

|Class|Starting bits|First octet|
|---|---|---|
|A|`0`|0–127|
|B|`10`|128–191|
|C|`110`|192–223|
|D|`1110`|224–239|
|E|`1111`|240–255|

### Fast GATE trick

Just inspect the **first octet**:

```
0–127     → A
128–191   → B
192–223   → C
224–239   → D
240–255   → E
```

Example:

```
138.24.6.1
```

138 lies in:

```
128–191
```

Therefore:

```
Class B
```

The lecture uses exactly this style of question.

# 7. Why Classful Addressing Failed

This is **very important** because it motivates CIDR.

Suppose a company needs:

```
500 hosts
```

Class C:

```
256 addresses
```

Not enough.

So Class B:

```
65,536 addresses
```

Huge wastage.

```
Need ≈ 500

Get = 65,536

Wasted ≈ 65,036
```

The lecture gives this exact problem: an organization needing only a few hundred addresses may have to take a Class B block.

### Problems

```
1. IP wastage
2. Underutilization
3. Address depletion
```

Class A also provided enormous blocks to relatively few organizations, while Class C blocks could be too small.

# 8. Classless Addressing / CIDR

CIDR:

> **Classless Inter-Domain Routing**

The major change:

```
There is NO fixed Class A/B/C boundary.
```

Instead, we explicitly specify the prefix length.

Example:

```
192.168.1.0/24
```

The `/24` means:

```
24 bits → network/prefix
32 - 24 = 8 bits → host
```

The lecture explicitly emphasizes that in classless addressing, the prefix must be specified because the class no longer implicitly tells us the network portion.

---

# 9. CIDR Formula

For:

```
IP/p
```

where `p` = prefix length:

```
Network bits = p

Host bits = 32 - p
```

Therefore:

```
Total addresses = 2^(32-p)
```

And, for the normal subnet calculation used in these lectures:

```
Usable hosts = 2^(32-p) - 2
```

### Example

```
192.168.1.0/24
```

Host bits:

```
32 - 24 = 8
```

Total:

```
2⁸ = 256
```

Usable:

```
256 - 2 = 254
```

# 12. Broadcast Address

The **direct broadcast address** is the last address in a subnet.

```

```

So:

```

```

```

```

```

```

# 16. AND Operation → Network Address

This is one of the most important operations.

```
IP Address
AND
Subnet Mask
=
Network Address
```

Rules:

```
1 AND 1 = 1
1 AND 0 = 0
0 AND 1 = 0
0 AND 0 = 0
```

Example:

```
192.168.1.130/24
```

Mask:

```
255.255.255.0
```

Therefore:

```
192.168.1.130
AND
255.255.255.0
----------------
192.168.1.0
```

So:

```
Network ID = 192.168.1.0/24
```

```

# 25. Question Wording Matters ⚠️

This is especially important for GATE.

If question asks:

> **How many IP addresses?**

Answer:

```
2^hostbits
```

If asks:

> **How many usable host addresses?**

Answer:

```
2^hostbits - 2
```

If asks:

> **Subnet mask?**

Stop after finding mask.

Don't unnecessarily calculate network ID.

If asks:

> **Network address?**

Then calculate network ID.

If asks:

> **Broadcast address?**

Find the last address of the subnet.

This distinction will save you from doing unnecessary calculations.

# 29. VLSM

**VLSM = Variable Length Subnet Mask**

The key idea:

> Different subnets can have different sizes.

Example requirements:

```
Department A → 60 hosts
Department B → 120 hosts
Department C → 30 hosts
Department D → 30 hosts
```

Don't give all of them `/26`.

Instead:

```
120 → /25 → 128 addresses
60  → /26 → 64 addresses
30  → /27 → 32 addresses
30  → /27 → 32 addresses
```

Total:

```
128 + 64 + 32 + 32
= 256
```

So an entire `/24` is perfectly utilized.

This is the exact VLSM example in the lecture.

---

# 30. VLSM Golden Rule

### ALWAYS allocate largest requirement first.

Example:

```
120
60
30
30
```

NOT:

```
30
60
120
30
```

Why?

Because large blocks need contiguous space and allocating small blocks first can fragment the remaining address space.

# 🧠 GATE Formula Sheet

## IPv4

```
IPv4 = 32 bits
Each octet = 8 bits
Each octet = 0–255
```

## CIDR

```
Host bits = 32 - prefix
```

```
Total addresses = 2^(32-prefix)
```

```
Usable hosts = 2^(32-prefix) - 2
```

---

## Subnetting

Borrow `s` bits:

```
Subnets = 2^s
```

Remaining host bits:

```
h = 32 - new prefix
```

Addresses/subnet:

```
2^h
```

Usable:

```
2^h - 2
```

---

## Mask

```
Prefix → first p bits = 1
Remaining = 0
```

---

## Block Size

```
Block size = 256 - mask value
```

---

## Network Address

```
IP AND Mask
```

```
Host bits = 0
```

Host bits = 1
```

---

Network + 1
```

## Last usable

```
Broadcast - 1
```

---

Sort requirements

```

Destination IP

# 🚨 GATE Traps You Must Recognize

### Trap 1 — Class vs CIDR

```
192.168.1.5/20
```

Do **not** automatically assume `/24` because it starts with 192.

The `/20` explicitly determines the prefix in classless addressing.

---

### Trap 2 — Network ≠ First Host

```
192.168.1.0/24
```

Network:

```
192.168.1.0
```

First usable:

```
192.168.1.1
```

---

### Trap 3 — Broadcast ≠ Last Usable

```
192.168.1.255
```

is broadcast for `/24`.

Last usable:

```
192.168.1.254
```

---

### Trap 4 — Number of addresses vs usable hosts

```
/26
```

Total:

```
64
```

Usable:

```
62
```

---

### Trap 5 — Different masks can create different beliefs

Two devices can have different subnet masks and therefore disagree about whether the other device is local.

---

### Trap 6 — Routing table: first match is NOT necessarily correct

Always ask:

```
Which matching route has the longest prefix?
```

---

### Trap 7 — Subnet count

Don't count:

```
number of routers
```

Count:

```
number of independent network segments
```

The lecture's router diagrams repeatedly demonstrate this.
