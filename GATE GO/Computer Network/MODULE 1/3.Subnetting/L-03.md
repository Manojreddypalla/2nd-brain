# 🌐 Computer Networks — Subnetting

## 1. Basic Idea: IP Address = Network + Host

An IPv4 address contains **32 bits**.

Conceptually:

```text
IP Address
┌──────────────────┬──────────────────┐
│   Network Part   │    Host Part     │
└──────────────────┴──────────────────┘
```

The **network portion** identifies the network/group.

The **host portion** identifies a particular device inside that network.

Example:

```text
192.168.1.10/24
```

`/24` means:

```text
Network bits = 24
Host bits    = 32 - 24 = 8
```

Binary mask:

```text
11111111.11111111.11111111.00000000
<-------- 24 --------><--- 8 --->
       Network             Host
```

So:

```text
/24 = 255.255.255.0
```

---

# 2. Network Mask / Subnet Mask

A **network mask** tells us which bits of an IP address belong to the network and which belong to the host.

Example:

```text
192.168.1.10/24
```

means the first 24 bits identify the network.

### CIDR / Slash Notation

```text
/8
/16
/18
/24
/26
/27
...
```

The number after `/` is the number of network bits.

General rule:

```text
Network bits = Prefix length

Host bits = 32 - Prefix length
```

---

# 3. Finding the Network Address

The fundamental operation is:

> **IP Address AND Subnet Mask = Network Address**

Why?

The mask contains:

```text
1 → preserve the IP bit
0 → erase the IP bit
```

AND rules:

```text
1 AND 1 = 1
1 AND 0 = 0
0 AND 1 = 0
0 AND 0 = 0
```

Therefore the host bits disappear.

---

## Example 1

Given:

```text
IP   = 192.168.1.130
Mask = /24
```

Binary:

```text
IP
11000000.10101000.00000001.10000010

Mask
11111111.11111111.11111111.00000000
```

AND:

```text
11000000.10101000.00000001.00000000
```

Therefore:

```text
Network Address = 192.168.1.0/24
```

# 5. What is Subnetting?

> **Subnetting is the process of dividing a network into smaller logical networks called subnets.**

This is done by **borrowing bits from the host portion**.

Before subnetting:

```text
┌─────────────┬─────────────┐
│ Network ID  │   Host ID   │
└─────────────┴─────────────┘
```

After subnetting:

```text
┌─────────────┬─────────────┬─────────────┐
│ Network ID  │  Subnet ID  │   Host ID   │
└─────────────┴─────────────┴─────────────┘
```

So the key mental model is:

> **Subnetting converts some host bits into subnet bits.**

# 6. Why Do We Need Subnetting?

Suppose a company contains:

```text
HR
Sales
IT
Admin
```

Instead of keeping every machine inside one huge network, we can create separate subnets.

Benefits include:

- separate IP space for departments
    
- smaller broadcast domains
    
- easier network management
    
- subnet-level access control
    
- reduced unnecessary broadcast interference
    

The lecture uses this departmental-network idea to motivate subnetting.

# 7. Most Important Subnetting Formulas

## Number of IP Addresses

If there are `h` host bits:

$$  
\text{Total Addresses}=2^h  
$$

Since:

$$  
h=32-\text{prefix}  
$$

we get:

$$  
\boxed{\text{Total Addresses}=2^{32-\text{prefix}}}  
$$

Example:

```text
/24
```

Host bits:

```text
32 - 24 = 8
```

Addresses:

$$  
2^8=256  
$$

---

# 8. Usable Hosts

Normally two addresses are reserved:

```text
Network address
Broadcast address
```

Therefore:

$$  
\boxed{\text{Usable Hosts}=2^h-2}  
$$

Example:

```text
/28
```

Host bits:

```text
32 - 28 = 4
```

Total addresses:

$$  
2^4=16  
$$

Usable:

$$  
16-2=14  
$$

---

# 9. Number of Subnets

Suppose we borrow `n` host bits.

Then:

$$  
\boxed{\text{Number of Subnets}=2^n}  
$$

Example:

Borrow 4 bits:

$$  
2^4=16  
$$

Therefore:

```text
16 subnets
```

---

# 10. Prefix After Borrowing Bits

If original prefix is:

```text
/p
```

and we borrow `n` bits:

$$  
\boxed{\text{New Prefix}=p+n}  
$$

Example:

```text
Original = /24
Borrow = 2 bits
```

Therefore:

```text
New prefix = /26
```

# 11. Fixed-Size Subnetting Example

Divide:

```text
192.168.9.0/24
```

into **4 equal subnets**.

Original host bits:

```text
32 - 24 = 8
```

We need 4 subnets:

$$  
2^n=4  
$$

Therefore:

```text
n = 2
```

Borrow 2 host bits.

New prefix:

```text
/24 + 2 = /26
```

Remaining host bits:

```text
8 - 2 = 6
```

Each subnet contains:

$$  
2^6=64  
$$

addresses.

Usable hosts:

$$  
64-2=62  
$$

# 12. Network and Broadcast Addresses

Every normal subnet has:

```text
First address → Network address
Last address  → Broadcast address
```

Everything between them is available to hosts.

Example:

```text
192.168.9.64/26
```

Range:

```text
192.168.9.64 – 192.168.9.127
```

Therefore:

```text
Network   = 192.168.9.64
First host = 192.168.9.65
Last host  = 192.168.9.126
Broadcast = 192.168.9.127
```

# 13. Important Broadcast Observation

When a network is subnetted, each subnet gets its own broadcast address.

For the **last subnet**, its broadcast address can also equal the broadcast address of the original network.

Example:

```text
Original:
192.168.9.0/24

Original broadcast:
192.168.9.255
```

Last `/26` subnet:

```text
192.168.9.192/26
```

Its broadcast:

```text
192.168.9.255
```

# 15. Block Size Shortcut

For masks operating inside one octet:

$$  
\boxed{\text{Block Size}=256-\text{Mask Value}}  
$$

Example `/26`:

```text
Mask = 255.255.255.192
```

Therefore:

```text
256 - 192 = 64
```

Networks occur at:

```text
0
64
128
192
```

So:

```text
192.168.9.0
192.168.9.64
192.168.9.128
192.168.9.192
```

This shortcut is much faster than converting every IP to binary.

This is extremely important.

Suppose a subnet must support `H` usable hosts.

Find smallest `h` such that:

$$  
\boxed{2^h-2\ge H}

Then:

$$  
\boxed{\text{Prefix}=32-h}  
$$

# 22. FLSM vs VLSM

## FLSM

**Fixed Length Subnet Mask**

All subnets have the same size.

Example:

```text
/24
 ↓
four /26 networks
```

Every subnet gets 64 addresses.

Problem:

If one department needs 60 hosts and another needs only 10, giving both 64 addresses wastes space.

---

# 23. VLSM

**Variable Length Subnet Mask**

Different subnets receive different prefix lengths depending on their requirements.

Example:

```text
500 hosts → large subnet
200 hosts → smaller subnet
100 hosts → smaller
20 hosts  → much smaller
2 hosts   → tiny subnet
```

This uses the address space much more efficiently.

---

# 24. Golden Rule of VLSM

> **Sort host requirements from largest to smallest and allocate the largest subnet first.**

This is the core algorithm.

Why?

Large networks need large contiguous aligned blocks.

If you randomly allocate tiny networks first, you may fragment the address space and make the large network harder/impossible to place cleanly.

So:

```text
1. Sort descending
2. Find required power of 2
3. Convert it to prefix
4. Allocate sequentially
5. Continue with remaining address space
```

# 27. How to Solve VLSM Questions

Whenever you see:

> Divide network X among networks requiring different numbers of hosts.

Immediately do:

```text
STEP 1
Sort requirements descending.

STEP 2
For every requirement H:
Find smallest h where

2^h - 2 >= H

STEP 3
Prefix = 32 - h

STEP 4
Block size = 2^h

STEP 5
Allocate from the beginning of the available address space.

STEP 6
Next network starts immediately after the previous block.
```

Mental pipeline:

```text
Hosts
 ↓
Required power of 2
 ↓
Host bits
 ↓
CIDR prefix
 ↓
Block size
 ↓
Network range
```

```text
IPv4 bits
= 32
```

```text
Host bits
= 32 - prefix
```

```text
Total addresses

```

```text
Usable hosts

```

```text
Borrowed bits

```

```text

```


```text
Network address
= IP AND subnet mask
```

```text
Broadcast address
= Last address of subnet
```

```text
First usable
= Network + 1
```

```text

= Broadcast - 1
```

For host requirement `H`:

```text
Find smallest h:

2^h - 2 >= H

Prefix = 32 - h
```

# 🎯 GATE Pattern Recognition

When you see **“find network address”**:

```text
IP AND Mask
```

or use the faster block-boundary method.

When you see **“H hosts required”**:

```text
2^h - 2 >= H
Prefix = 32 - h
```

When you see **“N equal subnets”**:

```text
2^n >= N
New prefix = Old prefix + n
```

When you see **different host requirements**:

```text
VLSM
→ sort largest to smallest
→ smallest power-of-two block for each
→ allocate sequentially
```

When you see **broadcast address**:

```text
Network + Block Size - 1
```

When you see **next subnet**:

```text
Previous Broadcast + 1
```

The single most useful mental picture for the entire lecture is:

```text
              32-bit IPv4
                   │
        ┌──────────┴──────────┐
     Network                Host
                               │
                       borrow some bits
                               ↓
        ┌──────────┬──────────┬─────────┐
        │ Network  │  Subnet  │  Host   │
        └──────────┴──────────┴─────────┘

More borrowed bits
      ↓
More subnets
      ↓
Fewer host bits
      ↓
Fewer hosts per subnet
```

That relationship is basically the heart of subnetting.
