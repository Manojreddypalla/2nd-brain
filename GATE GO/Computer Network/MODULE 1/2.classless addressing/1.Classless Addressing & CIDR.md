# Computer Networks — Classless Addressing / CIDR

## 1. First: Why do we even need Classless Addressing?

Before understanding **classless addressing**, we need to understand what was wrong with **classful addressing**.

Originally, IPv4 addresses were divided into fixed classes:

|Class|Starting Bits|First Octet|Network Prefix|
|---|---|--:|--:|
|A|`0`|0–127|8 bits|
|B|`10`|128–191|16 bits|
|C|`110`|192–223|24 bits|
|D|`1110`|224–239|Multicast|
|E|`1111`|240–255|Reserved|

Classes A, B and C contain a **Network ID + Host ID**. Classes D and E don't use the normal Network-ID/Host-ID division.

---

# 2. Network ID and Host ID

An IPv4 address contains **32 bits**.

Think of those 32 bits as:

```text
┌───────────────┬───────────────┐
│  Network ID   │    Host ID    │
└───────────────┴───────────────┘
       ↑                ↑
 identifies         identifies
 the network        device inside
                    that network
```

### Class A

```text
8 bits              24 bits
┌──────────┬──────────────────────────┐
│ Network  │          Host            │
└──────────┴──────────────────────────┘
```

### Class B

```text
16 bits             16 bits
┌──────────────────┬──────────────────┐
│     Network      │       Host       │
└──────────────────┴──────────────────┘
```

### Class C

```text
24 bits             8 bits
┌──────────────────────────┬──────────┐
│        Network           │   Host   │
└──────────────────────────┴──────────┘
```

The lecture emphasizes this fixed division as the key feature of old classful addressing.

---

# 3. Network Address

The **Network Address / Network ID** identifies the network itself.

### Rule

> Set every **host bit = 0**.

The first address of the network therefore becomes its network address. Routers use the network address when identifying the destination network.

### Example

Suppose:

```text
132.15.44.9
```

132 belongs to Class B.

Therefore:

```text
Network = first 16 bits
Host    = last 16 bits
```

Set host part to zero:

```text
132.15.44.9
       ↓
132.15.0.0
```

So:

```text
Network Address = 132.15.0.0
```

---

# 4. Direct Broadcast Address

The **Direct Broadcast Address (DBA)** represents **all hosts of a particular network**.

### Rule

> Keep network bits unchanged and set every host bit to `1`.

```text
Network bits | Host bits
 unchanged   | 111111...
```

It is therefore the **last address of the network**.

### Example — Class B

```text
IP = 172.30.10.5
```

Class B means:

```text
Network = 172.30
Host    = 10.5
```

Network address:

```text
172.30.0.0
```

Broadcast address:

```text
172.30.255.255
```

The lecture uses exactly this type of question.

---

## Another example

```text
10.20.15.8
```

This is Class A.

Network part:

```text
10
```

Host part:

```text
20.15.8
```

Therefore:

```text
Network Address   = 10.0.0.0
Broadcast Address = 10.255.255.255
```

# 5. First and Last Addresses

This gives us an extremely useful pattern.

For any network/block:

```text
Host bits = all 0
        ↓
Network Address
(first address)

Host bits = all 1
        ↓
Broadcast Address
(last address)
```

So usable host addresses normally lie between them:

```text
Network Address
      ↓
[ First usable host ........ Last usable host ]
                                      ↓
                              Broadcast Address
```

Hence if there are `h` host bits:

```text
Total addresses = 2^h
```

and traditionally:

```text
Usable host addresses = 2^h - 2
```

because the network address and broadcast address aren't assigned to ordinary hosts.

The lecture demonstrates this with a Class B network where `2^16` total addresses exist and subtracts two for host assignment.

---

# 6. Limited Broadcast Address

There is another special broadcast address:

```text
255.255.255.255
```

Binary:

```text
11111111.11111111.11111111.11111111
```

All **32 bits = 1**.

This is called the:

> **Limited Broadcast Address**

It is used to broadcast to hosts on the **local network**.

### Don't confuse these

```text
Direct Broadcast
→ broadcast to hosts in a particular network/block

Limited Broadcast
→ 255.255.255.255
→ local network
```

# 7. Number of Addresses in Classful Networks

The lecture revisits how many addresses each class gives.

### Class A

24 host bits:

```text
2^24
```

≈ 16 million addresses per network.

### Class B

16 host bits:

```text
2^16 = 65,536
```

### Class C

8 host bits:

```text
2^8 = 256
```

This sounds convenient until we look at real organizations.

---

# 8. The Big Problem with Classful Addressing

Imagine you're running an organization with:

```text
5000 employees
```

You need roughly 5000 IP addresses.

Which class do you choose?

### Class C?

Only:

```text
256 addresses
```

Not enough.

### Class B?

```text
65,536 addresses
```

Enough—but wildly oversized.

If you only need around 5000:

```text
65536 - 5000
≈ 60,536 addresses wasted
```

This is the core design problem demonstrated in the lecture's case study.

---

# 9. Problems with Classful Addressing

Classful addressing gives only a few rigid sizes:

```text
Class A → huge
Class B → medium but still huge
Class C → tiny
```

You cannot simply say:

> "Give me a network for roughly 5000 hosts."

You're forced into one of the predefined classes.

This caused:

**IP address wastage** and **underutilization of large address blocks**. The lecture notes that Class B blocks often went underused, Class C could be too small for many organizations, and large portions of the address space were wasted.

That motivates the transition to:

# Classless Addressing

---

# 10. Core Idea of Classless Addressing

Classless addressing removes the fixed:

```text
Class A
Class B
Class C
```

network boundaries.

Now we can decide:

```text
How many bits should represent network?
How many bits should represent hosts?
```

based on actual requirements.

This means:

> There is **no class**, so the network prefix is no longer implicit.

Therefore the prefix must be explicitly specified.

---

# 11. CIDR Notation

Classless addresses are written as:

```text
IP-address / prefix-length
```

Examples from the lecture:

```text
12.24.76.8/8

23.14.67.92/12

220.8.24.255/25
```

The number after `/` tells us:

> **How many leading bits belong to the network prefix.**

---

# 12. Understanding `/n`

Suppose:

```text
192.168.1.20/24
```

`/24` means:

```text
First 24 bits → Network
Remaining     → Host
```

IPv4 has 32 bits.

Therefore:

```text
Network bits = n

Host bits = 32 - n
```

This is probably the single most important CIDR formula.

---

# 13. Number of Addresses in a CIDR Block

If:

```text
Prefix = /n
```

then:

```text
Host bits = 32 - n
```

Therefore:

```text
Total addresses = 2^(32-n)
```

### Example

```text
205.16.37.39/28
```

Host bits:

```text
32 - 28 = 4
```

Therefore:

```text
Total addresses
= 2^4
= 16
```

The lecture asks exactly this question on page 54.

---

# 14. CIDR Mental Model

Visualize the address as a 32-bit strip:

```text
|---------------- 32 bits ----------------|

| NETWORK BITS | HOST BITS |
       n          32 - n
```

For `/27`:

```text
|--------- 27 ---------|--5--|
      network            host
```

So:

```text
Host bits = 5
Total addresses = 2^5 = 32
```

This exact `/27` reasoning is used in the lecture's worked example.

# 15. Finding the First Address

In classless addressing:

> First address = set all host bits to `0`.

Suppose:

```text
167.199.170.82/27
```

First determine host bits:

```text
32 - 27 = 5
```

So the final 5 bits are host bits.

Convert last octet:

```text
82 = 01010010
```

Separate `/27`:

```text
010 | 10010
↑      ↑
net    host
```

Set host bits to zero:

```text
010 | 00000
```

which is:

```text
64
```

Therefore:

```text
First address =
167.199.170.64/27
```

---

# 16. Finding the Last Address

Same IP:

```text
167.199.170.82/27
```

We had:

```text
010 | 10010
```

To obtain the last address:

> Set all host bits to `1`.

```text
010 | 11111
```

Binary:

```text
01011111
```

Decimal:

```text
95
```

Therefore:

```text
Last address =
167.199.170.95/27
```

So the entire block is:

```text
167.199.170.64
        ↓
        ...
        ↓
167.199.170.95
```

Total:

```text
95 - 64 + 1 = 32
```

which agrees with:

```text
2^(32-27)
= 2^5
= 32
```

The lecture confirms the first and last addresses as `.64` and `.95`.

---

# 17. The Universal CIDR Procedure

Whenever GATE gives:

```text
a.b.c.d/n
```

think in this exact order:

```text
1. Prefix bits = n

2. Host bits = 32 - n

3. Number of addresses
   = 2^(32-n)

4. Network/first address
   → host bits = all 0

5. Broadcast/last address
   → host bits = all 1
```

That one process handles most introductory CIDR questions.

# 19. Faster Method — Block Size

Binary always works, but during GATE you want speed.

If the prefix cuts through one octet, determine the block size.

For `/28`:

```text
Host bits in last octet = 4

Block size = 2^4 = 16
```

Ranges:

```text
0
16
32
48
64
80
96
112
128
144
160
176
192
208
224
240
```

Each number is a possible network boundary.

For:

```text
205.16.37.39/28
```

39 lies between:

```text
32 ≤ 39 ≤ 47
```

Hence:

```text
Network   = .32
Broadcast = .47
```

Much faster than converting everything to binary.

# 22. Extremely Useful Prefix Table

Memorize the pattern, not the whole table.

|Prefix|Host Bits|Addresses|Block Size|
|--:|--:|--:|--:|
|/24|8|256|256|
|/25|7|128|128|
|/26|6|64|64|
|/27|5|32|32|
|/28|4|16|16|
|/29|3|8|8|
|/30|2|4|4|
|/31|1|2|2|
|/32|0|1|1|

Notice the pattern:

```text
/24 → 256
/25 → 128
/26 → 64
/27 → 32
/28 → 16
/29 → 8
/30 → 4
```

Every time prefix increases by 1:

```text
number of addresses ÷ 2
```

because you've taken one bit away from the host portion.

---

# 23. Why Powers of Two Keep Appearing

This isn't a random networking formula.

Every host bit can be:

```text
0 or 1
```

So one host bit:

```text
2 possibilities
```

Two host bits:

```text
00
01
10
11

= 4
= 2²
```

Three host bits:

```text
2³ = 8
```

Therefore `h` host bits:

```text
2^h addresses
```

Since:

```text
h = 32 - prefix
```

we obtain:

```text
2^(32-prefix)
```

So CIDR calculations are fundamentally just **binary combinations**.

# 24. Network Address vs Broadcast Address

This distinction should become automatic:

```text
Network Address
Host bits → 000000...

Broadcast Address
Host bits → 111111...
```

Mental shortcut:

```text
Network  = FLOOR of block
Broadcast = CEILING/end of block
```

Example:

```text
IP = 130
block = 64
```

Blocks:

```text
0-----63
64----127
128---191    ← 130 lives here
192---255
```

Therefore:

```text
Network   = 128
Broadcast = 191
```

---

# 25. Finding Usable Host Range

Once network and broadcast are known:

```text
First usable = Network + 1
Last usable  = Broadcast - 1
```

Example:

```text
192.168.1.18/28
```

Block:

```text
192.168.1.16 → 192.168.1.31
```

Therefore:

```text
Network     = 192.168.1.16
First host  = 192.168.1.17

...

Last host   = 192.168.1.30
Broadcast   = 192.168.1.31
```

For ordinary subnet questions:

```text
Usable hosts = 2^h - 2
```

# 26. How Many Host Bits Do We Need?

This is the reverse type of problem.

Suppose an organization needs:

```text
300 hosts
```

We need the smallest `h` such that:

```text
2^h - 2 ≥ 300
```

Try:

```text
h = 8

2^8 - 2 = 254
```

Not enough.

Try:

```text
h = 9

2^9 - 2 = 510
```

Enough.

Therefore:

```text
Host bits = 9
```

Prefix:

```text
32 - 9 = 23
```

So we'd need approximately:

```text
/23
```

This is the flexibility that classful addressing lacked.

---

# 27. Why Classless Addressing Solves the Wastage Problem

Under classful addressing, an organization needing 300 hosts might have been forced toward a Class B-sized allocation:

```text
65,536 addresses
```

Classless addressing can instead choose a prefix according to the required host capacity.

For 300 hosts:

```text
2^8 - 2 = 254    ❌

2^9 - 2 = 510    ✓
```

So only:

```text
512 total addresses
```

are needed.

That's dramatically closer to the requirement.

This is the key transition shown between the lecture's classful-address-depletion discussion and its introduction of classless addressing.

# 28. Same Network / Same Block Questions

The final lecture question asks which addresses belong to the same network as:

```text
152.3.128.0/17
```

For `/17`:

```text
17 network bits
15 host bits
```

The first two octets provide 16 network bits:

```text
152.3
```

One more network bit comes from the third octet.

That means the third-octet space divides into:

```text
0xxxxxxx   → 0–127

1xxxxxxx   → 128–255
```

Since the given network starts at:

```text
152.3.128.0
```

its range is:

```text
152.3.128.0
      ↓
152.3.255.255
```

Therefore any IP inside that range belongs to the same `/17` block. This is exactly the bit-boundary reasoning illustrated on the final two lecture pages.

# 29. CIDR Question-Solving Framework

When you see something like:

```text
172.16.35.123/27
```

don't randomly start converting all 32 bits.

Ask:

```text
What is prefix?
        ↓
       /27

How many host bits?
        ↓
     32-27 = 5

How many addresses?
        ↓
       2⁵ = 32

What is block size?
        ↓
         32

Which block contains 123?
```

Multiples of 32:

```text
0
32
64
96
128
160
192
224
```

123 lies inside:

```text
96–127
```

Therefore immediately:

```text
Network   = 172.16.35.96
Broadcast = 172.16.35.127

First host = 172.16.35.97
Last host  = 172.16.35.126
```

No full binary conversion required.

# 30. The Binary Method vs Block Method

You should know both.

### Binary method

Best when:

- learning the concept
    
- prefix boundary is confusing
    
- MSQ asks whether multiple IPs belong to the same network
    
- you want a guaranteed method
    

Mental operation:

```text
Network → host bits = 0
Broadcast → host bits = 1
```

### Block-size method

Best for GATE speed.

Mental operation:

```text
Host bits
    ↓
2^hostbits
    ↓
block size
    ↓
find interval containing IP
```

Example `/27`:

```text
host = 5

2^5 = 32

0–31
32–63
64–95
96–127
...
```

# 31. Classful vs Classless — Final Comparison

|Classful|Classless|
|---|---|
|Fixed classes|No classes|
|A/B/C determine network size|Prefix determines network size|
|Network prefix implicit|Prefix explicitly written|
|Fixed network boundaries|Flexible network boundaries|
|High address wastage|Better address utilization|
|Example `192.20.4.5`|Example `192.20.4.5/27`|

The lecture's central transition is essentially:

```text
CLASSFUL

IP address
    ↓
look at class
    ↓
class tells prefix


CLASSLESS

IP address + /n
         ↓
/n explicitly tells prefix
```

# 32. GATE Formula Sheet

Keep this part in your Obsidian revision notes.

```text
IPv4 size = 32 bits

Prefix bits = n

Host bits = 32 - n

Total addresses
= 2^(32-n)

Network / First Address
= all host bits 0

Broadcast / Last Address
= all host bits 1

First usable host
= Network + 1

Last usable host
= Broadcast - 1

Usable hosts
= 2^(32-n) - 2
```

And for a host requirement `H`:

```text
Find minimum h such that:

2^h - 2 ≥ H

Then:

Prefix = 32 - h
```
