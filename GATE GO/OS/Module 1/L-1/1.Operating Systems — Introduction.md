# Operating Systems — Introduction

## 1. Program Execution

Basic flow:

Source Code → Compiler → Executable → Load into Memory → CPU Executes

### CPU Components
- **Control Unit** → controls instruction execution
- **ALU** → performs arithmetic/logical operations
- **Registers** → fast storage inside CPU
- **Program Counter (PC)** → stores address of the next instruction

### CPU Execution Cycle

Fetch → Decode → Execute → Repeat

> CPU continuously executes instructions; when a program finishes, control returns to the OS.

---

## 2. Why Do We Need an OS?

CPU is good at:
- Calculations
- Following instructions
- Executing programs

But we need management for:

- CPU
- Memory
- Storage
- I/O devices
- Multiple programs
- Protection/security

### Without an OS

Programmers would manually need to:

- Load programs into memory
- Set the PC
- Control hardware
- Manage memory
- Prevent programs from overwriting each other
- Manage multiple programs

> **OS = Resource Manager + Abstraction Layer**

---

## 3. Major Responsibilities of OS

### CPU Management
Decides which program gets CPU time.

→ **CPU Scheduling**

### Memory Management
- Allocates memory
- Tracks memory usage
- Prevents programs from interfering with each other

### I/O Management
Provides controlled access to:
- Monitor
- Keyboard
- Disk
- Other devices

### Storage Management
Provides a **File System** instead of making programs directly manage disk sectors.

---

## 4. CPU Virtualization

Suppose:

P1, P2, P3, P4

must run on **one CPU**.

The OS rapidly switches between them:

P1 → P2 → P1 → P3 → P2 → ...

This creates the **illusion that multiple programs are running simultaneously**.

> **CPU Virtualization = sharing one physical CPU among multiple programs.**

---

## 5. CPU Scheduling

**CPU Scheduling** decides:

> Which process should execute on the CPU next?

Examples studied later:
- FCFS
- Round Robin (RR)
- etc.

---

## 6. Context Switch

When CPU changes execution:

P1 → P2

the OS must preserve P1's execution state and restore P2's state.

This is called a **Context Switch**.

---

## 7. Big Picture

Applications
    ↓
Operating System
    ↓
Hardware

OS manages:

- Process creation
- CPU scheduling
- Synchronization
- Memory management
- Deadlocks
- File systems

---

## 8. Key GATE Points

- **PC** → address of next instruction
- CPU follows **Fetch → Decode → Execute**
- OS manages hardware/resources
- **CPU Scheduling** → decides who gets CPU
- **Context Switch** → switches CPU between processes
- **CPU Virtualization** → creates illusion of multiple programs running on one CPU
- **File System** → abstraction over raw disk/storage

---

## 9. Mental Model

**CPU = Worker**

**OS = Manager**

CPU executes instructions.

OS decides how CPU, memory, storage and devices are shared among programs.
