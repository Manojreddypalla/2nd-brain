

Which of the following statements about threads is/are TRUE?

1. Threads can only be implemented in kernel space
2. Each thread has its own file descriptor table for open files
3. All the threads belonging to a process share a common stack
4. Threads belonging to a process are by default not protected from each other explain 


The correct answer is **4 only** ✅

Let's examine each carefully — there are some classic GATE traps here.

|#|Statement|True/False|Why?|
|---|---|---|---|
|**1**|Threads can **only** be implemented in kernel space|❌ **FALSE**|Threads can be **user-level** or **kernel-level**.|
|**2**|Each thread has its own **file descriptor table**|❌ **FALSE**|Threads of the same process **share the file descriptor table**.|
|**3**|All threads share a **common stack**|❌ **FALSE**|Each thread has its **own stack**.|
|**4**|Threads in a process are by default **not protected from each other**|✅ **TRUE**|They share the same address space, so one thread can access/modify another thread's accessible memory.|

### 🧠 The big picture

Think of a **process as a container**:

```text
                 PROCESS
        ┌─────────────────────────┐
        │      SHARED             │
        │  Address Space          │
        │  ├── Code               │
        │  ├── Global Variables   │
        │  ├── Heap               │
        │  └── File Descriptors   │
        │                         │
        │  THREAD 1              │
        │  ├── PC                │
        │  ├── Registers         │
        │  └── Stack             │
        │                         │
        │  THREAD 2              │
        │  ├── PC                │
        │  ├── Registers         │
        │  └── Stack             │
        └─────────────────────────┘
```

### 🔥 The important concept behind option 4

Processes are normally **isolated**:

```text
Process A  ❌──────❌  Process B
```

Their address spaces are protected from each other.

But threads within the **same process**:

```text
Thread 1  ←──── shared address space ────→  Thread 2
```

So if Thread 1 has access to some shared memory:

```cpp
int x = 10;   // global

Thread 1: x = 50;
Thread 2: cout << x;   // sees 50
```

There is **no process-level memory protection separating Thread 1 from Thread 2**.

That's why:

> **Same process → shared address space → threads are not protected from each other by default.**

### ⚠️ GATE nuance

Don't interpret "not protected" as **"everything is shared."**

**Shared:**

- Address space
    
- Code
    
- Global/static data
    
- Heap
    
- Open-file/file-descriptor table
    

**Per-thread:**

- Stack
    
- Registers
    
- Program Counter
    
- Thread execution state
    

So the exam pattern is:

> **Threads share resources but have their own execution state.**

**Final: ④ only.**
