Consider the following statements with respect to user-level threads and kernel-supported threads

1. context switch is faster with kernel-supported threads
    
2. for user-level threads, a system call can block the entire process
    
3. Kernel supported threads can be scheduled independently
    
4. User level threads are transparent to the kernel
    

Which of the above statements are true?

1. (II), (III) and (IV) only
2. (II) and (III) only
3. (I) and (III) only
4. (I) and (II) only

The correct answer is **(II), (III) and (IV) only** ✅

### First, the mental model

Think of:

- **User-level threads (ULT)** → managed by a **user-space thread library**. Kernel sees **only the process**.
    
- **Kernel-supported threads (KLT)** → kernel knows about **each thread** and schedules them individually.
    

|Statement|True?|Why|
|---|---|---|
|**(I) Context switch is faster with kernel-supported threads**|❌|KLT context switching involves kernel intervention → generally **more overhead**. ULT switching can happen entirely in user space.|
|**(II) For user-level threads, a system call can block the entire process**|✅|Kernel doesn't know individual ULTs. If one ULT makes a **blocking system call**, the kernel blocks the whole process → other ULTs cannot run.|
|**(III) Kernel-supported threads can be scheduled independently**|✅|Kernel knows each thread separately, so it can schedule **T1 while T2 is blocked**.|
|**(IV) User-level threads are transparent to the kernel**|✅|Exactly. Kernel sees the **process**, not its individual ULTs.|

### 🔥 GATE trap: "independent" vs "shared"

For **KLT**:

```text
Process
 ├── T1 ← kernel knows
 ├── T2 ← kernel knows
 └── T3 ← kernel knows
```

If T1 blocks:

```text
T1 → BLOCKED
T2 → RUNNING   ✅
T3 → READY
```

For **ULT**:

```text
Process
 └── Kernel sees ONE process
      ├── T1
      ├── T2
      └── T3
```

If T1 makes a blocking system call:

```text
T1 → BLOCKED
     ↓
Entire process blocked ❌
     ↓
T2 and T3 also cannot execute
```

### ⚠️ Statement I is the key trap

Don't confuse **kernel-supported** with **faster**.

Generally:

**ULT context switch < KLT context switch**

because ULT switching can avoid entering the kernel.

So:

> **ULT → faster switching, but blocking problem**  
> **KLT → slower/heavier switching, but independent scheduling**

### Final

**(II), (III), (IV) only → Option 1 ✅**
