# CN Lecture 1 — Introduction to IP Addressing

## 1. Computer Network

A **computer network** is a collection of connected devices that communicate and exchange data.

### Basic parts of a network

- **Host** → end device such as laptop/computer/server
    
- **Router** → forwards packets between networks
    
- **Link** → communication path connecting devices
    
    - Wired
        
    - Wireless
        
- **Application** → software using the network, e.g. browser
    

Mental picture:

```text
Host A ── Router ── Router ── Host B
           ↑           ↑
        forwards     forwards
         packets      packets
```

The lecture introduces these pieces before moving into IP addresses.

---

# 2. Why Do We Need an IP Address?

Imagine sending a letter.

```text
Home Address   → IP Address
Postal Service → Routers
Letter         → Data Packet
```

Without the destination address, the postal system doesn't know where the letter should go.

Similarly:

> **Without an IP address, the network doesn't know where to deliver a packet.**

Therefore we need an addressing mechanism for identifying connections in a network.

---

# 3. IPv4 Address

An **IPv4 address is 32 bits long**.

Example:

```text
192.168.0.1
```

It consists of **4 groups**, called octets.

```text
192 . 168 . 0 . 1
 ↑     ↑    ↑   ↑
8bit  8bit 8bit 8bit

Total = 32 bits
```

Each octet can range from:

```text
00000000 → 11111111
    0     →    255
```

So the general IPv4 form is:

```text
x.x.x.x
```

where each `x` is `0–255`.

---

# 4. IP Address Belongs to a Connection

Important point from the lecture:

> An IP address identifies a **connection/interface**, rather than permanently identifying the physical host.

Why?

Suppose a device connects to two different networks:

```text
          Network 1
             |
          IP #1
             |
           Host
             |
          IP #2
             |
          Network 2
```

The same device can therefore have **two IPv4 addresses** because it has two network connections.

Likewise, moving a device to another network may cause its IP address to change.

---

# 5. Hierarchical Addressing

This is one of the key ideas of the lecture.

Consider a postal address:

```text
Country
  ↓
State
  ↓
City
  ↓
Street
  ↓
House
```

Or a telephone number:

```text
Area Code | Exchange | Subscriber
```

Instead of giving every device one giant unrelated identifier, addresses are organized **hierarchically**.

An IP address follows the same basic idea:

```text
IP Address
   │
   ├── Prefix
   │     ↓
   │   Network
   │
   └── Suffix
         ↓
      Connection/Node
```

So conceptually:

```text
IP Address = Network part + Host part
```

This hierarchy helps routers determine **which network** a packet should be forwarded toward.

---

# 6. Network ID and Host ID

For the classful addressing introduced in this lecture:

```text
IP Address
┌───────────────────────────────┐
│       NetID       │  HostID   │
└───────────────────────────────┘
```

### NetID

Identifies the **network**.

### HostID

Identifies a **host/connection inside that network**.

Think:

```text
Network ID = Street
Host ID    = House number
```

Routers mainly care about getting the packet toward the correct **network**.

---

# 7. Classful Addressing

IPv4 has:

```text
2³²
```

possible 32-bit bit patterns.

In **classful addressing**, this address space is divided into five classes:

```text
A
B
C
D
E
```

The class can be recognized from the **starting bits of the first octet**.

|Class|Starting Bits|First Octet Range|
|---|---|--:|
|A|`0`|0–127|
|B|`10`|128–191|
|C|`110`|192–223|
|D|`1110`|224–239|
|E|`1111`|240–255|

### Easy pattern

```text
A → 0
B → 10
C → 110
D → 1110
E → 1111
```

Notice what is happening:

```text
0
10
110
1110
1111
```

You can derive the classes from the leading bits instead of blindly memorizing all the ranges.

---

# 8. Finding the Class

Example:

```text
193.14.56.22
```

Only look at the **first octet**:

```text
193
```

Since:

```text
192 ≤ 193 ≤ 223
```

therefore:

```text
Class C
```

Another example:

```text
227.12.14.87
```

Since:

```text
224 ≤ 227 ≤ 239
```

therefore:

```text
Class D
```

The lecture works through this same class-identification idea using both binary and dotted-decimal addresses.

---

# 9. NetID and HostID in Classes

For classes A, B and C, the address is divided into **NetID + HostID**.

```text
Class A
[ NetID ][        HostID        ]
   8 bits          24 bits


Class B
[      NetID      ][   HostID   ]
      16 bits          16 bits


Class C
[         NetID        ][HostID]
          24 bits        8 bits
```

So:

|Class|NetID|HostID|
|---|--:|--:|
|A|1 byte|3 bytes|
|B|2 bytes|2 bytes|
|C|3 bytes|1 byte|

Class D and E are **not divided into NetID and HostID** in this scheme.

# 10. Quick Binary Values to Remember

These appear repeatedly when working with IPv4:

```text
00000000 = 0
00000001 = 1
00000011 = 3
00000111 = 7
00001111 = 15
00011111 = 31
00111111 = 63
01111111 = 127
11111111 = 255
```

And:

```text
10000000 = 128
11000000 = 192
11100000 = 224
11110000 = 240
11111000 = 248
11111100 = 252
11111110 = 254
11111111 = 255
```

These patterns make IP/subnet calculations much faster.

### One connection worth locking in

```text
Why hierarchy?
      ↓
We don't want routers reasoning about
every individual machine on Earth.
      ↓
Group machines into networks
      ↓
Network ID tells WHERE
Host ID tells WHICH connection inside it
      ↓
This leads directly into:
Classful Addressing
      ↓
Subnetting
      ↓
CIDR
      ↓
Routing
```

That **hierarchy → NetID/HostID → subnetting → routing** chain is the real conceptual backbone here.
