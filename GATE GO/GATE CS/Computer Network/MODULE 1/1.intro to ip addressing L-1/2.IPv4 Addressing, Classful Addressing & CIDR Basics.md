# Computer Networks — Lecture 1
## IPv4 Addressing, Classful Addressing & CIDR Basics

---

# 1. Computer Network

A **Computer Network** is a collection of interconnected devices that communicate and exchange data.

### Main Components

- **Host** → End device such as computer, laptop, server, phone
- **Router** → Forwards packets between networks
- **Link** → Communication path between devices
- **Application** → Software that uses the network

Example:

Host A → Router → Router → Host B

---

# 2. Why Do We Need Addressing?

When data travels through a network, the network must know:

1. Where the packet came from
2. Where the packet needs to go

Analogy:

Letter → Data Packet  
Postal Address → IP Address  
Postal System → Network/Routers

Without an address, routers would not know where to deliver a packet.

---

# 3. IP Address

**IP = Internet Protocol**

An IP address is used to identify a network connection/interface.

> Important:
> An IP address is associated with a network connection/interface rather than permanently identifying the physical device.

A device connected to multiple networks can therefore have multiple IP addresses.

Example:

Network A
    |
  IP #1
    |
 [Host]
    |
  IP #2
    |
Network B

---

# 4. IPv4

**IPv4 = Internet Protocol Version 4**

IPv4 uses:

32 bits

Total possible bit patterns:

2^32

IPv4 is normally written as four decimal numbers separated by dots.

Example:

192.168.1.10

This is called **dotted-decimal notation**.

---

# 5. IPv4 Structure

IPv4 contains four groups of 8 bits.

Each 8-bit group is called an **octet**.

192 . 168 . 1 . 10
 ↓     ↓    ↓    ↓
8bit  8bit 8bit 8bit

Total:

8 + 8 + 8 + 8 = 32 bits

Therefore:

IPv4 = 4 octets = 32 bits

Each octet can represent:

0 → 255

because:

00000000 = 0
11111111 = 255

---

# 6. Binary Values for IPv4

An IPv4 octet contains 8 bits.

Each position represents a power of 2:

| Bit Position | Value |
|---|---:|
| 7 | 128 |
| 6 | 64 |
| 5 | 32 |
| 4 | 16 |
| 3 | 8 |
| 2 | 4 |
| 1 | 2 |
| 0 | 1 |

Quick reference:

128 64 32 16 8 4 2 1

---

# 7. Decimal → Binary

To convert decimal to binary, determine which powers of 2 are required to create the number.

## Example — 192

192 = 128 + 64

128  64  32  16  8  4  2  1
 1    1   0   0   0  0  0  0

Therefore:

192 = 11000000

---

## Example — 168

168 = 128 + 32 + 8

128  64  32  16  8  4  2  1
 1    0   1   0   1  0  0  0

Therefore:

168 = 10101000

---

## Example IPv4 Conversion

192.168.1.1

192 = 11000000
168 = 10101000
1   = 00000001
1   = 00000001

Therefore:

192.168.1.1

=

11000000.10101000.00000001.00000001

Very important for IP addressing and subnetting:

| Binary | Decimal |
|---|---:|
| 00000000 | 0 |
| 10000000 | 128 |
| 11000000 | 192 |
| 11100000 | 224 |
| 11110000 | 240 |
| 11111000 | 248 |

Pattern:

10000000 → 128

11100000 → 224

---

# 9. Hierarchical Addressing

IP addressing is **hierarchical**.

Instead of treating every device as one unrelated number, an address can be logically divided into:

IP Address
    |
    ├── Network Part
    |
    └── Host Part

Conceptually:

IP Address = Network ID + Host ID

### Network ID / NetID

Identifies the network.

### Host ID / HostID

Identifies the host/connection inside that network.

Analogy:

Postal Address:

Country → State → City → Street → House

IP addressing follows the same idea.

---

# 10. Why Hierarchical Addressing?

Suppose millions of devices exist.

A router should not need completely unrelated information about every individual device.

Instead:

Destination IP
      ↓
Network portion
      ↓
Find destination network
      ↓
Forward packet toward that network
      ↓
Reach destination host

This hierarchy is fundamental to routing.

# 11. Classful Addressing

Originally, IPv4 used **Classful Addressing**.

The IPv4 address space was divided into:

- Class A
- Class B
- Class C
- Class D
- Class E

Classes are identified using the **leading bits of the address**.

---

# 12. Binary Representation of Classes

Class A:

0xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Class B:

10xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Class C:

110xxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Class D:

1110xxxxxxxxxxxxxxxxxxxxxxxxxxxx

Class E:

1111xxxxxxxxxxxxxxxxxxxxxxxxxxxx

Easy pattern:

A → 0
B → 10
C → 110
D → 1110
E → 1111

---

# 14. Why Class Sizes Differ

Class A starts with:

0

Only 1 bit is fixed.

Remaining free bits:

32 - 1 = 31

Address-space size:

2^31

---

Class B starts with:

10

2 bits fixed.

Remaining:

30 bits

Address-space size:

2^30

---

Class C starts with:

110

3 bits fixed.

Remaining:

29 bits

Address-space size:

2^29

---

Class D:

1110

4 fixed bits

→ 2^28 address patterns

---

Class E:

1111

4 fixed bits

→ 2^28 address patterns

> Note:
> These values describe how much of the entire IPv4 address space belongs to each class.
> They are NOT the number of hosts in one Class A/B/C network.

---

# 15. Class Ranges

| Class | Starting Bits | First Octet Range |
|---|---|---:|
| A | 0 | 0–127 |
| B | 10 | 128–191 |
| C | 110 | 192–223 |
| D | 1110 | 224–239 |
| E | 1111 | 240–255 |

---

# 16. Deriving Class C

Why does Class C start at 192?

192:

128 + 64 = 192

Binary:

128 64 32 16 8 4 2 1
 1   1  0  0  0 0 0 0

= 11000000

Class C requires:

110...

Therefore:

192 = beginning of Class C

Maximum:

11011111

=

128 + 64 + 16 + 8 + 4 + 2 + 1

=

223

Therefore:

Class C = 192–223

---

# 17. Finding Class from an IP Address

Look at the **first octet**.

Example:

193.10.20.30

First octet:

193

Since:

192 ≤ 193 ≤ 223

Therefore:

Class C

Binary method:

193 = 11000001

Starts with:

110

Therefore:

Class C

# 18. NetID and HostID in Classful Addressing

For normal host addressing:

## Class A

[ NetID ][              HostID              ]

8 bits                24 bits

Equivalent boundary:

/8

Example:

10.20.30.40

NetID  = 10
HostID = 20.30.40

---

## Class B

[          NetID          ][      HostID      ]

16 bits                       16 bits

Equivalent boundary:

/16

Example:

172.16.50.25

NetID  = 172.16
HostID = 50.25

---

## Class C

[              NetID              ][ HostID ]

24 bits                           8 bits

Equivalent boundary:

/24

Example:

192.168.1.25

NetID  = 192.168.1
HostID = 25

---

# 19. Class Summary

| Class | Leading Bits | Range | Default Boundary |
|---|---|---|---|
| A | 0 | 0–127 | /8 |
| B | 10 | 128–191 | /16 |
| C | 110 | 192–223 | /24 |
| D | 1110 | 224–239 | — |
| E | 1111 | 240–255 | — |

For A/B/C:

Class A → NetID 8 bits  | HostID 24 bits
Class B → NetID 16 bits | HostID 16 bits
Class C → NetID 24 bits | HostID 8 bits

---

# 20. IMPORTANT — Class Bits ≠ Network Prefix Length

Do NOT confuse these.

Class C starts with:

110

That means:

First 3 bits identify the address as belonging to Class C.

It DOES NOT mean:

Class C = /3 ❌

Class C's traditional network boundary is:

/24 ✅

Similarly:

Class A starts → 0
Default boundary → /8

Class B starts → 10
Default boundary → /16

Class C starts → 110
Default boundary → /24

---

# 21. Problem with Classful Addressing

Classful addressing provides fixed network sizes:

Class A → /8
Class B → /16
Class C → /24

This is inflexible.

Example:

Suppose an organization needs around 1000 addresses.

Class C:

2^8 = 256 addresses

Too small.

Class B:

2^16 = 65,536 addresses

Far too large.

This can waste address space.

This limitation motivates more flexible prefix-based addressing.

---

# 22. CIDR

**CIDR = Classless Inter-Domain Routing**

CIDR removes the requirement that the network boundary must follow Class A/B/C boundaries.

Instead, we explicitly specify:

> How many leading bits belong to the network prefix.

Notation:

IP/prefix-length

Example:

192.168.1.0/24

`/24` means:

First 24 bits = Network Prefix

Remaining:

32 - 24 = 8 bits

are available after the prefix.

---

# 23. Understanding /24

Example:

192.168.1.0/24

Binary structure:

xxxxxxxx.xxxxxxxx.xxxxxxxx.xxxxxxxx
\________________________/
         24 bits
      Network Prefix

Remaining:

8 bits

Number of addresses:

2^8 = 256

---

# 24. Understanding /25

/25 means:

25 prefix bits
7 remaining bits

Structure:

xxxxxxxx.xxxxxxxx.xxxxxxxx.0xxxxxxx
\_________________________/
          25 bits

Number of addresses:

2^7 = 128

---

# 25. /24 → /25 Connection

A /24 has:

8 free bits

xxxxxxxx

Possible values:

00000000 → 11111111

0 → 255

Now increase prefix:

/24 → /25

One additional bit becomes fixed.

The space splits into:

0xxxxxxx

and

1xxxxxxx

Therefore:

                /24
            256 addresses
                 |
        -------------------
        |                 |
      /25               /25
  128 addresses      128 addresses

Example:

192.168.1.0/24

splits into:

192.168.1.0/25

and

192.168.1.128/25

---

# 26. Repeated Binary Splitting

/24:

xxxxxxxx

2^8 = 256

/25:

0xxxxxxx
1xxxxxxx

2^7 = 128 each

/26:

00xxxxxx
01xxxxxx
10xxxxxx
11xxxxxx

2^6 = 64 each

/27:

5 remaining bits

2^5 = 32 each

Pattern:

/24 → 256
/25 → 128
/26 → 64
/27 → 32
/28 → 16
/29 → 8
/30 → 4

Every time the prefix increases by 1:

Address block size is divided by 2.

---

# 27. CIDR Formula

IPv4 contains:

32 bits

If prefix length = n:

Remaining bits:

32 - n

Therefore:

Number of addresses:

2^(32-n)

Example:

/26

Remaining bits:

32 - 26 = 6

Addresses:

2^6 = 64

---

# 28. CIDR and Subnet Mask

A subnet mask represents prefix bits using `1` and the remaining bits using `0`.

## /24

24 ones:

11111111.11111111.11111111.00000000

Decimal:

255.255.255.0

Therefore:

/24 = 255.255.255.0

---

## /25

11111111.11111111.11111111.10000000

Decimal:

255.255.255.128

Therefore:

/25 = 255.255.255.128

---

## /26

11111111.11111111.11111111.11000000

Decimal:

255.255.255.192

Therefore:

/26 = 255.255.255.192

| CIDR | Mask | Addresses |
|---|---|---:|
| /24 | 255.255.255.0 | 256 |
| /25 | 255.255.255.128 | 128 |

192 → 11000000

Same binary-prefix pattern again.

---

# 30. Classful vs CIDR

| Classful Addressing | CIDR |
|---|---|
| Uses classes | Classless |
| Fixed boundaries | Flexible boundaries |
| A → /8 | Any valid prefix length |
| B → /16 | e.g. /17, /20, /25 |
| C → /24 | e.g. /26, /27, /30 |
| Less flexible | More flexible |
| Can waste address space | Better address allocation |

---

# 31. Core Difference

Classful Addressing asks:

"What class does this IP belong to?"

The class determines the traditional network boundary.

CIDR asks:

"How many leading bits are the network prefix?"

The prefix length explicitly determines the boundary.

Example:

192.168.1.50

Historically:

192 → Class C → default /24

But:

192.168.1.50/26

explicitly says:

Network prefix = 26 bits

Therefore the CIDR prefix, not the historical class, determines the network boundary.

# 33. The Most Important Pattern

Everything comes back to:

FIX LEADING BITS → CREATE A BLOCK OF ADDRESSES

Example:

0xxxxxxx

fixes one bit.

10xxxxxx

fixes two bits.

110xxxxx

fixes three bits.

Similarly:

/24

fixes 24 bits.

/25

fixes 25 bits.

/26

fixes 26 bits.

Every additional fixed bit:

→ cuts the remaining address space in half.

This idea connects:

Classful Addressing
        ↓
Binary Prefixes
        ↓
CIDR
        ↓
Subnet Masks
        ↓
Subnetting
        ↓
Routing
        ↓
Longest Prefix Matching

# GATE Quick Revision

## IPv4

- IPv4 = 32 bits
- 4 octets
- 8 bits/octet
- Each octet = 0–255
- Total patterns = 2^32

## Binary Values

128 64 32 16 8 4 2 1

Important:

0   = 00000000
128 = 10000000
192 = 11000000
224 = 11100000
240 = 11110000
248 = 11111000
252 = 11111100
254 = 11111110

## Classes

A → 0    → 0–127   → /8
B → 10   → 128–191 → /16
C → 110  → 192–223 → /24
D → 1110 → 224–239
E → 1111 → 240–255

## CIDR

/24 → 8 remaining bits → 256 addresses
/25 → 7 remaining bits → 128
/26 → 6 remaining bits → 64
/27 → 5 remaining bits → 32
/28 → 4 remaining bits → 16
/29 → 3 remaining bits → 8
/30 → 2 remaining bits → 4

Formula:

Remaining bits = 32 - prefix

Addresses = 2^(32-prefix)

## Key Idea

Classful:
Boundary determined by class.

CIDR:
Boundary explicitly specified by prefix length.

## Golden Rule

More prefix bits
→ fewer remaining bits
→ smaller address block

Less prefix bits
→ more remaining bits
→ larger address block
