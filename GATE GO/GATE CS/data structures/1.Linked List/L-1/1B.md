# Linked List — Remaining Lecture Notes

## 1. Why Do We Need Linked Lists?

Now that we know **what a linked list is**, the next question is:

> Why not just use arrays everywhere?

The lecture gives several real-world examples before comparing the two structures.

The important idea is:

```text
Array
→ elements are organized next to each other in memory

Linked List
→ elements can exist at different places
→ pointers connect them
```

This difference gives each structure different strengths.

# 5. Array vs Linked List

This is the major conceptual section of the remaining lecture.

The diagrams on pages 32–43 compare how arrays and linked lists behave in memory.

## Array

Suppose:

```c
int a[5];
```

Conceptually:

```text
Memory

┌────┬────┬────┬────┬────┐
│ a0 │ a1 │ a2 │ a3 │ a4 │
└────┴────┴────┴────┴────┘

continuous memory
```

Elements are stored next to each other.

---

## Linked List

```text
Memory

┌────┬──────┐
│ 10 │  ●───┼────────┐
└────┴──────┘        │
                     ▼
                ┌────┬──────┐
                │ 20 │  ●───┼──────────────┐
                └────┴──────┘              │
                                           ▼
                                      ┌────┬──────┐
                                      │ 30 │ NULL │
                                      └────┴──────┘
```

The nodes don't need to be adjacent.

The pointers create the logical order.

---

# 6. Comparison 1 — Cache Locality

This is an important systems concept from the lecture.

### Arrays have good cache locality

Because array elements are contiguous:

```text
Main Memory

[10][20][30][40][50][60]
 ↑
 CPU asks for 10
```

The CPU doesn't necessarily fetch only `10`.

Memory is transferred to cache in blocks/cache lines, so nearby elements may arrive too.

Conceptually:

```text
CPU CACHE

[10][20][30][40]
```

Then when the program asks for:

```text
20
30
40
```

they may already be in cache.

That's fast.

The lecture illustrates this sequential-access/cache behavior on pages 36 and 43.

---

## Linked List Cache Locality

Linked-list nodes can be scattered:

```text
Node 1 @ 1000
       │
       └──────────────→ Node 2 @ 9000
                              │
                              └────→ Node 3 @ 3500
```

So loading Node 1 doesn't necessarily bring Node 2 into the same cache line.

Therefore, generally:

```text
Array
→ better cache locality

Linked List
→ poorer cache locality
```

The comparison table in the lecture marks cache locality in favor of arrays.

---

# 7. Comparison 2 — Dynamic Number of Elements

This is where linked lists become attractive.

Suppose you are storing students.

You don't know beforehand how many students will enroll.

If you write:

```c
int students[100];
```

you have fixed capacity for 100.

### What if only 50 join?

```text
[used used used ...][unused unused unused ...]
      50                  50
```

Some reserved space is unused.

### What if 150 join?

Now:

```text
capacity = 100
needed   = 150
```

The original fixed-size array isn't enough.

This dynamic-size problem is exactly what pages 37–40 discuss.

---

## Linked List Approach

With a linked list, create nodes as needed:

```text
Initially

NULL
```

Student joins:

```text
[Student 1] → NULL
```

Another joins:

```text
[Student 1] → [Student 2] → NULL
```

Another:

```text
[Student 1] → [Student 2] → [Student 3] → NULL
```

So the number of elements can grow dynamically.

Therefore:

```text
Dynamic number of elements

Array        ❌ less natural with a fixed-size array
Linked List  ✅ natural
```

That's one of the main motivations presented in the lecture.

---

# 8. Comparison 3 — Memory

There is a tradeoff.

Suppose you store integers.

### Array

```text
[10][20][30][40]
```

Primarily stores the values themselves.

### Linked List

Every node needs:

```text
┌──────────────┐
│ data         │
├──────────────┤
│ next pointer │
└──────────────┘
```

So in addition to data, every node stores a pointer.

Conceptually:

```text
Array:
[data][data][data]


Linked List:
[data + pointer]
[data + pointer]
[data + pointer]
```

So linked lists have **pointer overhead**.

However, the lecture's broader memory argument is that linked lists can allocate nodes as required rather than requiring a predetermined fixed-capacity block.

---

# 9. Comparison 4 — Random Access

This one is extremely important for GATE/DSA.

Suppose:

```c
int a[100];
```

You want:

```c
a[50]
```

Arrays support direct indexing.

Conceptually:

```text
address(a[i])
=
base address + i × element_size
```

So the machine can directly compute where element `i` is.

Therefore:

```text
Array random access → O(1)
```

---

# 10. Why Linked Lists Don't Have Random Access

Suppose:

```text
head
 ↓
[10] → [20] → [30] → [40] → [50]
```

You want the fourth node.

Can you write something like:

```c
head[3]
```

and jump there in the normal linked-list model?

No.

You have only the address of the first node.

So:

```text
head
 ↓
[10]

follow next
       ↓
      [20]

follow next
              ↓
             [30]

follow next
                     ↓
                    [40]
```

You must traverse through the chain.

The lecture illustrates this contrast on pages 41–42.

Therefore:

```text
Array random access       → O(1)

Linked List random access → O(n)
```

The lecture's comparison can be summarized as:

|Property|Array|Linked List|
|---|---|---|

# 13. The Core Traversal Operation

Before those algorithms, understand this:

```c
head = head->next;
```

Suppose:

```text
head
 ↓
[4] → [15] → [7] → [40] → NULL
```

Initially `head` contains the address of `[4]`.

Now:

```c
head->next
```

contains the address of `[15]`.

Therefore:

```c
head = head->next;
```

copies that address into `head`.

Result:

```text
BEFORE

head
 ↓
[4] → [15] → [7] → [40]


AFTER

       head
        ↓
[4] → [15] → [7] → [40]
```

So:

> `head = head->next` means **move the pointer one node forward**.

The lecture demonstrates this immediately before implementing length.

# 15. Finding Length of a Linked List

Suppose:

```text
head
 ↓
[4] → [15] → [7] → [40] → NULL
```

We want:

```text
length = 4
```

The lecture uses:

```c
int Length(struct node *head)
{
    int count = 0;

    while (head != NULL)
    {
        count++;
        head = head->next;
    }

    return count;
}
```

This is shown across pages 47–48.

---

# 16. Understand the Logic Before Memorizing It

We don't know the number of nodes beforehand.

But we know:

> Every valid node eventually leads us to `NULL`.

So:

```text
while I am standing on a node:
    count it
    move to next node
```

That's literally the algorithm.

```text
count = 0

        head
         ↓
        [4] → [15] → [7] → [40] → NULL
```

---

# 18. Why Passing `head` Like This Doesn't Destroy the Original Head

This is a useful C connection.

Function:

```c
int Length(struct node *head)
```

receives a **copy of the pointer value**.

Suppose original:

```text
head = 1000
```

When calling:

```c
Length(head);
```

the function gets its own local pointer containing:

```text
1000
```

So when the function does:

```c
head = head->next;
```

it's changing its local pointer variable.

The caller's original `head` remains unchanged.

That's why this traversal is safe in this form.

---

# 19. Time and Space Complexity of Length

For `n` nodes:

```text
visit node 1
visit node 2
...
visit node n
```

Therefore:

```text
Time = O(n)
```

Only a counter and pointer are needed:

```text
Extra Space = O(1)
```

# 20. Printing a Linked List

The final two pages implement printing.

The logic is almost identical to finding length.

Instead of:

```c
count++;
```

we do:

```c
printf("%d ", head->data);
```

Then move forward:

```c
head = head->next;
```

So:

```c
void PrintList(struct node *head)
{
    while (head != NULL)
    {
        printf("%d ", head->data);
        head = head->next;
    }
}
```

# 22. Notice the Pattern

Compare length:

```c
while (head != NULL)
{
    count++;
    head = head->next;
}
```

Printing:

```c
while (head != NULL)
{
    printf("%d ", head->data);
    head = head->next;
}
```

Same skeleton:

```c
while (p != NULL)
{
    // DO SOMETHING WITH CURRENT NODE

    p = p->next;
}
```

🔥 **This is the linked-list traversal pattern.**

Don't memorize every algorithm separately.

Learn this abstraction:

```text
START
  ↓
current node
  ↓
do something
  ↓
follow next
  ↓
current node
  ↓
do something
  ↓
follow next
  ↓
...
  ↓
NULL → STOP
```

Then the operation changes depending on the problem:

```text
Find length
→ count++

Print
→ print data

Search
→ compare data

Sum
→ sum += data

Find maximum
→ compare maximum
```

The traversal mechanism stays the same.

# 23. The Big Connection to Trees and Graphs

This is why understanding linked lists properly matters.

Linked list:

```text
NODE
 │
 └── next → ONE next node
```

Tree:

```text
NODE
 ├── left  → another node
 └── right → another node
```

Graph:

```text
NODE
 ├── neighbor
 ├── neighbor
 └── neighbor
```

The same fundamental idea keeps returning:

> **An object stores data + references/pointers to other objects.**

Linked lists are basically your first clean introduction to **pointer-based data structures**.
