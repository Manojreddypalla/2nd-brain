# L-3(3) — Pages 1–16 Notes

### Tricky Recursion on Linked List

> Pages 1–16 mainly cover **recursive insertion at the end of a singly linked list** and its correctness.

## 1. `insertRear()`

**Goal:** Insert a new node at the **end** of a linked list.

### Recursive idea

Think:

> “I don't need to find the last node myself. Ask the next node to insert at its end.”

Base case:

```c
if (l == NULL) {
    Node *n = createNode(data);
    return n;
}
```

Recursive case:

```c
l->next = insertRear(l->next, data);
return l;
```

### Full pattern

```c
Node* insertRear(Node* l, int data)
{
    if (l == NULL)
    {
        Node *n = createNode(data);
        return n;
    }
    else
    {
        l->next = insertRear(l->next, data);
        return l;
    }
}
```

---

## 2. Why `l->next = ...` is important

Suppose:

```text
4 → 7 → 5 → 3 → 2 → NULL
```

Call:

```c
head = insertRear(head, 8);
```

Recursion travels:

```text
insertRear(4)
    ↓
insertRear(7)
    ↓
insertRear(5)
    ↓
insertRear(3)
    ↓
insertRear(2)
    ↓
insertRear(NULL)
```

At `NULL`:

```text
create node 8
return address of 8
```

Now recursion **unwinds**:

```text
2->next = address(8)
3->next = address(2)
5->next = address(3)
7->next = address(5)
4->next = address(7)
```

Final:

```text
4 → 7 → 5 → 3 → 2 → 8 → NULL
```

### Key mental model

**Going down:** find the insertion position.

**Coming back:** reconnect the pointers.

---

## 3. Why `return l`?

Every recursive call must return the **head of the linked list it represents**.

For example:

```text
insertRear(2, 8)
```

returns:

```text
2 → 8 → NULL
```

Then previous call does:

```c
l->next = insertRear(l->next, data);
```

So it reconnects its `next`.

Finally the original `head` is returned unchanged.

### Important

```c
return l;
```

means:

> “My current node is still the head of this sub-list.”

---

## 4. Empty list case

If:

```text
head = NULL
```

then:

```c
insertRear(head, 8)
```

directly creates:

```text
8 → NULL
```

and returns the new node as the new head.

---

## 5. Correctness idea

The proof is based on **induction**:

### Base case

For an empty list:

```text
NULL
```

the function creates the new node correctly.

### Recursive case

Assume:

```c
insertRear(l->next, data)
```

correctly inserts the node into the smaller list.

Then:

```c
l->next = insertRear(l->next, data);
```

connects that modified list back to `l`.

Therefore the whole list is correct.

---

# GATE Important 🔥

### Recursive linked-list pattern

Whenever you see:

```c
l->next = recursive(l->next, ...);
return l;
```

think:

> **Recursion modifies the rest of the list and returns its new head; current node reconnects to it.**

This pattern appears in many linked-list recursion problems, not just insertion.

### Complexity

For a list of `n` nodes:

- **Time:** `O(n)`
    
- **Auxiliary stack:** `O(n)`
    
- **Extra linked-list nodes:** `O(1)` apart from the inserted node.

## One-line revision

```text
insertRear:
NULL → create new node
else → recursively insert in l->next
       l->next = returned head
       return l
```

**Core trick:** **Recursive call goes forward; pointer assignment happens while returning.**
