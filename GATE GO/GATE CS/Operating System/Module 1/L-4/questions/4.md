  
A thread is usually defined as a "light weight process" because an Operating System (OS) maintains smaller data structure for a thread than for a process. In relation to this, which of the following statement is TRUE?

1. On per- thread basis , the OS maintains only CPU register state . 
2. The OS does not maintain a separate stack for each thread .
3. On per- thread basis , the OS does not maintain virtual memory state .
4. On per- thread basis , the OS maintains only scheduling and accounting information .

[](https://gateoverflow.in/user/go_editor)

Yes — **Answer: 3** ✅

The key is understanding **what belongs to the process vs what belongs to each thread**.

### GATE Short Notes

|Option|Statement|Verdict|Why?|
|---|---|---|---|
|**1**|OS maintains **only CPU register state** per thread|❌ False|OS maintains **register state + scheduling/accounting information**, not just registers.|
|**2**|OS does **not** maintain separate stack for each thread|❌ False|**Each thread has its own stack**.|
|**3**|OS does not maintain **virtual memory state** per thread|✅ **TRUE**|Virtual memory/address-space information is generally **process-level**, shared by threads.|
|**4**|OS maintains **only scheduling and accounting information** per thread|❌ False|OS also maintains the **CPU register/context state** of each thread.|

### 🧠 The mental model

Think:

**Process = Resource container**

```text
PROCESS
├── Address space / Virtual memory  ← SHARED
├── Code
├── Data
├── Open files
│
├── Thread 1
│   ├── Registers ← PRIVATE
│   ├── Stack     ← PRIVATE
│   └── Scheduling/accounting info
│
├── Thread 2
│   ├── Registers ← PRIVATE
│   ├── Stack     ← PRIVATE
│   └── Scheduling/accounting info
```

So:

> **Virtual memory → process-level**  
> **Registers → thread-level**  
> **Stack → thread-level**  
> **Scheduling/accounting → thread-level**

### 🔥 Why is it called "lightweight"?

A **process** needs a lot of OS-maintained state, including its virtual memory/address-space information.

A thread **reuses the process's resources**, so the OS needs a smaller amount of **additional per-thread state**.

**Exam shortcut:**  
**Thread = its own execution state, shared process resources.**

Therefore **Option 3** is the correct answer.
