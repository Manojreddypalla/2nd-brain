Which one of the following is **FALSE**?

1. User level threads are not scheduled by the kernel.
2. When a user level thread is blocked, all other threads of its process are blocked.
3. Context switching between user level threads is faster than context switching between kernel level threads.
4. Kernel level threads cannot share the code segment

**Answer: 4 ❌**

Let's make each option GATE-ready:

|#|Statement|Verdict|Reason|
|---|---|---|---|
|**1**|User-level threads are not scheduled by kernel|✅ **TRUE**|Kernel doesn't know individual ULTs. A user-level thread library schedules them.|
|**2**|If a ULT blocks, all other threads of its process are blocked|✅ **TRUE**|Kernel sees the **process**, not individual ULTs. A blocking system call can block the whole process.|
|**3**|ULT context switching is faster than KLT switching|✅ **TRUE**|ULT switch happens in user space → no kernel involvement required.|
|**4**|Kernel-level threads cannot share the code segment|❌ **FALSE**|Threads belonging to the same process **share the process address space**, including **code/text segment**.|

### 🧠 Core picture

```
              PROCESS
       ┌─────────────────────┐
       │ Code/Text   ← SHARE │
       │ Data        ← SHARE │
       │ Heap        ← SHARE │
       │ Files       ← SHARE │
       │                     │
       │ Thread 1            │
       │  ├─ Registers      │
       │  └─ Stack          │
       │                     │
       │ Thread 2            │
       │  ├─ Registers      │
       │  └─ Stack          │
       └─────────────────────┘
```

**Important GATE distinction:**

> **Thread's stack is private/owned, but it exists inside the shared address space.**

So another thread can technically access it if it knows the address.

### 🔑 One-line memory trick

**Threads share resources; threads differ in execution state.**

Shared → **Code, Data, Heap, Address Space, Open Files**  
Per-thread → **Registers, Stack, PC, Scheduling state**

Therefore, **Option 4 is FALSE.**
