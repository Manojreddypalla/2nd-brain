# C Programming — Array of Pointers & Multiple Pointers

## 1. Array of Pointers

```c
int *arr[3];
```

Read from the variable outward:

> `arr` is an **array of 3 pointers to int**.

```text
arr
┌────────┬────────┬────────┐
│ arr[0] │ arr[1] │ arr[2] │
└────────┴────────┴────────┘
    ↓         ↓         ↓
   int       int       int
```

Example:

```c
int a = 10, b = 20, c = 50;

int *arr[3];

arr[0] = &a;
arr[1] = &b;
arr[2] = &c;
```

Memory:

```text
a = 10 @ 2000
b = 20 @ 2010
c = 50 @ 2050

arr:
┌──────┬──────┬──────┐
│ 2000 │ 2010 │ 2050 │
└──────┴──────┴──────┘
   ↓       ↓       ↓
  10      20      50
```

The lecture demonstrates this representation on pages 41–47.

# 2. Accessing Through an Array of Pointers

Given:

```c
int *arr[3];

arr[0] = &a;
arr[1] = &b;
arr[2] = &c;
```

Then:

```c
arr[1]
```

→ address of `b`

```c
*arr[1]
```

→ value of `b`

If:

```text
b = 20
```

then:

```c
*arr[1] == 20
```

### Important identity

```c
*arr[i]
```

means:

> Go to pointer `arr[i]`, then dereference it.

# 3. Pointer Arithmetic on Array of Pointers

Suppose:

```c
int *arr[3];
```

Then:

```c
arr + 1
```

moves from:

```text
arr[0] → arr[1]
```

because `arr` behaves as a pointer to its first element.

So:

```c
*(arr + 1)
```

is equivalent to:

```c
arr[1]
```

And:

```c
**(arr + 1)
```

is equivalent to:

```c
*arr[1]
```

Therefore, if `arr[1]` points to `b`:

```c
**(arr + 1) == b
```

This relationship is explicitly illustrated in the lecture.

---

# 4. `arr[i]` vs `*arr[i]`

Don't mix these up.

```text
arr[i]
 ↓
address

*arr[i]
 ↓
value at that address
```

Example:

```text
arr[1] = 2010
*arr[1] = 20
```

So:

```c
printf("%d", arr[1]);
```

would attempt to print an address using `%d` and is not the intended way to print the pointer.

Whereas:

```c
printf("%d", *arr[1]);
```

prints the pointed-to integer.


# 12. Pointer to an Array of Pointers

This is where pointer levels become important.

Suppose:

```c
int *arr[3];
```

Then:

```c
int **p = arr;
```

Why?

Because:

```text
arr
 ↓
first element of arr

arr[0]
 ↓
int *

therefore

arr
 ↓
int **
```

So:

```c
int **p = arr;
```

is valid.

# 13. Pointer-to-Pointer Example

Consider:

```c
int a[] = {1,2,3};
int b[] = {10,20,30};
int c[] = {5,6,7};

int *arr[] = {a,b,c};

int **pp = arr;
```

Memory:

```text
a → [1  2  3]

b → [10 20 30]

c → [5  6  7]

arr:
┌─────┬─────┬─────┐
│  a  │  b  │  c  │
└─────┴─────┴─────┘
   ↑
  pp
```

Important:

```text
pp
 ↓
arr
 ↓
arr[0]
 ↓
a
 ↓
[1 2 3]
```

So there are **two levels of pointers**.

---

# 14. `**pp`

Initially:

```c
int **pp = arr;
```

Then:

```c
*pp
```

gives:

```c
arr[0]
```

which is:

```text
a
```

Then:

```c
**pp
```

dereferences `a`:

```text
a[0]
```

Therefore:

```c
**pp = 1
```

---

# 15. `pp++`

Now:

```c
pp++;
```

Remember:

```c
pp
```

has type:

```c
int **
```

Therefore pointer arithmetic moves by:

```text
sizeof(int *)
```

So `pp` moves from:

```text
arr[0] → arr[1]
```

Now:

```text
pp
 ↓
arr[1]
 ↓
b
 ↓
[10 20 30]
```

Therefore:

```c
**pp
```

now gives:

```text
10
```

The lecture demonstrates this pointer movement on pages 59–61.

```text
b
```

```c

```

then:

```c
pp[1][2]
```

can be understood as:

```text
pp[1]
 ↓
arr[1]
 ↓
b

b[2]
 ↓
30
```

So:

```c
pp[1][2] == arr[1][2] == b[2]
```

For the lecture's values:

```text

```

# 18. `*(pp++)` vs `(*pp)++`

This is a classic pointer-expression trap.

### `pp++`

Moves the pointer:

```text
pp → next location
```

### `(*pp)++`

Changes the value stored at the location pointed to by `pp`.

The parentheses matter enormously.

```c
(*pp)++
```

means:

> Dereference `pp`, then increment that resulting value.

Whereas:

```c
pp++
```

means:

> Increment the pointer itself.


# 21. `(*pp)++` with Strings

Suppose:

```c
char **pp = arr;
```

Then:

```c
(*pp)++
```

does **not** modify the character.

It increments the pointer stored in `arr[0]`.

So:

```text
u
 ↓
G A T E \0
↑
```

After:

```c
(*pp)++;
```

the pointer moves:

```text
u
 ↓
G A T E \0
  ↑
```

Now it points to `'A'`.

This is why pointer-level dry runs are so important.

# GATE Mental Model 🧠

When you see multiple `*`, **don't evaluate the whole expression at once**.

Walk through one level at a time.

For:

```c
char **pp = arr;
```

think:

```text
pp
 ↓
arr[i]
 ↓
char *
 ↓
character
```

Therefore:

```text
pp       → pointer to pointer
*pp      → pointer
**pp     → character
```

This single mental model handles most of the questions in this section.

# GATE Traps 🔥

### Trap 1 — Array of pointers

```c
int *arr[3];
```

❌ Not a 2D integer array.

✅ Array containing 3 integer pointers.

---

### Trap 2 — `*arr[i]`

```c
arr[i]
```

→ pointer/address

```c
*arr[i]
```

→ pointed value

---

### Trap 3 — `pp++`

If:

```c
int **pp;
```

then:

```c
pp++;
```

moves by:

```text
sizeof(int *)
```

not `sizeof(int)`.

---

### Trap 4 — String literal vs character array

```c
char *p = "GATE";
```

and

```c
char p[] = "GATE";
```

are **not equivalent storage arrangements**.

The lecture specifically demonstrates that modifying through the string-pointer form is not allowed, while modification of the character-array form is allowed.

---

### Trap 5 — Pointer increment vs pointed-value increment

```c
pp++;
```

→ pointer moves.

```c
(*pp)++;
```

→ value/pointer stored at `pp` is incremented.

# Quick Revision

```text
ARRAY OF POINTERS
─────────────────

int *arr[3];

arr[i]       → pointer
*arr[i]      → pointed value

arr + 1      → next pointer element


POINTER TO POINTER
──────────────────

int **pp = arr;

pp
 ↓
arr[i]
 ↓
int *
 ↓
int


STRING POINTER ARRAY
────────────────────

char *sports[5];

sports[i]      → pointer to string
sports[i][j]   → j-th character


2D CHARACTER ARRAY
──────────────────

char sports[5][8];

sports[i][j] → actual character storage

Can modify:
sports[i][j] = 'x';


MULTIPLE POINTERS
─────────────────

pp          → pointer
*pp         → pointer
**pp        → value

pp++        → move pointer
(*pp)++     → increment pointed value
```

### The big pattern to remember

```text
One *
→ remove one pointer level

Two *
→ remove two pointer levels

Three *
→ remove three pointer levels
```

So when solving a GATE expression, **keep peeling one layer at a time** instead of trying to mentally jump straight to the answer.
