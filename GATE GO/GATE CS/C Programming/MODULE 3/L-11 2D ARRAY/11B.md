# C Programming — 2D Arrays & Pointer Relationships

## 1. Array of Pointers vs Pointer to Array

This is one of the most important distinctions in this lecture.

### Array of pointers

```c
int *p[4];
```

Read from the variable outward:

> `p` is an **array of 4 pointers to int**.

Memory:

```text
p
┌────┬────┬────┬────┐
│ p0 │ p1 │ p2 │ p3 │
└────┴────┴────┴────┘
  ↓    ↓    ↓    ↓
 int  int  int  int
```

Each `p[i]` stores an address.

Equivalent idea:

```c
int *p[4];
```

→ 4 integer pointers.

---

### Pointer to an array

```c
int (*p)[4];
```

Read:

> `p` is a **pointer to an array of 4 integers**.

```text
p
 ↓
┌────┬────┬────┬────┐
│    │    │    │    │
└────┴────┴────┴────┘
```

Here `p` points to the **whole array**, not one individual integer.

### GATE trap

```c
int *p[4];     // array of 4 int pointers
int (*p)[4];   // pointer to array of 4 ints
```

Parentheses completely change the meaning.

---

# 2. Pointer to 1D Array

Consider:

```c
int a[4] = {1,2,3,4};
int (*p)[4];

p = &a;
```

`a`:

```text
1000    1004    1008    1012
 ↓       ↓       ↓       ↓
┌───┬───┬───┬───┐
│ 1 │ 2 │ 3 │ 4 │
└───┴───┴───┴───┘
```

`p` stores address `1000`.

Therefore:

```c
*p
```

means the entire array `a`.

And:

```c
(*p)[i]
```

accesses `a[i]`.

For example:

```c
(*p)[2] = 3
```

The lecture demonstrates this pointer-to-array interpretation.

---

# 3. Pointer Arithmetic

For an `int *`:

```c
int *p;
```

If `sizeof(int) = 4`:

```text
p       → address 1000
p + 1   → address 1004
p + 2   → address 1008
```

So:

> Pointer arithmetic moves according to the **size of the pointed-to type**, not by 1 byte.

### Important

```c
p + 1
```

means:

```text
address + sizeof(*p)
```

not simply address + 1.

---

# 4. Example: `ptr = (int*)(&a + 1)`

Given:

```c
int a[] = {1,2,3,4,5,6};

int *ptr = (int*)(&a + 1);

printf("%d", *(ptr - 1));
```

Key idea:

```c
&a
```

is pointer to the **entire array**.

Since `a` contains 6 integers:

```text
&a
 ↓
┌──1──┬──2──┬──3──┬──4──┬──5──┬──6──┐
```

Therefore:

```c
&a + 1
```

moves by the **size of the whole array**.

So it points just after `6`.

Then:

```c
ptr - 1
```

moves back by one `int`.

Therefore:

```c
*(ptr - 1) = 6
```

This exact pointer-arithmetic pattern appears in the lecture.

### GATE pattern

Whenever you see:

```c
(int*)(&array + 1)
```

think:

> **Go to the end of the entire array.**

Then `-1` usually brings you to the last element.

# 5. `sizeof` with Pointers

Example from the lecture:

```c
int arr[] = {3,5,6,7,9};

int *p = arr;
int (*ptr)[5] = &arr;
```

Assuming:

```text
sizeof(int) = 4
```

Then:

```c
sizeof(p)       → size of pointer
sizeof(*p)      → size of int = 4

sizeof(ptr)     → size of pointer
sizeof(*ptr)    → size of entire array
                  = 5 × 4
                  = 20
```

### Very important mental model

```text
p
 ↓
one int

ptr
 ↓
entire array
```

So:

```c
*p
```

is an `int`.

But:

```c
*ptr
```

is an **array of 5 integers**.

# 6. 2D Array Memory Model

Consider:

```c
int a[4][4];
```

Think of it as:

```text
a
 ↓
┌───────────────┐
│ row 0         │
├───────────────┤
│ row 1         │
├───────────────┤
│ row 2         │
├───────────────┤
│ row 3         │
└───────────────┘
```

Each row contains 4 integers.

So:

```c
a
```

points to the **first row**.

More precisely:

```c
a : pointer to an array of 4 integers
```

Conceptually:

```c
int (*p)[4] = a;
```

This is why 2D arrays and pointer-to-array are tightly connected.

---

# 7. `a`, `a+1`, `*a`, `a[0]`

For:

```c
int a[4][4];
```

### `a`

Points to first row.

```text
a
↓
row 0
```

### `a + 1`

Moves to the **next row**.

```text
a       → row 0
a + 1   → row 1
```

Important:

It does **not** move by one integer.

It moves by:

```text
sizeof(one row)
= 4 × sizeof(int)
```

---

### `*a`

Dereferences `a`.

Since `a` points to row 0:

```c
*a
```

represents row 0.

And because an array expression usually decays to a pointer when used in an expression:

```c
*a
```

can behave as a pointer to the first element of row 0.

Thus:

```c
**a
```

gives:

```text
a[0][0]
```

---

# 8. The Core 2D-Array Identity

For:

```c
int a[R][C];
```

the following are equivalent for accessing elements:

```c
a[i][j]

*(a[i] + j)

*(*(a + i) + j)

*(&a[0][0] + i*C + j)
```

The lecture repeatedly uses this idea through pointer manipulation.

### Most important one

```c
a[i][j]
```

is equivalent to:

```c
*(*(a+i)+j)
```

Think:

```text
a
 ↓
+a
 ↓
row i
 ↓
*a
 ↓
first element of row i
 ↓
+j
 ↓
column j
 ↓
*
 ↓
value
```

---

# 9. Why `a + i` Moves by Rows

Suppose:

```c
int a[4][5];
```

Each row has:

```text
5 integers
```

Therefore:

```c
a + 1
```

moves by:

```text
5 × sizeof(int)
```

If `sizeof(int)=4`:

```text
a + 1 = address + 20 bytes
```

### GATE trap

For a 2D array:

```c
a + 1
```

does **not** mean next integer.

It means:

> **next row**

because `a` is a pointer to an array of 5 integers.

---

# 10. Pointer-to-Array Declaration

For:

```c
int (*p)[5];
```

read it as:

> `p` points to an array containing 5 integers.

Therefore:

```c
*p
```

is an array of 5 integers.

And:

```c
(*p)[i]
```

accesses an element inside that row.

The lecture explicitly contrasts this with `int *p[4]`.

---

# 11. Important Pointer Type Comparison

|Declaration|Meaning|
|---|---|
|`int *p`|pointer to int|
|`int *p[4]`|array of 4 pointers to int|
|`int (*p)[4]`|pointer to array of 4 ints|
|`int **p`|pointer to pointer to int|
|`int (*p)[5]`|pointer to array of 5 ints|

### Pattern

Parentheses determine what `*` belongs to.

```c
int *p[4]
```

`[]` binds before `*`

→ array first.

But:

```c
int (*p)[4]
```

parentheses force `*p` together.

→ pointer first.

---

# 12. GATE Problem Pattern: `&a + 1`

For:

```c
int a[5];
```

Compare:

```c
a + 1
```

vs

```c
&a + 1
```

### `a + 1`

`a` decays to:

```c
int *
```

So it moves by:

```text
sizeof(int)
```

### `&a + 1`

`&a` is:

```c
int (*)[5]
```

So it moves by:

```text
sizeof(entire array)
```

Therefore:

```text
a + 1   → next int
&a + 1  → after entire array
```

🔥 **This distinction is extremely GATE-relevant.**

# 13. 2D Array + Pointer-to-Array

Example:

```c
int arr[4][4] = {
    {1,2,3,4},
    {6,7,8,9}
};

int (*a)[4];

a = arr;
++a;

printf("%d", **a);
```

Initially:

```text
a
↓
row 0

1 2 3 4
```

After:

```c
++a;
```

`a` moves to the next **row**:

```text
6 7 8 9
↑
a
```

Then:

```c
*a
```

→ first element of row 1.

Then:

```c
**a
```

→ `6`.

This is demonstrated on page 40.

# GATE Corner 🧠

### Memorize the mental model, not formulas

For:

```c
int a[R][C];
```

think:

```text
a
│
▼
┌───────────────┐
│ C integers    │ ← row 0
├───────────────┤
│ C integers    │ ← row 1
├───────────────┤
│ C integers    │ ← row 2
└───────────────┘
```

Therefore:

```text
a       → first row
a + 1   → next row
*a      → first row
*a + 1  → next element in first row
**a     → first element
```

And:

```c
a[i][j] == *(*(a+i)+j)
```

```text
int *p[4]
→ array of 4 int pointers

int (*p)[4]
→ pointer to array of 4 ints

a[i][j]
→ *(*(a+i)+j)

For int a[R][C]:

a + 1
→ next row

*a
→ first row

**a
→ a[0][0]

&a + 1
→ after the entire array

a + 1
→ next element/row depending on a's decayed type
```

### ⚠️ Biggest GATE traps

1. **`int *p[4]` ≠ `int (*p)[4]`**
    
2. `a + 1` for a 2D array moves **one complete row**.
    
3. `&a + 1` moves past the **entire array**.
    
4. Pointer arithmetic depends on the **pointed-to type**.
    
5. `sizeof(*p)` can mean either one element or an entire row/array depending on `p`'s type.
    
6. Always identify the **type of the pointer first**, then perform arithmetic.
