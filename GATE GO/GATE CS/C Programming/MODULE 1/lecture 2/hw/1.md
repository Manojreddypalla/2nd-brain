## Question 1 — Truncation

**Assume:**

- `int` = 32 bits
    
- `short` = 16 bits
    

```c
int i = -3;
unsigned short u;

u = i;

printf("%u", u);
printf("%d", u);
```

### Explanation

#### 1. `i = -3`

`int` is 32-bit. In 2's complement:

```text
-3 = 11111111 11111111 11111111 11111101
```

#### 2. `u = i`

`u` is only **16 bits**, so when the 32-bit value is stored in it, the **higher 16 bits are truncated**:

```text
11111111 11111111 | 11111111 11111101
       removed     |     kept
```

So `u` contains:

```text
11111111 11111101
```

This is **65533** when interpreted as `unsigned short`.

```text
u = 65533
```

The lecture describes this as truncation from higher bits to lower bits.

#### 3. Before `printf`

`u` is an `unsigned short`, but it undergoes **integer promotion**.

Here it is promoted to a **32-bit `int`** while preserving the value:

```text
unsigned short
     65533
       ↓
integer promotion
       ↓
int
     65533
```

The lecture explicitly shows this promotion before both `printf` calls.

#### 4. Printing

The lecture's intended result is:

```text
printf("%u", u);  → 65533
printf("%d", u);  → 65533
```

### ✅ Answer

```text
65533 65533
```

### GATE takeaway

```text
32-bit -3
    ↓ truncation
16-bit 11111111 11111101
    ↓
65533
    ↓ integer promotion
32-bit 65533
```

**Key idea:**  
**Truncation changes the bit pattern being retained; integer promotion then increases the width again.**


```
int (32-bit)

00000000 00000000 11111111 11111101
^^^^^^^^^^^^^^^^
added during promotion
```
