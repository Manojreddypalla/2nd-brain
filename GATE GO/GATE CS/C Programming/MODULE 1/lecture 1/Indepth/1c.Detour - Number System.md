# Detour — Number System

## 1. Why Number Systems in C?

When we write:

```c
int a = 4;
int x = -5;
```

we write numbers in **decimal form**, but internally memory represents information using bits:

```text
0 and 1
```

So we need to understand:

```text
Decimal Number
      ↓
Binary Representation
      ↓
Bits in Memory
```

This is especially important for understanding:

- Signed integers
    
- Unsigned integers
    
- Negative numbers
    
- Integer ranges
    
- Bitwise operations
    

> [!note]  
> This is only a brief detour required for C programming. Detailed Number Systems are studied under **Digital Logic**.

# 2. Binary Number System

> [!definition] Binary Number System  
> The **binary number system** is a base-2 number system that uses only two digits:
> 
> `0` and `1`

Each binary digit is called a **bit**.

> [!definition] Bit  
> A **bit (binary digit)** is a single binary value that can be either `0` or `1`.

Binary positions represent powers of `2`.

```text
... 2⁵  2⁴  2³  2²  2¹  2⁰
```

For example:

```text
101101
```

has positional weights:

```text
1      0      1      1      0      1
↓      ↓      ↓      ↓      ↓      ↓
2⁵     2⁴     2³     2²     2¹     2⁰
```

# 3. Decimal → Binary

The lecture uses the **repeated division by 2** method.

## Method

To convert a positive decimal integer to binary:

1. Divide the number by `2`.
    
2. Record the remainder.
    
3. Divide the quotient again by `2`.
    
4. Continue until the quotient becomes `0`.
    
5. Read the remainders **from bottom to top**.
    

---

## Example — Convert 29 to Binary

```text
29 ÷ 2 = 14    remainder 1
14 ÷ 2 = 7     remainder 0
 7 ÷ 2 = 3     remainder 1
 3 ÷ 2 = 1     remainder 1
 1 ÷ 2 = 0     remainder 1
```

Read from bottom to top:

```text
11101
```

Therefore:

$$  
29_{10}=11101_2  
$$

### Verification

```text
11101

1×2⁴ + 1×2³ + 1×2² + 0×2¹ + 1×2⁰

= 16 + 8 + 4 + 0 + 1

= 29
```

---

## Example — Convert 35 to Binary

Repeated division gives:

```text
35 ÷ 2 → remainder 1
17 ÷ 2 → remainder 1
 8 ÷ 2 → remainder 0
 4 ÷ 2 → remainder 0
 2 ÷ 2 → remainder 0
 1 ÷ 2 → remainder 1
```

Bottom → top:

```text
100011
```

Therefore:

$$  
35_{10}=100011_2  
$$

Verification:

$$  
2^5+2^1+2^0  
$$

$$  
=32+2+1=35  
$$

# 4. Binary → Decimal

To convert binary to decimal, multiply every bit by its positional power of `2` and add the results.

For:

```text
bₙ ... b₂ b₁ b₀
```

the rightmost bit corresponds to:

$$  
2^0  
$$

then:

$$  
2^1,;2^2,;2^3,\dots  
$$

---

## Example — `100011`

```text
1      0      0      0      1      1
↓      ↓      ↓      ↓      ↓      ↓
2⁵     2⁴     2³     2²     2¹     2⁰
```

Therefore:

$$  
1(2^5)+0(2^4)+0(2^3)+0(2^2)+1(2^1)+1(2^0)  
$$

$$  
=32+2+1  
$$

$$  
=35  
$$

So:

$$  
100011_2=35_{10}  
$$

---

## Example — `101101`

```text
1      0      1      1      0      1
↓      ↓      ↓      ↓      ↓      ↓
2⁵     2⁴     2³     2²     2¹     2⁰
```

$$  
=1(32)+0(16)+1(8)+1(4)+0(2)+1(1)  
$$

$$  
=32+8+4+1  
$$

$$  
=45  
$$

Therefore:

$$  
101101_2=45_{10}  
$$

# 5. Important Mental Model

Normal binary positional values:

```text
Bit Position:   5   4   3   2   1   0

Weight:        32  16   8   4   2   1
```

So for:

```text
101101
```

just select the weights whose bits are `1`:

```text
1 → 32
0 → ignore
1 → 8
1 → 4
0 → ignore
1 → 1
```

Therefore:

```text
32 + 8 + 4 + 1 = 45
```

# 6. Why Ordinary Binary Is Not Enough

For positive numbers, normal binary representation works naturally.

Example:

```text
5 → 0101
```

But C also needs to represent:

```c
int x = -5;
```

Memory still only contains bits.

There is no literal `-` symbol stored beside the number:

```text
-5
```

So we need a binary convention capable of representing **negative numbers**.

# 2's Complement System

# 7. 2's Complement System

> [!definition] 2's Complement  
> **2's complement** is a binary representation system used to represent signed integers, including negative values.

The lecture gives two basic cases.

### Positive Number

Represent it using its usual binary representation, while ensuring the chosen bit-width gives an appropriate sign bit.

### Negative Number

Represent the magnitude in binary and take its **2's complement**.

---

# 8. MSB — Most Significant Bit

> [!definition] MSB  
> The **Most Significant Bit (MSB)** is the leftmost bit of a binary representation.

For an `n`-bit 2's-complement signed number, the MSB indicates whether the represented value is non-negative or negative:

```text
MSB = 0 → non-negative
MSB = 1 → negative
```

Example:

```text
0101
↑
MSB = 0
```

So it represents a non-negative value.

Whereas:

```text
1011
↑
MSB = 1
```

represents a negative value in 4-bit 2's complement.

---

# 9. Bit Width Matters

This is extremely important.

A bit pattern has to be interpreted with a known width and representation.

For example, to represent positive `5`:

```text
101
```

is ordinary binary for `5`.

But if we say this is a **3-bit 2's-complement signed value**, its MSB is `1`, so it does **not** represent positive `5`.

Therefore, for positive `5`, we need enough bits to keep the sign bit `0`.

Using 4 bits:

```text
0101
```

Now:

```text
MSB = 0
```

and the value is:

```text
5
```

This exact bit-width issue is highlighted in the lecture.

> [!warning]  
> Never solve a 2's-complement question without checking the **number of bits**.

# 10. Computing 2's Complement

The lecture gives the standard procedure:

### Step 1 — Complement every bit

```text
0 → 1
1 → 0
```

This gives the **1's complement**.

### Step 2 — Add `1`

```text
2's complement
=
invert all bits + 1
```

Mental model:

```text
Original
   ↓
Flip every bit
   ↓
Add 1
   ↓
2's Complement
```

---

# 11. Example — 2's Complement of `0100`

Original:

```text
0100
```

### Step 1 — Flip bits

```text
0100
 ↓
1011
```

### Step 2 — Add 1

```text
  1011
+    1
------
  1100
```

Therefore:

```text
2's complement of 0100 = 1100
```

# 12. Example — 2's Complement of `101101`

```text
  010011
```

# 13. Representing a Positive Number

Suppose we want to represent:

```text
+5
```

Using 4-bit 2's complement:

Normal binary:

```text
5 = 101
```

Add a leading `0`:

```text
0101
```

Therefore:

```text
+5 = 0101
```

because:

```text
MSB = 0
```

# 14. Representing a Negative Number

Suppose we want to represent:

```text
-5
```

using **4 bits**.

### Step 1 — Represent +5

```text
+5 = 0101
```

### Step 2 — Flip all bits

```text
0101
↓
1010
```

### Step 3 — Add 1

```text
  1010
+    1
------
  1011
```

Therefore:

```text
-5 = 1011
```

in 4-bit 2's complement.

The lecture uses this exact `-5 → 1011` memory example.

```text
+5 → 0101
```

# 16. GATE Example — Represent `-28` in 16 Bits

The lecture solves a GATE CSE 2019 question using this procedure.

First represent positive `28`:

```text
28 = 16 + 8 + 4
```

Binary:

```text
0000 0000 0001 1100
```

Now invert all bits:

```text
1111 1111 1110 0011
```

Add `1`:

```text
1111 1111 1110 0011
+                  1
--------------------
1111 1111 1110 0100
```

Therefore:

```text
-28 = 1111 1111 1110 0100
```

in 16-bit 2's complement.

# 17. Positive Numbers in 2's Complement

The lecture also gives the example of decimal `43`.

For a positive number, use its ordinary binary representation with a leading `0` as necessary for the chosen signed width.

```text
43 = 32 + 8 + 2 + 1
```

Therefore:

```text
00101011
```

for an 8-bit representation.

Because:


it represents a positive value.

# 18. Same Bits Can Mean Different Things

This is one of the most important ideas in this section.

Consider:

```text
10001
```

If interpreted as **ordinary unsigned binary**:

$$  
2^4+2^0  
$$

$$  
=16+1  
$$

$$  
=17  
$$

But if interpreted as a **5-bit 2's-complement signed number**, it represents:

```text
-15
```

The lecture explicitly contrasts these interpretations.

> [!important]  
> Bits alone do not tell you the mathematical value.
> 
> You must know **how those bits are being interpreted**.

Mental model:

```text
Bits
+
Representation/Interpretation
=
Value
```
