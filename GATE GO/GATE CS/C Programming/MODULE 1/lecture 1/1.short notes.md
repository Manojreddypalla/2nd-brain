```c

    printf("Hello World!\n");
```

# 6. Number Systems

### Decimal → Binary

Repeatedly divide by `2` and collect **remainders from bottom → top**.

Example:

```text
29 / 2 → remainder 1
14 / 2 → remainder 0
 7 / 2 → remainder 1
 3 / 2 → remainder 1
 1 / 2 → remainder 1
```

Therefore:

```text
29₁₀ = 11101₂
```

### Binary → Decimal

Each bit represents a power of 2:

```text
101101
 ↓↓↓↓↓↓
2⁵ 2⁴ 2³ 2² 2¹ 2⁰
```

So:

```text
101101₂
= 1×2⁵ + 0×2⁴ + 1×2³ + 1×2² + 0×2¹ + 1×2⁰
= 45
```

# 7. The BIG GATE Concept: Same Bits ≠ Same Number

This is one of the most important ideas from this lecture.

Consider:

```text
1010
```

### Unsigned interpretation

```text
1010 = 2³ + 2¹
     = 8 + 2
     = 10
```

### Signed 2's-complement interpretation

MSB is `1` → negative.

For 4-bit 2's complement:

```text
1010
```

Value:

```text
-2³ + 0×2² + 1×2¹ + 0×2⁰
= -8 + 2
= -6
```

Therefore:

```text
1010

unsigned       → 10
signed 2's C   → -6
```

**Same bits, different interpretation.**

> 🧠 **Mental model:** Bits don't inherently mean a number.  
> **The representation tells you how to interpret those bits.**

This idea becomes extremely important later in **COA, OS, C, and memory-related GATE questions.**

# 8. 2's Complement

For a positive number:

```text
Represent normally in binary.
```

For a negative number:

```text
1. Write magnitude in binary
2. Complement every bit
3. Add 1
```

Example:

```text
+4 = 0100

1's complement:
1011

+1:
1100

Therefore:
-4 = 1100   (4-bit 2's complement)
```

The lecture explicitly uses **invert bits + add 1** as the method.

---

# 9. MSB = Sign Bit

In signed 2's-complement:

```text
MSB = 0 → positive
MSB = 1 → negative
```

Example:

```text
0101 → positive
1011 → negative
```

---

# 10. Converting 2's Complement → Decimal

### Method 1 — Weighted representation

For an `n`-bit signed 2's-complement number:

```text
MSB has weight -2^(n-1)

remaining bits:
+2^(n-2), +2^(n-3), ... +2⁰
```

Example:

```text
1011

= -2³ + 0×2² + 1×2¹ + 1×2⁰
= -8 + 2 + 1
= -5
```

### Method 2 — Easier for negative values

If MSB = `1`:

```text
1. Take 2's complement
2. Convert resulting binary to decimal
3. Put negative sign
```

Example:

```text
1011
 ↓
2's complement → 0101
 ↓
5
 ↓
-5
```


# 12. Bit Extension ⭐

When moving from fewer bits → more bits, **the value must remain unchanged**.

### Unsigned → Zero Extension

Fill extra MSBs with `0`.

Example:

```text
4-bit:
0101

8-bit:
00000101
```

### Signed → Sign Extension

Copy the **sign bit**.

```text
Positive:
0101 → 00000101

Negative:
1011 → 11111011
```

So:

```text
MSB = 0 → add 0s
MSB = 1 → add 1s
```

### Why?

Because we're changing the **number of bits**, not the actual value.

Think:

```text
Same number
   ↓
different storage width
   ↓
extend representation without changing value
```

# 13. Signed Number Range ⭐⭐⭐

For **k-bit unsigned**:

```text
Minimum = 0
Maximum = 2ᵏ - 1
```

So:

```text
8-bit unsigned
→ 0 to 255
```

### k-bit signed 2's complement

```text
Minimum = -2^(k-1)

Maximum = 2^(k-1) - 1
```

Therefore:

```text
8-bit signed:

-128 to +127
```

### Why asymmetric?

There are `2ᵏ` possible bit patterns.

Half are negative and half are non-negative:

```text
negative:      2^(k-1)
non-negative:  2^(k-1)
```

But zero occupies one of the non-negative patterns, giving:

```text
-2^(k-1) ... -1
0 ... 2^(k-1)-1
```

# 🧠 GATE Corner — What You Actually Need to Remember

Don't memorize the lecture page-by-page. Reduce it to these **7 mental rules**:

```text
1. Same bits can represent different values depending on interpretation.

2. Unsigned k-bit:
   0 → 2^k - 1

3. Signed 2's-complement k-bit:
   -2^(k-1) → 2^(k-1)-1

4. MSB:
   0 → positive
   1 → negative

5. Negative 2's complement:
   invert bits + 1

6. Unsigned extension:
   add 0s

7. Signed extension:
   replicate MSB
```

### The pattern to recognize in GATE

Whenever you see:

```text
"n-bit"
"unsigned"
"signed"
"2's complement"
"representation"
"sign extension"
"zero extension"
"range"
"minimum / maximum"
```

**STOP.**

Before calculating, ask:

> **What interpretation are these bits using?**

That one habit prevents a _lot_ of silly GATE mistakes.

The lecture's later questions are essentially testing exactly these representation/interpretation patterns.
