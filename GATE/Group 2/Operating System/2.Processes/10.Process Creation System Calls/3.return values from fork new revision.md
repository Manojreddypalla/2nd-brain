# `fork()` Return Values ⭐⭐⭐⭐⭐

## Core Idea

> **`fork()` is called once by the parent, but returns twice.**

Why?

Because after a successful `fork()`, **two processes exist**:

- Parent Process
    
- Child Process
    

Both resume execution from the **instruction immediately after `fork()`**.

The kernel returns **different values** so each process knows its role.

---

# Syntax

```c
pid_t pid = fork();
```

> **Important:** The variable `pid` stores the **return value of `fork()`**, **NOT** the process's own PID.

To get a process's own PID:

```c
getpid();
```

---

# Return Values

|Return Value|Returned To|Meaning|
|---|---|---|
|`> 0`|Parent|Child created successfully. Return value is the **child's actual PID**.|
|`0`|Child|Indicates **"I am the child process."**|
|`-1`|Parent|Process creation failed. **No child process is created.**|

---

# Visual

```text
             Parent
                │
             fork()
                │
      ┌─────────┴─────────┐
      ▼                   ▼
 Parent               Child

fork() returns

Parent → Child PID (>0)

Child  → 0
```

---

# Why Does the Parent Get Child's PID?

Suppose

```text
Parent PID = 100

Child PID = 101
```

The parent receives

```text
pid = 101
```

This tells the parent

> "Your child is process 101."

The parent later uses this PID for

- `wait()`
    
- `waitpid()`
    
- `kill()`
    
- Managing multiple child processes
    

---

# Why Does the Child Get `0`?

The child **already has its own PID**.

It can obtain it anytime using

```c
getpid();
```

So the return value **0 is NOT the child's PID**.

It is simply a special value chosen by the kernel to identify

> "You are the child."

This allows code like

```c
if (pid == 0)
{
    // Child Code
}
else
{
    // Parent Code
}
```

Without returning `0`, both processes would execute the same branch.

---

# Why Doesn't the Child Receive Its Own PID?

Because it is unnecessary.

The child can always do

```c
getpid();
```

The parent, however, **needs the child's PID** to manage it.

Therefore

```text
Parent

↓

Receives Child's PID
```

```text
Child

↓

Receives 0
```

---

# What Happens When `fork()` Fails?

If the kernel cannot create a new process because of

- insufficient memory,
    
- process limit reached,
    
- insufficient system resources,
    

then

```text
fork()

↓

Returns -1

↓

No Child Exists
```

Only the parent continues executing.

---

# Memory Example

Suppose

```text
Parent PID = 200
```

After `fork()`

```text
Parent PID = 200

Child PID = 201
```

### Parent

```text
Actual PID = 200

fork() returned = 201
```

### Child

```text
Actual PID = 201

fork() returned = 0
```

Notice

```text
fork() return value

≠

Actual Process PID
```

# Example Program

```c
#include <stdio.h>
#include <unistd.h>

int main()
{
    pid_t pid = fork();

    if(pid == -1)
    {
        printf("Fork Failed\n");
    }
    else if(pid == 0)
    {
        printf("Child\n");
    }
    else
    {
        printf("Parent\n");
    }

    return 0;
}
```

# Common Mistakes

❌ `0` is the child's PID.

✔ False.

`0` is only the return value of `fork()`.

---

❌ `pid` stores my process ID.

✔ False.

`pid` stores the **return value of `fork()`**.

Use

```c
getpid();
```

to obtain the process's PID.

---

❌ Child calls `fork()`.

✔ False.

The parent calls `fork()` once.

The kernel creates the child.

Both return from the **same** `fork()` system call.

---

❌ `-1` means the child was created incorrectly.

✔ False.

`-1` means **no child process was created**.

---

# Interview/GATE One-Liner ⭐⭐⭐⭐⭐

> **`fork()` is called once by the parent but returns twice. The parent receives the child's actual PID, the child receives `0` to identify itself, and `-1` indicates that child creation failed.**
