# 2. Process States (GATE)

This is one of the **most important topics in Operating Systems**. Many GATE questions ask you to identify the current state of a process after a given event.

---

# Intuition

Imagine you're waiting at a railway station.

You don't spend your entire journey sitting inside the train.

Instead, you go through different stages:

```text
Bought Ticket
      ↓
Waiting at Platform
      ↓
Train Arrives
      ↓
Travelling
      ↓
Train Stops
      ↓
Waiting Again
      ↓
Destination
```

A process behaves similarly. It doesn't continuously use the CPU. It moves between different **states** depending on what it's doing.

---

# Why Do We Need Process States?

Suppose your computer is running:

- Chrome
    
- VS Code
    
- Spotify
    
- Terminal
    
- Discord
    

There is only **one CPU core**.

The CPU cannot execute all of them simultaneously.

So the OS must know:

- Which process is ready?
    
- Which one is currently running?
    
- Which one is waiting for I/O?
    
- Which one has finished?
    

To track this, the OS maintains **process states**.

# 1. New State

## Meaning

The process has just been created.

Example:

```cpp
fork();
```

Immediately after creation, the child process enters the **New** state.

The OS now:

- allocates memory
    
- creates the PCB
    
- assigns a PID
    
- initializes registers
    
- prepares resources
    

The process **cannot execute yet**.

---

## Transition

```text
NEW
 ↓
READY
```

when the OS admits it into memory.

---

# 2. Ready State

This is probably the most misunderstood state.

## Meaning

The process is **ready to execute**.

The only thing it lacks is the CPU.

Think of it as:

> "I'm prepared. Just give me the processor."

---

Example

Suppose three processes exist.

```text
P1

P2

P3
```

Only one CPU.

The scheduler chooses one.

```text
CPU

↓

P1 Running

P2 Ready

P3 Ready
```

P2 is **not waiting for I/O**.

It is waiting only for CPU.

---

# Ready Queue

All ready processes stay in the **Ready Queue**.

```text
Ready Queue

P2

P3

P4

P5
```

The CPU Scheduler selects one process from this queue.

---

# Transition

```text
READY

↓

RUNNING
```

Occurs when the scheduler assigns the CPU.

---

# 3. Running State

Meaning:

The CPU is executing the process.

Only **one process per CPU core** can be in the Running state.

---

Example

```cpp
int main()
{
    int a=5;
    int b=10;
    cout<<a+b;
}
```

While these instructions are executing,

the process is in the **Running** state.

---

# From Running

Three possibilities exist.

## A) Time Quantum Ends

```text
Running

↓

Ready
```

The scheduler preempts it.

---

## B) Needs I/O

Suppose

```cpp
cin>>x;
```

Keyboard input is required.

The CPU cannot keep waiting.

The process moves to

```text
Running

↓

Waiting
```

---

## C) Program Ends

```cpp
return 0;
```

Moves to

```text
Running

↓

Terminated
```

---

# 4. Waiting (Blocked) State

Also called

- Blocked
    
- Waiting
    

Both mean the same in GATE.

---

Meaning

The process **cannot continue** until some event occurs.

Examples

- Disk read
    
- Keyboard input
    
- Network packet
    
- Semaphore
    
- Signal
    
- Child process completion
    

---

Example

```cpp
scanf(...)
```

User has not typed anything.

CPU cannot help.

So

```text
Running

↓

Waiting
```

The CPU immediately switches to another process.

---

Important

Waiting is **NOT waiting for CPU.**

It is waiting for an **event**.

This distinction is frequently tested.

---

# Transition

After the event finishes,

```text
Waiting

↓

Ready
```

Notice

It does **not** go directly to Running.

It must again compete for the CPU.

---

# 5. Terminated State

Meaning

Execution has finished.

Reasons

- Program completed
    
- exit()
    
- Fatal error
    
- Killed by OS
    
- Parent terminated it
    

Resources are released.

PCB is eventually removed.

---

# Complete State Transition Table

|Current State|Event|Next State|
|---|---|---|
|New|Admitted by OS|Ready|
|Ready|CPU Allocated|Running|
|Running|Time Slice Over|Ready|
|Running|I/O Request|Waiting|
|Waiting|I/O Complete|Ready|
|Running|Process Ends|Terminated|

---

# Memory Visualization

Imagine RAM contains

```text
RAM

--------------------

Chrome

Ready

--------------------

Spotify

Waiting

--------------------

VS Code

Running

--------------------

Terminal

Ready

--------------------
```

The scheduler constantly moves processes between these states.

# Internal Working

Every process has a **PCB (Process Control Block)**.

One field inside it is:

```text
State = Ready
```

or

```text
State = Running
```

Whenever a transition occurs,

the kernel updates this field.

---

# Ready vs Waiting (Most Asked)

|Ready|Waiting|
|---|---|
|Waiting for CPU|Waiting for an event|
|Can execute immediately if CPU is available|Cannot execute even if CPU is free|
|Stored in Ready Queue|Stored in Device/Event Wait Queue|

---

Example

CPU is free.

Suppose

```cpp
scanf();
```

User still hasn't typed anything.

Can the process execute?

No.

It stays Waiting.

---

Another process

```cpp
x=x+1;
```

needs only the CPU.

It is Ready.

The CPU runs it immediately.

---

# GATE Traps

### Trap 1

> Waiting means waiting for CPU.

❌ False

Waiting means waiting for an **event** (like I/O).

---

### Trap 2

> Ready means waiting for I/O.

❌ False

Ready means **only CPU is needed**.

---

### Trap 3

> Waiting → Running

❌ False

It is:

```text
Waiting

↓

Ready

↓

Running
```

The scheduler must choose it again.

---

### Trap 4

> Multiple processes can be Running on a single-core CPU.

❌ False

Only one process can be Running at a time on a single-core processor.

---

### Trap 5

> New → Running

❌ False

The correct path is:

```text
New → Ready → Running
```

---

# Extended Process States (7-State Model)

Some systems also include:

- Ready Suspended
    
- Blocked Suspended
    

These occur when the OS swaps processes out of RAM to secondary storage.

**For GATE, focus primarily on the 5-state model unless a question explicitly mentions suspension or swapping.**

---

# GATE Corner 📝

### Core State Flow

```text
New → Ready → Running
          ↑       │
          │       │
      Waiting ←───┘
          │
          ▼
        Ready

Running → Terminated
```

### One-Line Revision

- **New:** Process created.
    
- **Ready:** Waiting only for the CPU.
    
- **Running:** Currently executing on the CPU.
    
- **Waiting (Blocked):** Waiting for an event/I/O.
    
- **Terminated:** Execution finished.
    

### Must Remember

- **Ready Queue** stores ready processes.
    
- **Waiting Queue** stores blocked processes.
    
- **Waiting → Ready**, never **Waiting → Running** directly.
    
- On a **single-core CPU, only one process can be in the Running state at any instant.**
    
- The **PCB stores the current process state**, and the OS updates it during every state transition.
    

Mastering these transitions will make later topics like **PCB**, **Context Switching**, **CPU Scheduling**, and **`fork()`** much easier because they all operate on processes moving through these states.
