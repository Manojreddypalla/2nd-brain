This is one of the **best GATE questions** because it tests whether you truly understand **what a context switch is**.

Let's build it from scratch.

---

# Step 1: What is a Context?

Before answering the question, ask:

> **What does "context" mean?**

Suppose the CPU is executing:

```c
int a = 10;
int b = 20;
int c = a + b;
printf("%d", c);
```

At some instant:

- `a` is in a register.
    
- `b` is in another register.
    
- The CPU is about to execute `c = a + b`.
    
- The current function has local variables on the stack.
    

Everything that describes **where execution currently is** is called the **execution context**.

It includes things like:

- Current instruction
    
- Register values
    
- Stack location
    

---

# Step 2: What happens during a context switch?

Suppose:

```text
CPU

↓

Thread T1
```

The timer interrupt occurs.

The scheduler decides:

```text
Run Thread T2
```

If we simply start T2, what happens to T1?

It forgets:

- where it was,
    
- what values were in registers,
    
- which function it was executing.
    

When T1 runs again, it must continue **exactly where it stopped**.

Therefore the OS saves T1's context into its **TCB (Thread Control Block)**.

---

# Option A

## Page Table Base Register (PTBR)

❌ **Not saved**

This is the trickiest option.

---

### What is the PTBR?

Every process has its own virtual memory.

Example:

```text
Process A

Virtual Address

↓

Page Table A

↓

Physical Memory
```

The CPU uses the **Page Table Base Register** to locate the page table.

---

### Now look carefully.

The question says:

> **Thread T1 → Thread T2 of the SAME process**

Both threads belong to the same process.

```text
Process P

├── Thread T1
└── Thread T2
```

Threads share:

- Address Space
    
- Heap
    
- Code
    
- Globals
    

Therefore they use the **same page table**.

Nothing changes.

So:

```
PTBR
```

already points to the correct page table.

No need to save or reload it.

---

### If it were a process switch...

Suppose

```
Process A

↓

Process B
```

Now the address spaces are different.

Therefore the OS must change

```
PTBR
```

to Process B's page table.

---

**Rule**

Same Process

→ Same Page Table

→ PTBR unchanged

---

# Option B

## Stack Pointer

✅ **Must be saved**

Every thread has its own stack.

Example

```text
Process

├── Thread A Stack
└── Thread B Stack
```

Suppose T1 is here

```text
Function A

↓

Function B

↓

Function C
```

The Stack Pointer points somewhere inside Thread A's stack.

When switching to T2,

the CPU must use

```
Thread B's Stack
```

Otherwise,

T2 would continue using

```
Thread A's Stack
```

Everything would be corrupted.

Therefore

Stack Pointer must be saved.

---

# Option C

## Program Counter

✅ **Must be saved**

The Program Counter tells the CPU

```
Execute next instruction here.
```

Suppose

```c
a = b + c;
printf("Hello");
```

T1 stopped here

```
↓

printf("Hello");
```

When T1 resumes,

should it start from

```c
int main()
```

again?

No.

It should continue exactly where it stopped.

Therefore

Program Counter must be saved.

---

# Option D

## General Purpose Registers

✅ **Must be saved**

Registers contain temporary values.

Suppose

```
R1 = 25

R2 = 40
```

Now switch to Thread T2.

T2 starts using

```
R1

R2
```

The values become

```
R1 = 90

R2 = 12
```

If T1 resumes later without restoring its registers,

its calculations are destroyed.

Therefore

Registers must also be saved.

---

# Visual Summary

Suppose

```
T1

PC = 120

SP = 0x7000

R1 = 10

R2 = 50
```

Context Switch

Save

```

SP

Registers
```

into

```
TCB(T1)
```

Load

```
PC

SP

Registers
```

from

```
TCB(T2)
```

CPU resumes T2.

# Why PTBR is Different

Think of the page table as a **map of the process's memory**.

```
Process

↓

Address Space

↓

Page Table
```

Threads are like **different workers inside the same building**.

They all use the **same building map**.

So changing workers does **not** require changing the map.

Changing to another **process** is like entering a different building.

Now you need a **different map**.

---

# GATE Rule ⭐

Whenever you see a context-switch question, first ask:

> **Is it a thread switch or a process switch?**

### Thread → Thread (Same Process)

**Changes:**

- ✅ Program Counter
    
- ✅ Stack Pointer
    
- ✅ General Purpose Registers
    

**Does not change:**

- ❌ Page Table Base Register
    
- ❌ Address Space
    
- ❌ Open Files
    
- ❌ Heap
    
- ❌ Global Variables
    

### Process → Process

Everything above changes **plus**:

- ✅ Page Table Base Register (new address space)
    
- ✅ Other process-specific resources as needed
    

---

**Correct Answer:** **B, C, and D.**

The key intuition is:

> A **thread switch** only changes the **execution state** (where and how the CPU was executing). It does **not** change the **process resources** that all threads of the process share.
