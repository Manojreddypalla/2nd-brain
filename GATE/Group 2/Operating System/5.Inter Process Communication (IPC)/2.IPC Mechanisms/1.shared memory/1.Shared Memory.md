# Shared Memory

## Definition

**Shared Memory** is an **Inter Process Communication (IPC)** mechanism in which **two or more processes share a common region of physical memory** to exchange data.

Instead of sending data through the operating system every time, all communicating processes directly read from and write to the same memory area.

It is one of the **fastest IPC mechanisms** because data copying is minimized.

---

# Why Shared Memory?

Normally, every process has its own private address space.

```text
Process A

+-----------+
| Variables |
| Stack     |
| Heap      |
+-----------+

Cannot access

+-----------+
| Process B |
+-----------+
```

Because of **Process Isolation**, one process cannot directly access another process's memory.

The operating system solves this by creating a **shared memory region** that both processes can access.

---

# Working of Shared Memory

## Step 1

The operating system creates a shared memory segment.

```text
Operating System

+----------------------+
| Shared Memory Block  |
+----------------------+
```

---

## Step 2

Process A attaches to it.

```text
Process A
     |
     |
     ▼
+----------------------+
| Shared Memory Block  |
+----------------------+
```

---

## Step 3

Process B also attaches.

```text
Process A
     |
     |
     ▼

+----------------------+
| Shared Memory Block  |
+----------------------+
     ▲
     |
     |
Process B
```

Now both processes can access the same data.

---

# Communication

Example:

Process A writes

```text
Temperature = 35
```

Shared Memory

```text
Temperature = 35
```

Process B immediately reads

```text
Temperature = 35
```

No message transfer is required.

---

# Characteristics

- Fastest IPC mechanism.
- Data is shared instead of copied.
- Suitable for large amounts of data.
- Requires synchronization.
- Managed by the Operating System.

---

# Synchronization Problem

Since multiple processes access the same memory simultaneously,

they may try to modify the same data at the same time.

Example:

```text
Counter = 5
```

Process A

```text
Counter++
```

Process B

```text
Counter++
```

If both execute simultaneously,

the final value may incorrectly become

```text
6
```

instead of

```text
7
```

This is called a **Race Condition**.

---

# Solution

Shared Memory is usually combined with synchronization mechanisms like:

- Semaphore
- Mutex
- Monitor
- Spinlock

These ensure that only one process modifies shared data at a time.

---

# Advantages

## 1. Very Fast

Processes directly access memory.

No repeated kernel involvement.

---

## 2. No Data Copying

Only one copy of the data exists.

This improves efficiency.

---

## 3. Efficient for Large Data

Suitable for:

- Images
- Videos
- Databases
- Scientific Computing

---

## 4. Low Communication Overhead

After the shared memory is created,

communication happens directly.

---

## 5. High Performance

Frequently used in high-speed applications.

---

# Disadvantages

## 1. Requires Synchronization

Without synchronization,

Race Conditions occur.

---

## 2. Programming is Difficult

The programmer must carefully coordinate processes.

---

## 3. Security Issues

Any attached process can modify shared data.

---

## 4. Debugging is Difficult

Concurrent memory access is harder to debug than message passing.

---

## 5. Not Suitable for Distributed Systems

Shared Memory only works on the same machine.

It cannot directly communicate over a network.

---

# Real-Life Analogy

Imagine two students working on the same whiteboard.

```text
Student A

      │

      ▼

+----------------+
| Shared Board   |
+----------------+

      ▲

      │

Student B
```

Both students can:

- Read
- Write
- Erase

If both write simultaneously,

their work may overlap.

Therefore,

they need rules like

> "One person writes at a time."

That rule is equivalent to **Synchronization**.

---

# Shared Memory vs Message Passing

| Feature | Shared Memory | Message Passing |
|---------|---------------|-----------------|
| Speed | Very Fast | Slower |
| Data Copy | No | Yes |
| Synchronization | Required | Usually Handled by OS |
| Complexity | High | Low |
| Best For | Large Data | Small Messages |
| Network Support | No | Yes |

# Linux System Calls

Linux provides the following System V shared memory functions:

- `shmget()` → Create or obtain a shared memory segment.
- `shmat()` → Attach the segment to a process.
- `shmdt()` → Detach the segment.
- `shmctl()` → Control or remove the shared memory segment.

> You only need to know the purpose of these calls for GATE.

---

# GATE Points ⭐

- Shared Memory is one of the **fastest IPC mechanisms**.
- Processes communicate through a **common memory region**.
- No repeated data copying.
- Requires synchronization.
- Can suffer from Race Conditions.
- Synchronization is commonly achieved using Semaphores or Mutexes.
- Suitable for processes on the **same machine**.
