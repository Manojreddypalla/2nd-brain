# Message Passing

## Definition

**Message Passing** is an **Inter Process Communication (IPC)** mechanism in which **processes communicate by sending and receiving messages through the operating system**.

Unlike Shared Memory, processes **do not share the same memory region**. Instead, the operating system acts as an intermediary that transfers messages between processes.

---

# Why Message Passing?

Due to **Process Isolation**, one process cannot directly access another process's memory.

Instead of sharing memory, processes exchange information by sending messages.

```text
Process A
     |
     | send()
     ▼
+--------------------+
| Operating System   |
+--------------------+
     |
     | receive()
     ▼
Process B
```

The operating system ensures that the message is delivered correctly.

---

# Working of Message Passing

## Step 1

Process A creates a message.

```text
"Hello"
```

---

## Step 2

The operating system receives the message.

---

## Step 3

The operating system delivers the message to Process B.

```text
Process A
     │
     ▼
Operating System
     │
     ▼
Process B
```

---

# Characteristics

- Processes communicate using **send()** and **receive()** operations.
- No shared memory is required.
- The operating system manages communication.
- Easier to implement than Shared Memory.
- Suitable for communication between processes on the same computer or across a network.

---

# Advantages

## 1. Easy to Implement

The operating system handles communication.

---

## 2. No Shared Memory

Processes remain isolated.

---

## 3. Safe Communication

Less chance of Race Conditions because processes do not directly modify the same memory.

---

## 4. Suitable for Distributed Systems

Can communicate over different computers using sockets.

---

## 5. Better Security

Processes cannot directly modify each other's memory.

---

# Disadvantages

## 1. Slower Than Shared Memory

Messages are copied through the operating system.

---

## 2. Kernel Overhead

Every message passes through the kernel.

---

## 3. Communication Delay

Large messages require additional copying.

---

# Message Passing Models

There are two important communication models.

---

# 1. Direct Communication

## Definition

Processes communicate by **explicitly naming each other**.

Example:

```text
Process A
     │
 send(B)
     │
     ▼
Process B
```

The sender knows the receiver.

The receiver knows the sender.

---

## Characteristics

- One-to-one communication.
- Simple.
- Processes must know each other's identity.

---

## Example

```text
Client
   │
   ▼
Server
```

---

## Advantages

- Simple implementation.
- Fast lookup.

---

## Disadvantages

- Processes become tightly coupled.
- Difficult to scale.

---

# 2. Indirect Communication

## Definition

Processes communicate through an intermediate object called a **Mailbox (Port)**.

```text
Process A
     │
     ▼
 Mailbox
     ▲
     │
Process B
```

Neither process needs to know the identity of the other.

---

## Characteristics

- Uses Mailboxes (Ports).
- Supports one-to-one, one-to-many, many-to-one, and many-to-many communication.
- Processes are loosely coupled.

---

## Advantages

- Flexible.
- Easier to manage multiple processes.

---

## Disadvantages

- Slightly more complex.
- Mailbox management is required.

---

# Direct vs Indirect Communication

| Feature | Direct | Indirect |
|---------|---------|-----------|
| Communication | Process to Process | Through Mailbox |
| Coupling | Tight | Loose |
| Flexibility | Low | High |
| Scalability | Poor | Better |

---

# Blocking vs Non-Blocking Communication

These define **whether a process waits during send() or receive()**.

---

# 1. Blocking Communication (Synchronous)

## Definition

The process waits until the communication operation completes.

---

### Blocking Send

The sender waits until the message is accepted.

```text
Sender
 |
 | Waiting...
 |
 ▼
Message Delivered
```

---

### Blocking Receive

The receiver waits until a message arrives.

```text
Receiver

Waiting...

↓

Message Arrives
```

---

## Characteristics

- Simpler.
- Easier synchronization.
- Lower concurrency.

---

# 2. Non-Blocking Communication (Asynchronous)

## Definition

The process continues execution immediately without waiting.

---

### Non-Blocking Send

```text
Send Message

↓

Continue Execution
```

---

### Non-Blocking Receive

```text
Check for Message

↓

If Available → Receive

Otherwise → Continue
```

---

## Characteristics

- Better CPU utilization.
- Higher concurrency.
- Slightly more difficult to program.

---

# Blocking vs Non-Blocking

| Feature | Blocking | Non-Blocking |
|---------|----------|--------------|
| Waits | Yes | No |
| Simplicity | Easy | More Complex |
| Concurrency | Lower | Higher |
| CPU Utilization | Lower | Higher |

---

# Buffering

Messages are usually stored in a temporary area called a **Buffer** before the receiver reads them.

The operating system supports three buffering strategies.

---

# 1. Zero Capacity Buffer

Buffer Size = **0**

No message can be stored.

The sender must wait until the receiver is ready.

```text
Sender ↔ Receiver
```

This is also called a **Rendezvous**.

---

## Characteristics

- No storage.
- Always Blocking.
- Immediate synchronization.

---

# 2. Bounded Capacity Buffer

Buffer has a fixed size.

Example:

```text
Capacity = 5 Messages
```

```text
+---+---+---+---+---+
| M | M |   |   |   |
+---+---+---+---+---+
```

If the buffer becomes full,

the sender blocks until space becomes available.

---

## Characteristics

- Limited storage.
- Most commonly used in operating systems.
- Efficient memory usage.

---

# 3. Unbounded Capacity Buffer

Theoretically unlimited storage.

```text
+-------------------------+
| M M M M M M M M M M ... |
+-------------------------+
```

The sender never waits.

Only the receiver may wait if there are no messages.

---

## Characteristics

- Infinite logical capacity.
- Sender never blocks because of a full buffer.
- Not practical in real systems due to finite memory.

---

# Buffering Comparison

| Buffer Type | Sender Waits? | Receiver Waits? |
|-------------|---------------|-----------------|
| Zero Capacity | Always | If no message |
| Bounded Capacity | Only if Full | If Empty |
| Unbounded Capacity | Never (Buffer Full) | If Empty |

---

# Message Passing vs Shared Memory

| Feature | Message Passing | Shared Memory |
|---------|-----------------|---------------|
| Communication | Messages | Shared Data |
| Speed | Slower | Faster |
| Data Copy | Required | No Copy |
| Synchronization | Mostly OS Managed | Programmer Must Handle |
| Network Support | Yes | No |
| Complexity | Lower | Higher |

# Linux Examples

Message Passing IPC in Linux includes:

- Pipes
- Named Pipes (FIFO)
- Message Queues
- Sockets

Typical System Calls:

- `msgget()`
- `msgsnd()`
- `msgrcv()`
- `msgctl()`

# GATE Points ⭐

### Message Passing

- Processes communicate using **send()** and **receive()**.
- No shared memory is used.
- Operating system transfers the messages.

### Direct Communication

- Sender and receiver know each other's identity.
- Tight coupling.

### Indirect Communication

- Uses a Mailbox (Port).
- Loose coupling.

### Blocking Communication

- Process waits.
- Also called **Synchronous Communication**.

### Non-Blocking Communication

- Process continues execution.
- Also called **Asynchronous Communication**.

### Buffering

- **Zero Capacity** → Sender always waits.
- **Bounded Capacity** → Sender waits only if the buffer is full.
- **Unbounded Capacity** → Sender never waits because of a full buffer.

# Quick Revision ⭐

- Message Passing = **send() + receive()**
- No shared memory.
- OS transfers messages.
- **Direct** → Process ↔ Process
- **Indirect** → Mailbox
- **Blocking** → Wait
- **Non-Blocking** → Continue
- **Zero Buffer** → Always wait
- **Bounded Buffer** → Wait if full
- **Unbounded Buffer** → Sender never waits due to a full buffer
- Easier than Shared Memory but slower due to data copying.
