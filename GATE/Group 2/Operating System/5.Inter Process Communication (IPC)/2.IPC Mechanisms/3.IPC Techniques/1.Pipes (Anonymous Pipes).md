# Pipes (Anonymous Pipes)

## Definition

A **Pipe** is one of the simplest **Inter Process Communication (IPC)** mechanisms that allows **two related processes** to communicate by transferring data in a **one-way (unidirectional)** stream.

It acts like a temporary communication channel managed by the operating system.

---

# Why Do We Need Pipes?

Suppose a parent process creates a child process.

```text
Parent Process

      fork()

          │

          ▼

Child Process
```

Both processes are isolated and cannot directly access each other's memory.

A **Pipe** provides a communication channel between them.

---

# Real-Life Analogy

Imagine a water pipe connecting two rooms.

```text
Room A

Water
  │
  ▼

======== PIPE ========>

                      Room B
```

- Room A writes water.
- Room B receives water.
- Water flows only in one direction.

Similarly,

- One process writes data.
- Another process reads data.

---

# Working of a Pipe

The operating system creates a temporary buffer.

```text
Process A

Write()

    │

    ▼

+-------------------+
|      PIPE         |
|   (Kernel Buffer) |
+-------------------+

    │

Read()

    ▼

Process B
```

The kernel stores the data until the receiving process reads it.

---

# Characteristics

- One-way communication.
- Uses a kernel buffer.
- Usually used between **parent and child processes**.
- Temporary IPC mechanism.
- Simple and efficient.

---

# Unidirectional Communication

A standard pipe transfers data in only **one direction**.

```text
Writer

   │

   ▼

PIPE

   │

   ▼

Reader
```

If two-way communication is needed,

two pipes are required.

```text
Parent  =====> Child

Parent  <===== Child
```

---

# Parent-Child Relationship

Anonymous Pipes work only between **related processes**.

Example:

```text
Parent

    │

 fork()

    │

    ▼

Child
```

Since the child inherits the pipe from the parent,

both can communicate.

Unrelated processes cannot use an anonymous pipe.

---

# FIFO (First In First Out)

A pipe behaves like a queue.

The first byte written is the first byte read.

```text
Write:

A

B

C

↓

Read:

A

B

C
```

This property is called **FIFO**.

---

# Internal Working

```text
Writer

    │

 write()

    │

    ▼

+----------------------+
| Kernel Pipe Buffer   |
+----------------------+

    │

 read()

    ▼

Reader
```

The operating system maintains the pipe buffer.

---

# Blocking Behavior

### Read

If the pipe is empty,

```text
Reader

↓

Wait
```

The reader blocks until data arrives.

---

### Write

If the pipe buffer becomes full,

```text
Writer

↓

Wait
```

The writer blocks until space becomes available.

---

# Advantages

## 1. Simple

Easy to create and use.

---

## 2. Fast

Data remains inside the kernel.

No disk access.

---

## 3. Efficient

Suitable for small amounts of data.

---

## 4. Automatic Synchronization

The operating system manages much of the synchronization.

---

# Disadvantages

## 1. One-Way Communication

Only one direction.

Two pipes are needed for bidirectional communication.

---

## 2. Related Processes Only

Anonymous pipes work only between parent and child processes.

---

## 3. Temporary

The pipe exists only while the communicating processes are alive.

---

## 4. Limited Buffer Size

The kernel buffer has a fixed capacity.

If full, writers block.

---

# Linux System Call

## pipe()

Creates an anonymous pipe.

```c
int pipe(int fd[2]);
```

After creation,

```text
fd[0] → Read End

fd[1] → Write End
```

Diagram:

```text
        PIPE

+----------------------+

fd[1]  ------->  fd[0]

Write            Read
```

Typical steps:

1. Create pipe.
2. Call `fork()`.
3. Parent writes.
4. Child reads.
5. Close unused ends.

> For GATE, remember only the purpose of `pipe()` and the meaning of `fd[0]` and `fd[1]`.

---

# Pipe vs File

| Pipe | File |
|------|------|
| Temporary | Permanent |
| IPC only | Data Storage |
| FIFO | Random Access |
| Kernel Buffer | Disk |

---

# Pipe vs Shared Memory

| Pipe | Shared Memory |
|------|---------------|
| Data Copy | Yes |
| Communication | Stream |
| Speed | Moderate |
| Synchronization | Mostly OS Managed |

| Shared Memory | |
|---------------|--|
| Data Copy | No |
| Communication | Shared Data |
| Speed | Very Fast |
| Synchronization | Programmer Must Handle |

---

# Real-World Example

Linux command:

```bash
ls | grep txt
```

```text
ls

↓

PIPE

↓

grep txt
```

- `ls` writes its output to the pipe.
- `grep` reads the output from the pipe.
- Neither program knows about the other directly; the shell connects them.

This is one of the most common uses of pipes in Unix/Linux.

---

# GATE Points ⭐

- Pipe is an IPC mechanism.
- Anonymous Pipe is **unidirectional**.
- Uses a **kernel buffer**.
- Follows **FIFO**.
- Used between **parent and child (related) processes**.
- If the pipe is empty, `read()` blocks.
- If the pipe is full, `write()` blocks.
- `pipe()` creates a pipe.
- `fd[0]` → Read end.
- `fd[1]` → Write end.
