# Signals

## Definition

A **Signal** is an IPC mechanism used by the operating system or a process to **notify another process that an event has occurred**.

Unlike Pipes or Message Queues, signals **do not transfer data**. They simply inform a process that something has happened.

---

# Why Signals?

Sometimes a process doesn't need data—it only needs a notification.

Examples:

- Stop execution.
- Continue execution.
- Terminate.
- User presses **Ctrl + C**.
- Timer expires.

Instead of sending a message,

the operating system sends a **Signal**.

---

# Real-Life Analogy

Think of a **doorbell**.

```text
Person

↓

Doorbell

↓

Person Inside
```

The doorbell does not contain information.

It simply says:

> "Someone is at the door."

Similarly,

Signals notify a process that an event has occurred.

```text

 kill()

     │

     ▼

```

The operating system delivers the signal.

---

# Signal Handling

When a process receives a signal, it can:

## 1. Ignore the Signal

Continue execution.

---

## 2. Handle the Signal

Execute a custom signal handler.

---

## 3. Perform Default Action

The operating system performs the default behavior.

Example:

- Terminate
- Stop
- Continue

---

# Characteristics

- Asynchronous communication.
- Small notification only.
- No user data transfer.
- Kernel managed.
- Used for process control.

---

# Common Signals

| Signal | Meaning |
|---------|----------|
| SIGINT | Interrupt (Ctrl + C) |
| SIGTERM | Request process termination |
| SIGKILL | Forcefully terminate process |
| SIGSTOP | Pause a process |
| SIGCONT | Resume a stopped process |
| SIGALRM | Alarm timer expired |
| SIGSEGV | Invalid memory access |

> You don't need to memorize every signal for GATE—know the common ones.

---

# Linux System Calls

## kill()

Sends a signal to another process.

---

## signal()

Registers a simple signal handler.

---

## sigaction()

Registers an advanced signal handler (preferred in modern systems).

---

## raise()

Sends a signal to the current process.

---

# Advantages

- Very fast.
- Simple notification mechanism.
- Low overhead.
- Useful for process control.

---

# Disadvantages

- Cannot transfer large data.
- Limited information.
- Signals may interrupt normal execution.
- Some signals cannot be ignored (e.g., SIGKILL).

---

# Signal vs Message Queue

| Signal | Message Queue |
|---------|---------------|
| Notification | Data Transfer |
| No Data | Messages |
| Very Small | Large Messages |
| Very Fast | Slower |

---

# Signal vs Pipe

| Signal | Pipe |
|---------|------|
| Notification | Byte Stream |
| No Data | Data Transfer |
| Process Control | Communication |

---

# Real-World Examples

Terminate a process:

```bash
kill 1234
```

Interrupt a running program:

```text
Ctrl + C
```

This sends:

```text
SIGINT
```

Pause a process:

```bash
kill -STOP PID
```

Resume it:

```bash
kill -CONT PID
```

---

# GATE Points ⭐

- Signal = Notification mechanism.
- No data transfer.
- Asynchronous IPC.
- Used for process control.
- `kill()` sends a signal.
- `signal()` and `sigaction()` register handlers.
- `SIGINT` → Ctrl + C.
- `SIGKILL` cannot be caught or ignored.
