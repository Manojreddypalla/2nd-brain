# Shared Memory Segments

## Definition

A **Shared Memory Segment** is a **block of physical memory created and managed by the operating system** that can be attached to multiple processes for communication.

It is the actual memory region used in the **Shared Memory IPC mechanism**.

---

# Why Shared Memory Segments?

Processes have separate address spaces.

```text
Process A

Memory A


Process B

Memory B
```

Normally,

- Process A cannot access Memory B.
- Process B cannot access Memory A.

The operating system creates a **Shared Memory Segment**.

```text
Process A

      │

      ▼

+----------------------+
| Shared Memory Segment|
+----------------------+

      ▲

      │

Process B
```

Now both processes access the same memory.

---

# Working

### Step 1

Operating System creates a shared memory segment.

---

### Step 2

Processes attach to it.

```text
Process A

      │

      ▼

Shared Memory Segment

      ▲

      │

Process B
```

---

### Step 3

Processes directly read and write data.

Example

```text
Shared Memory

Temperature = 30°C
```

Process B immediately sees

```text
Temperature = 30°C
```

No message copying occurs.

---

# Characteristics

- Shared physical memory.
- Multiple processes can attach.
- Fastest IPC mechanism.
- No data copying.
- Requires synchronization.

---

# Synchronization

Since multiple processes access the same memory,

Race Conditions can occur.

Example

```text
Balance = 1000
```

Process A

```text
Balance += 100
```

Process B

```text
Balance -= 200
```

If both update simultaneously,

incorrect results may occur.

Therefore,

Shared Memory Segments are usually protected using:

- Semaphores
- Mutexes
- Spinlocks

---

# Advantages

## 1. Extremely Fast

Processes directly access memory.

---

## 2. No Data Copying

Only one copy of data exists.

---

## 3. Suitable for Large Data

Useful for:

- Databases
- Multimedia
- Scientific Applications

---

## 4. Low CPU Overhead

After setup,

the kernel is rarely involved.

---

# Disadvantages

## 1. Synchronization Required

Without synchronization,

Race Conditions occur.

---

## 2. More Difficult to Program

Programmers must carefully coordinate access.

---

## 3. Local Machine Only

Processes must be running on the same computer.

---

# Linux System Calls

## shmget()

Creates or obtains a Shared Memory Segment.

---

## shmat()

Attaches the segment to a process.

---

## shmdt()

Detaches the segment.

---

## shmctl()

Controls or removes the segment.

---

# Typical Workflow

```text
shmget()

↓

shmat()

↓

Read / Write Data

↓

shmdt()

↓

shmctl()
```

---

# Shared Memory vs Shared Memory Segment

| Shared Memory | Shared Memory Segment |
|--------------|-----------------------|
| IPC Technique | Actual Memory Block |
| General Concept | OS-created Shared Region |

Think of it this way:

- **Shared Memory** = The idea of sharing memory.
- **Shared Memory Segment** = The actual shared block created by the OS.

---

# Real-Life Analogy

Imagine a shared whiteboard.

```text
Person A

      │

      ▼

+------------------+
| Shared Whiteboard|
+------------------+

      ▲

      │

Person B
```

Both people can write and read from the same whiteboard.

The whiteboard is the **Shared Memory Segment**.

# GATE Points ⭐

- Shared Memory Segment is the **actual shared memory block**.
- Created using **`shmget()`**.
- Attached using **`shmat()`**.
- Detached using **`shmdt()`**.
- Removed using **`shmctl()`**.
- No data copying.
- Fastest IPC mechanism.
- Requires synchronization.
