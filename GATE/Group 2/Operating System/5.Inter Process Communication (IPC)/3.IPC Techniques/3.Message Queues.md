# Message Queues

## Definition

A **Message Queue** is an IPC mechanism that allows processes to communicate by **sending and receiving messages through a queue maintained by the operating system**.

Instead of directly communicating with each other, processes exchange messages using a **kernel-managed queue**.

---

# Why Message Queues?

Pipes have several limitations:

- One-way communication.
- FIFO order only.
- Processes often need to run simultaneously.
- Cannot easily prioritize messages.

Message Queues solve these problems by allowing messages to be stored until the receiver is ready.

---

# Working

```text
Sender Process

 send()

     │

     ▼

+----------------------+
|   Message Queue      |
|----------------------|
| Message 1            |
| Message 2            |
| Message 3            |
+----------------------+

     │

 receive()

     ▼

Receiver Process
```

The operating system stores messages inside the queue until another process reads them.

---

# Characteristics

- Managed by the Operating System.
- Stores messages in a queue.
- Sender and receiver are independent.
- Multiple processes can use the same queue.
- Supports message priorities (implementation dependent).

---

# Communication Flow

```text
Process A

↓

Send Message

↓

Kernel Queue

↓

Receive Message

↓

Process B
```

The sender and receiver do not communicate directly.

---

# Queue Behavior

Example

Messages sent:

```text
Login

Payment

Logout
```

Stored in queue

```text
+-----------+
| Login     |
| Payment   |
| Logout    |
+-----------+
```

Receiver gets

```text
Login

↓

Payment

↓

Logout
```

unless message priorities are used.

---

# Message Structure

A message generally contains:

```text
+---------------------+
| Message Type        |
| Data                |
+---------------------+
```

Example

```text
Type = 2

Message = "Payment Successful"
```

The receiver may choose messages based on their type.

---

# Advantages

## 1. Processes Need Not Execute Simultaneously

The sender can send messages even if the receiver is not currently running.

---

## 2. Structured Communication

Messages can contain:

- Type
- Priority
- Data

---

## 3. Better Organization

Multiple messages are stored in order.

---

## 4. Multiple Processes

Several senders and receivers can use the same queue.

---

## 5. Kernel Managed

The operating system manages synchronization.

---

# Disadvantages

## 1. Slower Than Shared Memory

Messages must be copied through the kernel.

---

## 2. Limited Queue Size

If the queue becomes full,

the sender may block.

---

## 3. Kernel Overhead

Every send and receive operation requires kernel intervention.

---

# Blocking Behavior

## Send

If the queue is full,

```text
Sender

↓

Wait
```

---

## Receive

If the queue is empty,

```text
Receiver

↓

Wait
```

---

# Linux System Calls

## msgget()

Creates or opens a message queue.

---

## msgsnd()

Sends a message.

---

## msgrcv()

Receives a message.

---

## msgctl()

Controls or deletes the queue.

---

# Real-Life Analogy

Imagine a post office.

```text
Person A

↓

Post Office

↓

Person B
```

- Person A drops a letter.
- The post office stores it.
- Person B collects it later.

The sender and receiver never need to meet.

The **post office** is the **Message Queue**.

---

# Message Queue vs Pipe

| Pipe | Message Queue |
|------|---------------|
| Byte Stream | Structured Messages |
| FIFO Only | FIFO or Message Type/Priority |
| Parent-Child Preferred | Any Processes |
| Simple | More Flexible |

---

# Message Queue vs Shared Memory

| Message Queue | Shared Memory |
|--------------|---------------|
| Data is copied | Data is shared |
| Slower | Faster |
| Easier | More Complex |
| OS handles synchronization | Programmer handles synchronization |

---

# GATE Points ⭐

- Kernel-managed IPC mechanism.
- Uses **send** and **receive** operations.
- Stores messages until they are read.
- Processes need not run simultaneously.
- Supports structured messages (type, data).
- Created using **msgget()**.
- Sending → **msgsnd()**.
- Receiving → **msgrcv()**.
- Deleting/controlling → **msgctl()**.

# Common GATE MCQs

### Q1

Which IPC mechanism stores messages in a kernel queue?

- Shared Memory

- Message Queue
- Semaphore

✅ **Answer:** Message Queue

---

### Q2

Which system call sends a message?

- msgrcv()
- msgsnd()
- msgctl()
- shmget()

✅ **Answer:** msgsnd()

### Q3

Which IPC mechanism allows the sender and receiver to execute at different times?

- Anonymous Pipe
- Shared Memory

- FCFS
