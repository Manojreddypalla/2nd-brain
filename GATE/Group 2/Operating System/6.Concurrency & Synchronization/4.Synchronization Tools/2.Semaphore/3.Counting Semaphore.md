# Counting Semaphore — GATE Notes

## What is a Counting Semaphore?

A **Counting Semaphore** is a semaphore used when there are **multiple instances of the same resource**.

> 🧠 **Counting Semaphore = Multiple Permits 🎟️🎟️🎟️**

The semaphore represents how many permits/resources are available.

---

# Why Do We Need It?

Suppose a system has:

```text
3 Printers 🖨️ 🖨️ 🖨️
```

We want:

- Maximum 3 processes using printers simultaneously.
- Any additional process must wait.

Initialize:

```text
Semaphore S = 3
```

Meaning:

```text
3 permits/resources available
```

---

# Simple Example

Initially:

```text
S = 3
```

P1 requests a printer:

```text
P1 → wait(S)

3 → 2
```

P2:

```text
P2 → wait(S)

2 → 1
```

P3:

```text
P3 → wait(S)

1 → 0
```

All printers are now occupied.

P4 requests one:

```text
P4 → wait(S)

No permit available
↓
P4 WAITS
```

---

# Releasing a Resource

Suppose P2 finishes.

```text
P2 → signal(S)
```

A permit/resource is released.

```text
Resource available
      ↓
Waiting process P4 can proceed
```

---

# Operations

Counting Semaphore uses:

```text
wait(S)
signal(S)
```

Both operations must be **atomic**.

---

## wait(S)

Meaning:

> **"I want one permit."**

Conceptually:

```text
Permit available?
       │
       ├── YES → Acquire one → Proceed
       │
       └── NO  → Wait
```

Example:

```text
S = 5

wait(S)

↓

S = 4
```

---

## signal(S)

Meaning:

> **"I'm releasing/returning one permit."**

Example:

```text
S = 4

signal(S)

↓

S = 5
```

If another process is waiting, it may now proceed.

---

# General Rule

If there are:

```text
N identical resources
```

initialize:

```c
semaphore S = N;
```

Therefore:

```text
S = Number of available permits/resources
```

---

# Example — Database Connections

Suppose a server allows:

```text
10 simultaneous database connections
```

Initialize:

```text
S = 10
```

Every process executes:

```c
wait(S);

// Use database connection

signal(S);
```

Maximum:

```text
10 processes
```

can use connections simultaneously.

The 11th must wait.

---

# Where Counting Semaphores Are Used

Typical examples:

- Multiple printers
- Database connection pools
- Buffer slots
- Memory pools
- Limited worker slots
- Multiple identical devices
- Limiting concurrent users

# Binary vs Counting Semaphore

| Binary Semaphore | Counting Semaphore |
|---|---|
| One permit | Multiple permits |
| Logical states 0 / 1 | Represents N permits |
| Mutual exclusion / signaling | Resource counting |
| One process at a time when used as lock | Up to N processes |
| Example: one permission | Example: 5 printers |

---

# Mutex vs Binary vs Counting

| Feature | Mutex | Binary Semaphore | Counting Semaphore |
|---|---|---|---|
| Main idea | Lock 🔑 | One permit 🎟️ | N permits 🎟️🎟️🎟️ |
| Ownership | ✅ | ❌ | ❌ |
| Multiple permits | ❌ | ❌ | ✅ |
| Mutual Exclusion | ✅ | ✅ Can be used | Not its main use |
| Signaling | ❌ | ✅ | ✅ |
| Resource Counting | ❌ | ❌ | ✅ |

---

# 🎯 GATE Important Points

- Counting Semaphore represents **multiple permits/resources**.
- If there are `N` identical resources:

```text
S = N
```

- `wait()` → acquire one permit.
- `signal()` → release one permit.
- `wait()` and `signal()` must be **atomic**.
- When no permit is available → process waits.
- Used mainly for **resource management**.
- Does not have Mutex-style ownership.

# Common GATE Traps

## Trap 1

> Counting Semaphore can only have values 0 and 1.

❌ False

That's a **Binary Semaphore**.

Counting Semaphore represents multiple permits.

---

## Trap 2

> Counting Semaphore is mainly used when multiple identical resources exist.

✅ True

Example:

```text
5 printers

↓

S = 5
```

---

## Trap 3

> Counting Semaphore has Mutex-style ownership.

❌ False

Semaphore does not have the same ownership rule as Mutex.

---

## Trap 4

> `wait()` and `signal()` don't need to be atomic.

❌ False

Both must be **atomic**.
