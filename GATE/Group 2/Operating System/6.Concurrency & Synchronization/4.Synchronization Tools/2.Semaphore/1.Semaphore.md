# Semaphore — GATE Notes

## What is a Semaphore?

A **Semaphore** is a synchronization tool used to **control access to shared resources** between multiple processes or threads.

> 🧠 Simple idea: **Semaphore = Permit Counter 🎟️**

The semaphore value tells us how many permits/resources are available.

---

# Why Do We Need Semaphore?

Suppose multiple processes want to use shared resources.

Without synchronization:

```text
P1 ──┐
P2 ──┼──→ Shared Resource
P3 ──┘
```

They may access/update the resource incorrectly.

Semaphore controls **who can proceed and who must wait**.

```text
Process
   ↓
Ask Semaphore
   ↓
Permit available?
   │
   ├── YES → Proceed
   │
   └── NO  → Wait
```

---

# Simple Example

Imagine a parking lot.

```text
Available Spaces = 3

Semaphore S = 3
```

Three cars can enter.

```text
S = 3

Car 1 enters
↓
S = 2

Car 2 enters
↓
S = 1

Car 3 enters
↓
S = 0
```

Now:

```text
Car 4 arrives

S = 0
↓
No permit
↓
WAIT
```

When a car leaves:

```text
Car leaves
↓
Permit returned
↓
Waiting car can proceed
```

That's the basic idea of a semaphore.

---

# Semaphore Operations ⭐⭐⭐⭐⭐

A semaphore is accessed using two important **atomic operations**:

```text
wait()
signal()
```

You may also see:

```text
wait()   = P() = down()

signal() = V() = up()
```

---

# 1. wait(S)

`wait()` means:

> **"I want to acquire a permit/resource."**

Conceptually:

```text
wait(S)
   ↓
Permit available?
   │
   ├── YES → Take permit → Continue
   │
   └── NO  → Wait
```

Example:

```text
S = 3

wait(S)

↓

S = 2
```

One permit was acquired.

---

# 2. signal(S)

`signal()` means:

> **"I'm releasing/returning a permit."**

Example:

```text
S = 2

signal(S)

↓

S = 3
```

A permit becomes available.

A waiting process may now be allowed to proceed.

---

# Basic Flow

```text
        Process
           │
           ▼
        wait(S)
           │
           ▼
    Resource Available?
       │         │
      YES        NO
       │         │
       ▼         ▼
    Proceed     Wait
       │
       ▼
   Use Resource
       │
       ▼
     signal(S)
       │
       ▼
   Release Permit
```

---

# wait() and signal() Must Be Atomic ⭐⭐⭐⭐⭐

This is extremely important.

Suppose:

```text
S = 1
```

P1 and P2 both try:

```text
wait(S)
```

If `wait()` wasn't atomic, both might see:

```text
S = 1
```

and both could proceed.

That creates another **Race Condition**.

Therefore:

> `wait()` and `signal()` are **atomic operations**.

---

# What Happens When No Permit Is Available?

Suppose:

```text
S = 0
```

P2 executes:

```text
wait(S)
```

P2 cannot continue.

It must wait.

A semaphore implementation can **block** the waiting process/thread.

```text
P2
 ↓
wait(S)
 ↓
No Permit
 ↓
BLOCKED
 ↓
Waiting Queue
```

When another process executes:

```text
signal(S)
```

a waiting process can be awakened.

```text
signal(S)
    ↓
Permit available
    ↓
Wake waiting process
```

---

# Semaphore vs Busy Waiting

Semaphore does **NOT necessarily require Busy Waiting**.

Instead of:

```text
Check
Check
Check
Check
Check...
```

the OS can:

```text
No resource
    ↓
BLOCK process
    ↓
Run something else
    ↓
Wake process later
```

This saves CPU time.

# Semaphore Can Be Used For

## 1. Mutual Exclusion

Protect a Critical Section.

```text
Process
   ↓
wait()
   ↓
Critical Section
   ↓
signal()
```

---

## 2. Resource Management

Control access to limited resources.

Example:

```text
Printers
Database Connections
Buffer Slots
Memory Pools
```

---

## 3. Process / Thread Synchronization

One process can wait until another finishes some work.

```text
P1 does work
     ↓
signal(S)
     ↓
P2 can continue
```

This is an important difference from a simple lock.

---

# Semaphore vs Mutex — Basic Idea

Don't go deep yet.

Just remember:

```text
Mutex
  ↓
One owned lock 🔑
```

```text
Semaphore
  ↓
Permit / counter system 🎟️
```

Mutex focuses mainly on:

> **Who owns the lock?**

Semaphore focuses on:

> **How many permits/resources are available, or whether an event has been signaled?**

---

# Important GATE Points ⭐

- Semaphore is a **synchronization primitive/tool**.
- Used to coordinate processes/threads.
- Uses `wait()` and `signal()`.
- `wait()` → acquire a permit / may wait.
- `signal()` → release a permit / may wake a waiter.
- `wait()` and `signal()` must be **atomic**.
- Can be used for Mutual Exclusion.
- Can manage limited resources.
- Can be used for process/thread synchronization.
- Semaphore does **not** have Mutex-style ownership.
- Waiting processes can be blocked instead of busy waiting.

---

# Common GATE Traps

## Trap 1

> `wait()` and `signal()` don't need to be atomic.

❌ False

They **must be atomic** to avoid race conditions on the semaphore itself.

---

## Trap 2

> Semaphore always uses Busy Waiting.

❌ False

Semaphore implementations can block waiting processes.

---

## Trap 3

> Semaphore is only used for Mutual Exclusion.

❌ False

It can also be used for:

- Resource counting
- Process/thread synchronization
- Signaling

---

## Trap 4

> Semaphore and Mutex are exactly the same.

❌ False

```text
Mutex → Owned Lock

Semaphore → Permit/Counter + Signaling
```
