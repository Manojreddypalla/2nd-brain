# Binary Semaphore — GATE Notes

## What is a Binary Semaphore?

A **Binary Semaphore** is a semaphore whose state is restricted to two logical values:

```text
0 → Permit unavailable
1 → Permit available
```

> 🧠 **Binary Semaphore = Semaphore with ONE permit 🎟️**

Because only one permit exists, it can be used to provide **Mutual Exclusion**.

---

# Initial State

Suppose:

```text
S = 1
```

Meaning:

> One permit is available.

Process P1 executes:

```text
wait(S)
```

P1 takes the permit.

```text
S = 1
   ↓ wait()
S = 0
```

P1 proceeds.

---

# Another Process Arrives

Now:

```text
S = 0
```

P2 executes:

```text
wait(S)
```

There is no permit.

Therefore:

```text
P2 → WAIT
```

---

# When P1 Finishes

P1 executes:

```text
signal(S)
```

The permit becomes available / a waiter can be released.

Conceptually:

```text
S = 0
   ↓ signal()
S = 1
```

P2 can now proceed.

---

# Full Flow

```text
Initially

S = 1
│
│ P1 → wait(S)
▼
S = 0
│
├── P1 proceeds
│
│ P2 → wait(S)
▼
P2 WAITS
│
│ P1 → signal(S)
▼
Permit available
│
▼
P2 proceeds
```

---

# Using Binary Semaphore for Critical Section

Initialize:

```c
semaphore S = 1;
```

Process:

```c
wait(S);

// Critical Section

signal(S);
```

### Why does this work?

Initially:

```text
S = 1
```

P1:

```text
wait(S)
↓
takes the only permit
↓
P1 enters CS
```

P2:

```text
wait(S)
↓
No permit available
↓
WAIT
```

Therefore:

> Only **one process at a time** enters the protected Critical Section.

That gives us **Mutual Exclusion**.

---

# Why "Binary"?

Because there are only two logical states:

```text
1
↓
Permit Available

0
↓
Permit Unavailable
```

Hence:

> **Binary Semaphore**

---

# Binary Semaphore vs Mutex ⭐⭐⭐⭐⭐

They can look very similar:

```text
Binary Semaphore

wait()
↓
Critical Section
↓
signal()
```

and

```text
Mutex

lock()
↓
Critical Section
↓
unlock()
```

But they are **not the same thing**.

---

## Main Difference — Ownership

### Mutex

```text
P1 → lock()

↓

P1 owns Mutex

↓

P1 → unlock()
```

Mutex has an **owner**.

The owner is responsible for unlocking it.

---

### Binary Semaphore

Semaphore does not have Mutex-style ownership.

For synchronization/signaling, one thread may wait:

```text
P1 → wait(S)
```

while another thread/process performs:

```text
P2 → signal(S)
```

This is perfectly useful for signaling.

---

# Example — Signaling

Imagine:

```text
P2 must wait until P1 finishes loading data.
```

Initialize:

```text
S = 0
```

P2:

```text
wait(S)
↓
WAIT
```

P1 finishes:

```text
Load Data
↓
signal(S)
```

Now:

```text
P2 proceeds
```

Notice:

```text
P2 → wait()

P1 → signal()
```

Different threads performed the operations.

That's why binary semaphores are useful for **event synchronization**, not just mutual exclusion.

---

# Binary Semaphore Uses

### 1. Mutual Exclusion

```text
wait()
↓
Critical Section
↓
signal()
```

---

### 2. Process / Thread Synchronization

```text
P1 completes task
↓
signal()

P2
↓
wait()
↓
Continue
```

---

# Binary Semaphore vs Mutex

| Binary Semaphore | Mutex |
|---|---|
| One permit / two-state synchronization | Lock |
| `wait()` / `signal()` | `lock()` / `unlock()` |
| No ownership requirement | Has ownership |
| Can provide Mutual Exclusion | Provides Mutual Exclusion |
| Useful for signaling | Mainly locking |
| Different thread can signal | Owner should unlock |

---

# Binary Semaphore vs Spinlock

| Binary Semaphore | Spinlock |
|---|---|
| Can block waiting thread | Busy waits |
| CPU can do other work | Consumes CPU while waiting |
| `wait()` / `signal()` | Atomic spinning |
| Synchronization + signaling | Mutual-exclusion lock |

---

# 🎯 GATE Important Points

- Binary Semaphore has **one permit / two logical states**.
- Usually represented as `0` and `1`.
- `1` → permit available.
- `0` → permit unavailable.
- Can provide **Mutual Exclusion**.
- Uses atomic `wait()` and `signal()`.
- Does **not** have Mutex-style ownership.
- Can be used for **signaling** between processes/threads.
- Waiting can use **blocking** rather than busy waiting.

# Common GATE Traps

## Trap 1

> Binary Semaphore and Mutex are exactly the same.

❌ False

Both can provide Mutual Exclusion, but:

```text
Mutex
↓
Ownership

Binary Semaphore
↓
No Mutex-style ownership
```

---

## Trap 2

> Binary Semaphore can only be used for Mutual Exclusion.

❌ False

It can also be used for **process/thread synchronization and signaling**.

---

## Trap 3

> Binary Semaphore always uses Busy Waiting.

❌ False

Waiting processes can be **blocked**.

---

## Trap 4

> Binary Semaphore has multiple permits.

❌ False

That's the idea behind a **Counting Semaphore**.

Binary Semaphore has **one permit**.
