## Spinlock — Super Simple

A **spinlock is a lock where the waiting thread keeps checking the lock again and again until it becomes free.**

That's it.

Imagine a bathroom:

**Mutex with blocking:**

> "Occupied? Okay, I'll sleep/wait. Wake me when it's free."

**Spinlock:**

> "Free? No. Free? No. Free? No. Free? NOW?..." 😭

The thread is **spinning** around the same check.

### In code

```cpp
while (lock == 1) {
    // keep checking
}
```

Or using the atomic instruction you already learned:

```cpp
while (TestAndSet(lock)) {
    // spin
}

// Critical Section

lock = 0;
```

While another thread owns the lock:

```text
P1 → Critical Section

P2 → Check → Locked
      Check → Locked
      Check → Locked
      Check → Locked
      Check → FREE!
              ↓
             Enter
```

The important consequence is that **P2 is consuming CPU while waiting**.

So:

> **Spinlock = Lock + Busy Waiting**

### Why would we ever use it?

Because sleeping/waking a thread also has overhead.

If the lock will be held for an **extremely short time**, it may be faster to:

```text
wait actively for 1 μs
```

than:

```text
Put thread to sleep
→ Context switch
→ Wake thread
→ Schedule thread
```

So the intuition is:

|Spinlock|Blocking Mutex|
|---|---|
|Keeps checking|Goes to sleep|
|Busy waiting|Blocking|
|Consumes CPU while waiting|Frees CPU|
|Good for **very short waits**|Good for **longer waits**|

### Connection to what you learned

This is why we kept saying:

```text
Test-and-Set
      ↓
while(TestAndSet(lock))
      ↓
Keep checking
      ↓
Busy Waiting
      ↓
SPINLOCK
```

Test-and-Set/CAS are **atomic hardware operations** that can be used to **build a spinlock**.

### GATE one-liner

> **A spinlock is a mutual-exclusion lock in which a waiting process/thread continuously checks the lock in a loop (busy waiting) instead of blocking.**

🧠 **Memory trick:** **Spin = keep spinning/checking.**
