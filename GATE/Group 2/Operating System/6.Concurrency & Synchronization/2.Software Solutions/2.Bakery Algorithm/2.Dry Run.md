# Why `choosing[]` Exists

This is the trickiest part.

Imagine P1 is **still calculating** its ticket.

Suppose the current tickets are:

```text
P0 → 1
P1 → ?
P2 → 0
```

P1 has **not finished** choosing.

If P2 immediately looks at P1's ticket, it might still see:

```text
0
```

and think:

> "P1 isn't interested."

That's wrong—P1 **is** interested, but it's in the middle of choosing its ticket.

So P1 sets:

```c
choosing[1] = true;
```

When P2 sees this, it waits until P1 finishes choosing.

Only after P1 sets:

```c
choosing[1] = false;
```

does P2 read `number[1]`.

This prevents inconsistent or partially updated ticket values from being used.

# 🎯 Memory Trick

Think of a bakery:

```text
Walk in

↓

Take Token

↓

Wait until everyone finishes taking tokens

↓

Smallest Token Wins

↓

Finish Shopping

↓

Throw Away Token
```

Mapping to the algorithm:

|Bakery|Algorithm|
|---|---|
|Take token|`number[i] = max(number) + 1`|
|Still taking token|`choosing[i] = true`|
|Done taking token|`choosing[i] = false`|
|Wait for your turn|Compare ticket numbers|
|Leave bakery|`number[i] = 0`|

Once you remember this analogy, you don't have to memorize the code—you can reconstruct it from the real-world process.
