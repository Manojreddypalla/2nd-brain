# Bakery Algorithm (Lamport's Bakery Algorithm)

---

# Definition

**Bakery Algorithm** is a **software-based synchronization algorithm** that solves the **Critical Section Problem for multiple processes (N processes)**.

It is based on the idea of taking a **token number**, just like customers waiting in a bakery.

It guarantees:

- ✅ Mutual Exclusion
- ✅ Progress
- ✅ Bounded Waiting

without using special hardware instructions.

---

# Why Do We Need Bakery Algorithm?

Peterson's Algorithm works only for:

```
P0

P1
```

What if we have

```
P0
P1
P2
P3
...
Pn
```

Peterson cannot handle this.

So Lamport proposed the **Bakery Algorithm**.

# Shared Variables

The Bakery Algorithm uses two arrays.

## 1. choosing[]

```c
bool choosing[n];
```

Purpose:

Indicates that a process is **currently choosing a ticket number**.

Initially

```c
false
```

for every process.

---

## 2. number[]

```c
int number[n];
```

Stores the ticket number of every process.

Initially

```c
0
```

means

```
Not interested.
```

---

# Algorithm

For process Pi

```c
choosing[i] = true;

number[i] = 1 + max(number[]);

choosing[i] = false;

for each process j

    while(choosing[j]);

    while(number[j] != 0 &&
          (number[j], j) < (number[i], i));


// Critical Section


number[i] = 0;
```

# Understanding the Steps

## Step 1

Process decides to enter.

```
I want to enter.
```

---

## Step 2

Take a token.

```
number = max(existing numbers)+1
```

Example

Existing

```
2

5

7
```

New process gets

```
8
```

---

## Step 3

Finished taking token.

```
choosing=false
```

---

## Step 4

Wait until

- everyone finishes choosing

AND

- processes with smaller numbers finish first.

---

## Step 5

Enter Critical Section.

---

## Step 6

Leave.

Reset

```c
number=0;
```

meaning

```
I'm no longer waiting.
```

# What if Two Processes Take Same Number?

Example

```
P0 → 5

P1 → 5
```

Tie.

Use Process ID.

```
(5,0)

(5,1)
```

Smaller PID wins.

So

```
P0 enters first.
```

---

# Why choosing[]?

Suppose

P1 is still calculating

```
max(number)+1
```

If another process reads its number now,

it may get an incorrect value.

So

```
choosing=true
```

tells everyone

```
Wait.

I'm still taking my token.
```

---

# Why Does It Work?

## Mutual Exclusion

Smallest ticket enters.

Only one process has highest priority.

---

## Progress

If Critical Section is free,

smallest ticket enters immediately.

---

## Bounded Waiting

Every new process gets a larger ticket.

Therefore,

older tickets are always served first.

No starvation.

---

# Advantages

- Supports multiple processes.
- Pure software solution.
- Fair ordering.
- Guarantees Mutual Exclusion.
- Guarantees Progress.
- Guarantees Bounded Waiting.

---

# Limitations

- Busy Waiting.
- Slower for many processes.
- Complex compared to Peterson.
- Mostly theoretical.
- Rarely used in modern operating systems.

---

# Peterson vs Bakery

| Peterson | Bakery |
|-----------|--------|
| 2 Processes | N Processes |
| flag[] + turn | choosing[] + number[] |
| Busy Waiting | Busy Waiting |
| Simple | More complex |
