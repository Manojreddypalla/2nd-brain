# Hardware Solutions (Critical Section) — GATE Summary Notes

---

# Why Hardware Solutions?

Software solutions (like Peterson's Algorithm) have limitations:

- Works only for limited processes.
- Difficult to implement on multicore CPUs.
- Relies on normal instructions that can be interrupted.

Hardware solutions solve this by providing **atomic instructions**.

> **Atomic = Executes completely or not at all (cannot be interrupted).**

---

# Hardware Synchronization Instructions

There are **3 important hardware instructions**:

1. Test-and-Set (TSL)
2. Compare-and-Swap (CAS)
3. Swap Instruction

All are used to implement **Mutual Exclusion**.

---

# 1. Test-and-Set (TSL)

## Definition

An **atomic hardware instruction** that

- Returns the **old value**
- Sets the lock to **1**

---

## Internal Working

```cpp
old = lock;

lock = 1;

return old;
```

(Executed atomically)

---

## Logic

```text
old = 0

↓

Lock was free

↓

Enter Critical Section
```

```text
old = 1

↓

Someone already owns the lock

↓

Busy Wait
```

---

## Characteristics

- Hardware Instruction
- Atomic
- Always writes to memory
- Returns old value
- Busy Waiting
- Spin Lock
- Mutual Exclusion

---

## Memory Trick

> **Test → Set → Return Old Value**

---

# 2. Compare-and-Swap (CAS)

## Definition

An atomic instruction that

- Compares memory with an expected value.
- Updates memory **only if they are equal**.

---

## Internal Working

```cpp
if(memory == expected)

memory = newValue;
```

(Executed atomically)

---

## Logic

```text
Expected == Current

↓

YES

↓

Update Memory
```

```text
Expected != Current

↓

No Update
```

---

## Characteristics

- Hardware Instruction
- Atomic
- Conditional Update
- Reduces unnecessary writes
- Busy Waiting
- Used in Lock-Free Algorithms

---

## Memory Trick

> **Compare → Match → Update**

---

# 3. Swap Instruction

## Definition

An atomic instruction that exchanges two variables.

---

## Internal Working

```cpp
Swap(lock,key);
```

Conceptually

```cpp
temp = lock;

lock = key;

key = temp;
```

(Executed atomically)

---

## Logic

Initially

```text
lock = 0

key = 1
```

After Swap

```text
lock = 1

key = 0
```

If

```text
key == 0
```

Process acquired the lock.

---

## Characteristics

- Hardware Instruction
- Atomic
- Exchanges values
- Busy Waiting
- Spin Lock

---

## Memory Trick

> **Swap = Exchange**

# Advantages of Hardware Solutions

- Atomic operations
- Prevent Race Conditions
- Hardware Supported
- Faster than software solutions
- Suitable for multicore processors
- Used to implement synchronization primitives

---

# Disadvantages

- Busy Waiting (CPU Wastage)
- Starvation Possible
- Fairness Not Guaranteed
- Usually require higher-level primitives (Mutex/Semaphore) for practical systems

❌ False

❌ False

### Trap 3

> Test-and-Set performs conditional updates.

❌ False

---

### Trap 4

❌ False

❌ False
