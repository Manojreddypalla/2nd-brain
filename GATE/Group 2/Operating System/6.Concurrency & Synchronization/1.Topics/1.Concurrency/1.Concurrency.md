# Concurrency

---

# Definition

**Concurrency** is the ability of a system to **make progress on multiple tasks during the same period of time**.

> It does **not** mean tasks execute at the exact same instant. Instead, they **overlap in execution**.

---

# Why Do We Need Concurrency?

Imagine you're downloading a file while listening to music.

Without concurrency:

```text
Download File

↓

Finish

↓

Play Music
```

You would have to wait for the download to finish before listening to music.

With concurrency:

```text
Download File
      ↕
Play Music
```

Both tasks make progress during the same time period.

This improves:

- CPU utilization
- Responsiveness
- User experience

---

# How Does Concurrency Work?

On a **single-core CPU**, only **one instruction** can execute at any instant.

The operating system rapidly switches the CPU between tasks.

```text
Time →

Task A : ███     ███     ███

Task B :     ███     ███

CPU     : A A A B B B A A A B B A
```

The switching happens so quickly that both tasks appear to run simultaneously.

This is called **context switching**.

---

# Concurrency vs Simultaneous Execution

Many people think:

> "Concurrency means running everything at the same time."

This is **not necessarily true**.

Concurrency means:

- Multiple tasks are **in progress**.
- The CPU may switch between them.

Even if only one task runs at a particular instant, the overall execution is concurrent.

---

# Concurrency on Multi-Core Systems

If multiple CPU cores are available:

```text
Core 1

Task A

----------------

Core 2

Task B
```

Tasks can still be concurrent.

They may also become **parallel**, which we'll study next.

---

# Characteristics

- Multiple tasks overlap.
- Improves responsiveness.
- Achieved using scheduling.
- May or may not use multiple CPU cores.
- Requires synchronization when tasks share resources.

---

# Real-Life Analogy

Imagine a chef preparing two dishes.

```text
Boil Pasta

↓

While waiting...

↓

Cut Vegetables

↓

Stir Sauce

↓

Return to Pasta
```

The chef isn't cooking both dishes at the exact same moment.

Instead, the chef alternates between tasks, ensuring both progress.

This is **Concurrency**.

---

# Operating System Examples

- Web browser downloading a file while rendering a webpage.
- Music player playing songs while loading the next track.
- IDE compiling code while you continue typing.
- Server handling requests from multiple clients.

---

# Advantages

- Better CPU utilization.
- Improved responsiveness.
- Higher throughput.
- Efficient resource usage.

---

# Disadvantages

- More difficult to program.
- Race conditions may occur.
- Requires synchronization mechanisms.
- Debugging is harder.

---

# Important Terms

### Task

A unit of work.

Examples:

- Process
- Thread

---

### Context Switching

The operating system saves the state of one task and loads the state of another.

This enables concurrency on a single-core CPU.

---

# GATE Points ⭐

- Concurrency means **multiple tasks make progress during the same time period**.
- It **does not require** multiple CPU cores.
- A single-core CPU achieves concurrency through **context switching**.
- Concurrency improves responsiveness and resource utilization.
- Concurrency can lead to **race conditions** when tasks share data.

---

# Common GATE MCQs

### Q1

Can concurrency exist on a single-core processor?

- Yes
- No

✅ **Answer:** Yes

Reason: Context switching.

---

### Q2

Which mechanism enables concurrency on a single-core CPU?

- DMA
- Context Switching
- Paging
- Caching

✅ **Answer:** Context Switching

---

### Q3

Does concurrency always imply parallel execution?

- Yes
- No

✅ **Answer:** No

Parallelism requires simultaneous execution, whereas concurrency only requires overlapping progress.
