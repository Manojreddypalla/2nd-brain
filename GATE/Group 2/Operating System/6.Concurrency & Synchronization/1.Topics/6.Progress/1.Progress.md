
# Progress

---

# Definition

**Progress** is a property that ensures:

> **If no process is currently executing inside the Critical Section, then the selection of the next process to enter should not be postponed indefinitely.**

In simple words:

> If the Critical Section is free, **someone who wants to enter should be allowed to enter.**

---

# Why Do We Need Progress?

Imagine the Critical Section is empty.

```text
Critical Section

EMPTY
```

Thread A wants to enter.

Thread B wants to enter.

Nobody is inside.

Question:

**Who should enter?**

A correct synchronization algorithm should quickly decide.

It should **not keep everyone waiting forever.**

---

# Without Progress

```text
Thread A → Wants to Enter

Thread B → Wants to Enter

Critical Section → Empty

↓

Nobody Enters
```

The CPU keeps waiting forever.

Even though the resource is free.

This violates **Progress**.

---

# With Progress

```text
Critical Section

Empty

↓

Thread A enters

↓

Leaves

↓

Thread B enters
```

The system keeps moving forward.

---

# Important Rule

Processes that **do not want to enter** the Critical Section

must **not affect** the decision.

Example

```text
Thread A → Wants Critical Section

Thread B → Doesn't Care

Thread C → Doesn't Care
```

Only Thread A should participate in the decision.

B and C should not delay A.

---

# Real-Life Analogy

Imagine a restaurant.

There is one empty table.

```text
Customer A → Waiting

Customer B → Waiting

Table → Empty
```

A waiter says:

> "Nobody can sit."

Everyone waits forever.

This is **No Progress**.

Correct behavior:

```text
Table Empty

↓

Seat Customer A

↓

Later

↓

Seat Customer B
```

---

# Characteristics

- Applies only when the Critical Section is empty.
- Someone waiting should eventually be selected.
- Decision should not be postponed forever.
- Only interested processes participate.

---

# Progress vs Mutual Exclusion

## Mutual Exclusion

Question:

> Can two processes enter together?

Answer:

**No.**

---

## Progress

Question:

> If nobody is inside, can someone who wants to enter actually get in?

Answer:

**Yes.**

---

# Example

Suppose

```text
Critical Section

EMPTY
```

Thread A

```text
Waiting
```

Thread B

```text
Doing unrelated work
```

Correct algorithm:

Thread A enters immediately.

Wrong algorithm:

Wait for Thread B's permission.

This violates Progress because B isn't interested.

---

# Why Progress Matters

Without Progress:

- CPU time is wasted.
- Resource stays unused.
- Threads wait unnecessarily.
- System throughput decreases.

---

# GATE Points ⭐

- Progress applies **only when the Critical Section is empty.**
- If processes want to enter, one of them should be selected.
- Decision should not be delayed indefinitely.
- Processes not interested in entering should not influence the decision.

---

# Quick Revision ⭐

- Critical Section is empty.
- Someone wants to enter.
- Let them enter.
- Don't wait forever.
- Ignore processes that aren't interested.
