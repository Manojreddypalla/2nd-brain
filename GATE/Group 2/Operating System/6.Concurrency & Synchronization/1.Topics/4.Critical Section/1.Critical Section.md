# Critical Section

---

# Definition

A **Critical Section** is the **part of a program where shared resources (shared data, files, memory, devices, etc.) are accessed or modified**.

Only **one process or thread** should execute its critical section at a time.

---

# Why Do We Need a Critical Section?

Consider two threads updating the same bank account.

```text
Balance = 1000
```

Thread A

```c
balance = balance + 100;
```

Thread B

```c
balance = balance - 200;
```

If both execute together,

a **Race Condition** occurs.

To prevent this,

the shared code must be protected.

That protected code is called the **Critical Section**.

---

# What Makes a Section "Critical"?

A section becomes critical when it accesses **shared resources**.

Examples:

- Shared variable
- Shared memory
- Shared file
- Printer
- Database record

If only one thread uses a variable,

it is **not** a critical section.

---

# Program Structure

Every process can be divided into four parts.

```text
Entry Section

↓

Critical Section

↓

Exit Section

↓

Remainder Section
```

---

## 1. Entry Section

Requests permission to enter the Critical Section.

Example:

```text
Acquire Lock
```

---

## 2. Critical Section

Accesses shared resources.

Example:

```c
balance = balance + 100;
```

---

## 3. Exit Section

Releases the resource.

Example:

```text
Release Lock
```

---

## 4. Remainder Section

Normal program code.

No shared resource is accessed.

Example:

```c
printf("Hello");
```

---

# Example

```c
lock();

balance = balance + 100;

unlock();
```

Here

```c
balance = balance + 100;
```

is the **Critical Section**.

# Real-Life Analogy

Imagine a bathroom with only one key.

```text
Person A

↓

Gets Key

↓

Uses Bathroom

↓

Returns Key

↓

Person B
```

Only one person can use the bathroom at a time.

The bathroom is the **Critical Section**.

The key is the **Lock/Mutex**.

---

# Characteristics

- Contains shared resources.
- Must be protected.
- Only one execution unit should enter at a time.
- Prevents race conditions.
- Uses synchronization mechanisms.

---

# Why Can't Multiple Threads Enter?

Suppose

```text
Counter = 0
```

Thread A

```c
counter++;
```

Thread B

```c
counter++;
```

Both execute together.

Possible result

```text
Counter = 1
```

instead of

```text
Counter = 2
```

This happens because the Critical Section was not protected.

---

# Critical Section Problem

The **Critical Section Problem** asks:

> **How can multiple processes share resources without causing race conditions?**

The operating system must ensure:

- Mutual Exclusion
- Progress
- Bounded Waiting

These are the three correctness requirements that we'll study next.

shared->temperature = 30;

# Critical Section vs Race Condition

| Critical Section | Race Condition |
|-----------------|----------------|
| Protected code region | Error caused by concurrent access |
| Contains shared resource | Incorrect result |
| Needs synchronization | Occurs without synchronization |

---

# Critical Section vs Remainder Section

| Critical Section | Remainder Section |
|-----------------|-------------------|
| Shared resources | Private work |
| Needs synchronization | No synchronization |
| One thread at a time | Multiple threads allowed |

---

# GATE Points ⭐

- Critical Section is the code that accesses shared resources.
- It must be executed by only one process/thread at a time.
- Protecting the Critical Section prevents race conditions.
- Program structure:
  - Entry
  - Critical
  - Exit
  - Remainder
- The Critical Section Problem is solved using synchronization mechanisms.
