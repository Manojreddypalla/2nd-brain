# Multilevel Queue (MLQ) & Multilevel Feedback Queue (MLFQ)

## Why Do We Need Them?

Different processes have different requirements.

For example:

- System processes need quick CPU access.
- Interactive applications need fast response.
- Batch jobs can wait longer.

Instead of placing every process in one Ready Queue, the operating system can divide them into **multiple queues**.

---

# 1. Multilevel Queue (MLQ)

## Definition

**Multilevel Queue (MLQ)** is a CPU scheduling algorithm in which the **Ready Queue is divided into multiple fixed queues**, and each process is permanently assigned to one queue.

Each queue may use a different scheduling algorithm.

---

## How MLQ Works

- Processes are classified into different queues.
- A process **cannot move** from one queue to another.
- The CPU schedules processes either:
  - By assigning priorities to queues, or
  - By giving each queue a fixed amount of CPU time.

---

## Example

```text
Ready Queue

+-------------------------+
| System Processes (RR)   |
+-------------------------+
| Interactive (RR)        |
+-------------------------+
| Batch Processes (FCFS)  |
+-------------------------+
```

Example:

- System Queue → Round Robin
- Interactive Queue → Round Robin
- Batch Queue → FCFS

---

## Characteristics

- Multiple fixed queues.
- Process remains in the same queue.
- Different scheduling algorithms can be used for different queues.
- Queue priorities are predefined.

---

## Advantages

- Easy to organize different types of processes.
- Different scheduling policies for different workloads.
- Good for systems with well-defined process classes.

---

## Disadvantages

- Inflexible because processes cannot change queues.
- Low-priority queues may suffer from starvation.

---

# 2. Multilevel Feedback Queue (MLFQ)

## Definition

**Multilevel Feedback Queue (MLFQ)** is an extension of MLQ in which a process **can move between queues** based on its CPU usage and behavior.

---

## How MLFQ Works

- Multiple queues with different priorities.
- New processes usually start in the highest-priority queue.
- If a process uses too much CPU, it is moved to a lower-priority queue.
- If a process waits for a long time, it may be promoted to a higher-priority queue (Aging).

---

## Example

```text
High Priority Queue (RR)
          ↓
Medium Priority Queue (RR)
          ↓
Low Priority Queue (FCFS)
```

A CPU-bound process gradually moves downward, while interactive processes remain near the top.

---

## Characteristics

- Multiple queues.
- Processes can move between queues.
- Uses feedback based on process behavior.
- Helps balance fairness and performance.

---

## Advantages

- Better response time for interactive processes.
- Reduces starvation using Aging.
- More flexible than MLQ.
- Adapts automatically to different workloads.

---

## Disadvantages

- Complex to implement.
- Choosing queue parameters is difficult.
- More scheduling overhead.

---

# Difference Between MLQ and MLFQ

| Feature | MLQ | MLFQ |
|---------|-----|------|
| Number of Queues | Multiple | Multiple |
| Process Movement | Not Allowed | Allowed |
| Queue Assignment | Fixed | Dynamic |
| Flexibility | Low | High |
| Starvation | Possible | Reduced using Aging |
| Complexity | Simple | More Complex |

---

# GATE Points ⭐

### Multilevel Queue (MLQ)

- Multiple fixed queues.
- Process **cannot** move between queues.
- Different queues may use different scheduling algorithms.
- Can suffer from starvation.

### Multilevel Feedback Queue (MLFQ)

- Multiple queues with different priorities.
- Process **can** move between queues.
- Uses feedback based on CPU usage.
- Aging helps reduce starvation.
- More flexible than MLQ.

---
