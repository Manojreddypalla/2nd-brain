# CPU Scheduling – General Q&A

## Q1. What is CPU Scheduling?

**Answer:**  
CPU Scheduling is the process by which the operating system selects one process from the **Ready Queue** and allocates the CPU to it.

---

## Q2. Why is CPU Scheduling needed?

**Answer:**  
To keep the CPU busy and improve system performance. When one process waits for I/O, another process can use the CPU.

---

## Q3. What is the primary goal of CPU Scheduling?

**Answer:**  
**Maximize CPU utilization while minimizing waiting and response times.**

---

## Q4. Who performs CPU Scheduling?

**Answer:**  
The **Short-Term Scheduler (CPU Scheduler)**.

---

## Q5. When is CPU Scheduling performed?

**Answer:**  
Scheduling may occur when:

- A process terminates.
    
- A process blocks for I/O.
    
- A process becomes ready.
    
- A timer interrupt occurs (preemptive scheduling).
    

---

## Q6. What is a CPU Burst?

**Answer:**  
The period during which a process executes instructions on the CPU.

---

## Q7. What is an I/O Burst?

**Answer:**  
The period during which a process waits for an I/O operation to complete.

---

## Q8. What is the CPU–I/O Burst Cycle?

**Answer:**  
A process alternates between CPU execution and I/O waiting.

```text
CPU Burst → I/O Burst → CPU Burst → I/O Burst → ...
```

---

## Q9. What is a CPU-bound process?

**Answer:**  
A process that spends most of its time performing computations.

Characteristics:

- Long CPU bursts
    
- Few I/O operations
    

Example:

- Video rendering
    
- AI training
    
- Scientific computation
    

---

## Q10. What is an I/O-bound process?

**Answer:**  
A process that spends most of its time waiting for I/O.

Characteristics:

- Short CPU bursts
    
- Frequent I/O
    

Example:

- Browser
    
- File copy
    
- Database query
    

---

## Q11. What happens if there is no CPU Scheduling?

**Answer:**  
The CPU remains idle whenever the running process waits for I/O, resulting in poor CPU utilization.

---

## Q12. What is Multiprogramming?

**Answer:**  
Keeping multiple processes in memory so that whenever one process waits for I/O, another process can execute.

---

## Q13. What is the relationship between Multiprogramming and CPU Scheduling?

**Answer:**  
Multiprogramming provides multiple ready processes, while CPU Scheduling decides **which one gets the CPU next**.

---

## Q14. Can CPU Scheduling happen if only one process exists?

**Answer:**  
No. If there is only one runnable process, there is no scheduling decision to make; the process simply runs whenever it is ready.

---

## Q15. Is CPU Scheduling done in User Mode or Kernel Mode?

**Answer:**  
**Kernel Mode.**

Only the operating system can allocate the CPU.

---

## Q16. What is the difference between Scheduling and Dispatching?

**Answer:**

**Scheduling**

- Decides **which** process should run next.
    

**Dispatching**

- Actually gives the CPU to that selected process.
    

---

## Q17. Can a blocked process be scheduled?

**Answer:**  
No.

Only processes in the **Ready** state are eligible for CPU scheduling.

---

## Q18. Which queue does the scheduler select a process from?

**Answer:**  
The **Ready Queue**.

---

## Q19. Can more than one process execute on a single-core CPU at the same instant?

**Answer:**  
No.

A single-core CPU executes only one process at a time, using rapid context switches to create the illusion of concurrency.

---

## Q20. What is the main objective of a good scheduling algorithm?

**Answer:**

- Maximize CPU utilization
    
- Increase throughput
    
- Reduce waiting time
    
- Reduce turnaround time
    
- Improve response time
    
- Ensure fairness
    
- Avoid starvation

- **I/O-bound = Frequent I/O**
    
- **Scheduling happens in Kernel Mode**
    
- **Only Ready processes are scheduled**
