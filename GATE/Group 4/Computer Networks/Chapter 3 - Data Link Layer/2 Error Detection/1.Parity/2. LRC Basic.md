# 3.2.2 Longitudinal Redundancy Check (LRC)

> [!info] Definition
> **Longitudinal Redundancy Check (LRC)** is an error detection technique in which a **parity bit is calculated for each column** of multiple data units. The collection of these parity bits forms an additional row called the **LRC**.

It is also known as the **Two-Dimensional Parity Check** because parity can be checked both row-wise (VRC) and column-wise (LRC).

---

# Why is LRC Needed?

VRC (Parity Check) uses only **one parity bit** for each data unit.

If an **even number of bits** changes, VRC may fail to detect the error.

LRC improves error detection by checking the parity of **each column** across multiple data units.

---

# Basic Idea

Suppose we have four 4-bit data units.

```
D1 : 1 0 1 1
D2 : 0 1 0 1
D3 : 1 1 1 0
D4 : 0 0 1 1
```

Arrange them in a table.

| Data | b1 | b2 | b3 | b4 |
|------|----|----|----|----|
| D1 | 1 | 0 | 1 | 1 |
| D2 | 0 | 1 | 0 | 1 |
| D3 | 1 | 1 | 1 | 0 |
| D4 | 0 | 0 | 1 | 1 |

Now calculate **Even Parity** for each column.

| Column | Number of 1s | Parity Bit |
|---------|--------------|------------|
| b1 | 2 | 0 |
| b2 | 2 | 0 |
| b3 | 3 | 1 |
| b4 | 3 | 1 |

Hence,

```
LRC = 0 0 1 1
```

---

# Data Transmitted

```
D1  : 1 0 1 1
D2  : 0 1 0 1
D3  : 1 1 1 0
D4  : 0 0 1 1
-----------------
LRC : 0 0 1 1
```

The sender transmits all the data rows followed by the **LRC row**.

---

# Sender Algorithm

1. Arrange data into rows.
2. Count the number of 1s in each column.
3. Generate the parity bit for every column.
4. Form the LRC row.
5. Append the LRC row to the transmitted data.

---

# Receiver Algorithm

1. Receive all data rows and the LRC row.
2. Count the number of 1s in each column.
3. Verify the parity of every column.
4. If any column violates the parity rule, an error is detected.

---

# Example of Error Detection

Suppose the transmitted data is

```
D1 : 1 0 1 1
D2 : 0 1 0 1
D3 : 1 1 1 0
D4 : 0 0 1 1
LRC: 0 0 1 1
```

During transmission, one bit changes.

```
Original D2 : 0 1 0 1

Received D2 : 0 1 1 1
```

Now column **b3** has incorrect parity.

Receiver recalculates parity.

```
Expected : Even

Received : Odd
```

Hence,

```
Error Detected
```

---

# Error Detection Capability

LRC can detect

- ✅ All single-bit errors
- ✅ Most double-bit errors
- ✅ Many burst errors (short bursts)

LRC cannot detect every possible error pattern.

---

# Advantages

- Better error detection than VRC.
- Detects many multiple-bit errors.
- Easy to implement.
- Low computational overhead.
- Improves communication reliability.

---

# Disadvantages

- Cannot detect all burst errors.
- Cannot correct errors.
- Requires transmitting an additional parity row.
- Less reliable than CRC.

---

# Applications

LRC is used in

- Magnetic tape storage
- Serial communication
- Early communication systems

Modern communication systems generally use **CRC** because it provides much stronger error detection.

---

# VRC vs LRC

| Feature | VRC | LRC |
|----------|-----|-----|
| Full Form | Vertical Redundancy Check | Longitudinal Redundancy Check |
| Parity Applied On | Each Row | Each Column |
| Extra Bits | One parity bit per data unit | One parity row |
| Detects Single-Bit Errors | ✅ | ✅ |
| Detects Multiple-Bit Errors | Limited | Better |
| Burst Error Detection | Poor | Better |
| Reliability | Lower | Higher |

---

# Memory Trick

Imagine a classroom.

```
VRC → Check each student's marks (Row)

LRC → Check each subject's marks (Column)
```

**VRC = Horizontal Check**

**LRC = Vertical Check**

---

# Summary

- LRC stands for **Longitudinal Redundancy Check**.
- It is also called **Two-Dimensional Parity Check**.
- A parity bit is calculated for each **column**.
- The generated parity bits form an **LRC row**.
- LRC detects errors more effectively than VRC.
- Modern networks prefer CRC because it offers much stronger error detection.
