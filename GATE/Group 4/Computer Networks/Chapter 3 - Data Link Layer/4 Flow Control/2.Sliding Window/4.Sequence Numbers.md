# Sequence Numbers

## Definition

A **Sequence Number** is a unique number assigned to every frame before transmission.

> It enables the sender and receiver to uniquely identify each frame during communication.

---

# Why Do We Need Sequence Numbers?

Suppose the sender transmits three frames.

```text
Frame
Frame
Frame
```

If one frame is lost or duplicated,

the receiver cannot determine:

- Which frame was lost?
- Which frame is a duplicate?
- Which frame should be acknowledged?

Hence, every frame is assigned a unique sequence number.

Example

```text
Frame 0

Frame 1

Frame 2

Frame 3
```

Now every frame has its own identity.

---

# Functions of Sequence Numbers

Sequence numbers help the receiver to:

- Identify duplicate frames.
- Detect lost frames.
- Maintain the correct order.
- Distinguish retransmissions from new transmissions.
- Perform reliable communication.

---

# Example

Sender transmits

```text
0 → 1 → 2 → 3
```

Receiver receives

```text
0

1

3
```

Frame **2** is missing.

Because of sequence numbers,

the receiver immediately knows

```text
Missing Frame = 2
```

---

# Sequence Number Space

Sequence numbers are finite.

They are represented using **n bits**.

Suppose

$$
n=3
$$

Maximum sequence numbers

$$
2^3=8
$$

Available sequence numbers

```text
0 1 2 3 4 5 6 7
```

---

# General Formula

If sequence numbers use

$$
n
$$

bits,

then

$$
\boxed{\text{Sequence Number Space}=2^n}
$$

---

# Wrap Around

After the largest sequence number,

numbering starts again from zero.

Example

For

$$
n=3
$$

```text
0 → 1 → 2 → 3 → 4 → 5 → 6 → 7

↓

0 → 1 → 2 ...
```

This is called **Wrap Around**.

---

# Why Does Wrap Around Happen?

Sequence numbers use a fixed number of bits.

Example

3 bits

Maximum binary value

```text
111
```

which equals

```text
7
```

There is no

```text
1000
```

because that requires **4 bits**.

Hence,

after

```text
111
```

the counter becomes

```text
000
```

again.

---

# Problem Without Proper Window Size

Suppose

Sequence Numbers

```text
0 1 2 3
```

Sender transmits

```text
0

1

2

3
```

Later,

the sender again transmits

```text
0
```

Receiver may become confused.

Question:

Is this

- Old Frame 0?

or

- New Frame 0?

This ambiguity is solved by restricting the window size.

---

# Sequence Number Rules

The maximum window size depends on the protocol.

---

## Stop-and-Wait

Sender Window Size

$$
SWS=1
$$

Receiver Window Size

$$
RWS=1
$$

Only one frame is outstanding.

---

## Go-Back-N

Receiver Window

$$
RWS=1
$$

Maximum Sender Window

$$
\boxed{SWS\le2^n-1}
$$

where

$$
n
$$

is the number of sequence number bits.

---

### Example

Suppose

$$
n=3
$$

Sequence Number Space

$$
2^3=8
$$

Maximum Sender Window

$$
SWS=7
$$

---

## Selective Repeat

Sender Window

Receiver Window

Both can be greater than one.

Maximum Window Size

$$
\boxed{SWS=RWS\le2^{n-1}}
$$

---

### Example

Suppose

$$
n=3
$$

Maximum Window

$$
2^{3-1}=4
$$

Therefore,

```text
Sender Window = 4

Receiver Window = 4
```

---

# Why Selective Repeat Uses Half the Sequence Space

Suppose

Sequence Numbers

```text
0 1 2 3
```

If the window size is also

```text
4
```

then after wrap around,

the receiver cannot distinguish

Old Frame 0

from

New Frame 0.

To avoid this ambiguity,

Selective Repeat limits the window size to **half of the sequence number space**.

---

# Summary Table

| Protocol | Sender Window | Receiver Window |
|-----------|--------------:|----------------:|
| Stop-and-Wait | 1 | 1 |
| Go-Back-N | $$2^n-1$$ | 1 |
| Selective Repeat | $$2^{n-1}$$ | $$2^{n-1}$$ |

---

# Important Facts

- Every frame has a sequence number.
- Sequence numbers repeat after wrap around.
- Sequence number space depends on the number of bits.
- Larger sequence space allows larger windows.
- Window size restrictions prevent ambiguity.
