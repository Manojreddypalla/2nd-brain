# Receiver Window

## Definition

The **Receiver Window** is the set of sequence numbers (frames) that the receiver is currently willing to accept.

> It specifies which incoming frames are considered **valid** and can be accepted.

---

# Why Do We Need a Receiver Window?

Suppose the sender transmits multiple frames.

```text
Sender

F0
F1
F2
F3
```

The receiver must decide:

- Which frames should be accepted?
- Which frames should be rejected?
- Which frames are duplicates?
- Which frames are outside the expected range?

The Receiver Window provides these rules.

---

# Basic Idea

The receiver accepts only the frames whose sequence numbers lie inside its current window.

Frames outside the window are rejected or ignored.

---

# Example

Suppose

Window Size = 4

Sequence Numbers

```text
0 1 2 3 4 5 6 7
```

Receiver Window

```text
[0 1 2 3] 4 5 6 7
```

The receiver can currently accept

- Frame 0
- Frame 1
- Frame 2
- Frame 3

Any other frame is outside the window.

---

# Receiving Frames

Suppose Frame 0 arrives.

```text
Receiver

Receive F0

↓

Accept

↓

Send ACK
```

Now the receiver expects the next frame.

The window slides.

```text
0 [1 2 3 4] 5 6 7
```

Frame 4 now becomes acceptable.

---

Suppose Frame 1 is received.

```text
0 1 [2 3 4 5] 6 7
```

Again,

the window slides forward.

---

# Window Movement

Initially

```text
[0 1 2 3]
```

After receiving Frame 0

```text
[1 2 3 4]
```

After receiving Frame 1

```text
[2 3 4 5]
```

Thus,

the receiver window continuously moves forward as valid frames are accepted.

---

# What Happens to Frames Outside the Window?

Suppose the receiver is expecting

```text
[4 5 6 7]
```

Instead, it receives

```text
Frame 1
```

Frame 1 lies outside the receiver window.

Therefore,

```text
Reject / Ignore Frame 1
```

Similarly,

Suppose the receiver gets

```text
Frame 0
```

again.

This is a duplicate frame.

It is also outside the current window and is discarded.

---

# Receiver Window Size (RWS)

Receiver Window Size specifies the maximum number of frames the receiver can accept at a given time.

Different protocols use different receiver window sizes.

---

## Stop-and-Wait

```text
RWS = 1
```

Only one frame can be accepted.

---

## Go-Back-N

```text
RWS = 1
```

Receiver accepts only the next expected frame.

Out-of-order frames are discarded.

---

## Selective Repeat

```text
RWS > 1
```

Receiver can accept multiple frames simultaneously.

Out-of-order frames are buffered until the missing frame arrives.

---

# Sender Window vs Receiver Window

| Sender Window | Receiver Window |
|---------------|-----------------|
| Controls transmission | Controls reception |
| Frames allowed to be sent | Frames allowed to be accepted |
| Maintained by sender | Maintained by receiver |
| Slides after ACKs | Slides after valid frame reception |

---

# Important Characteristics

- Defines acceptable sequence numbers.
- Rejects duplicate frames.
- Rejects invalid frames.
- Slides forward after receiving valid frames.
- Works together with the sender window.

---

# Applications

Receiver Window is used in

- Sliding Window Protocol
- Go-Back-N ARQ
- Selective Repeat ARQ
- TCP Flow Control
