# Sender Window

## Definition

The **Sender Window** is the set of sequence numbers (frames) that the sender is currently allowed to transmit.

> It limits the maximum number of **unacknowledged (outstanding)** frames that can be present in the network at any instant.

---

# Why Do We Need a Sender Window?

Suppose a sender has 1000 frames.

Without any restriction,

```text
Sender

F1
F2
F3
...
F1000
```

The sender may flood the network.

Problems:

- Receiver buffer overflow
- Congestion
- Lost frames
- Wasted bandwidth

Hence, the sender is allowed to send only a limited number of frames.

This limit is called the **Sender Window**.

---

# What Does the Sender Window Contain?

The Sender Window contains all frames that are:

- Already sent but not yet acknowledged.
- Ready to be transmitted.

Example

Window Size = 4

```text
Sequence Numbers

0 1 2 3 4 5 6 7

┌──────────────┐
│ 0 1 2 3      │
└──────────────┘
 4 5 6 7
```

The sender can transmit

- Frame 0
- Frame 1
- Frame 2
- Frame 3

---

# Window Size (SWS)

**Sender Window Size (SWS)** is the maximum number of outstanding frames allowed.

Example

```text
SWS = 4
```

Maximum outstanding frames

```text
4
```

---

# Outstanding Frames

Outstanding frames are frames that

- Have already been transmitted.
- Have **not yet** been acknowledged.

Example

```text
Sender

F0 ✓ Sent

F1 ✓ Sent

F2 ✓ Sent

F3 ✓ Sent

ACK not received
```

Outstanding Frames = 4

---

# Window Movement

Initially

```text
Sequence Numbers

0 1 2 3 4 5 6 7

[0 1 2 3] 4 5 6 7
```

Sender transmits

```text
F0

F1

F2

F3
```

Now the sender must wait because

Outstanding Frames = Window Size

---

Receiver sends

```text
ACK(0)
```

The sender window slides.

```text
0 [1 2 3 4] 5 6 7
```

Now Frame 4 becomes eligible for transmission.

---

Again,

ACK(1)

```text
0 1 [2 3 4 5] 6 7
```

Window continues moving.

---

# Why is it Called Sliding?

The window does **not** remain fixed.

Whenever acknowledgements arrive,

the window shifts forward.

```text
Before

[0 1 2 3]

↓

After ACK(0)

[1 2 3 4]

↓

After ACK(1)

[2 3 4 5]
```

Thus,

the transmission range continuously "slides."

---

# Sender Window Variables

The sender maintains two important pointers.

---

## 1. Last Acknowledgement Received (LAR)

LAR is the sequence number of the **last frame that has been acknowledged**.

Example

```text
ACK received up to Frame 5

LAR = 5
```

---

## 2. Last Frame Sent (LFS)

LFS is the sequence number of the **last frame transmitted**.

Example

```text
Frames Sent

0 1 2 3 4

LFS = 4
```

---

## Outstanding Frames

Outstanding Frames

$$
=LFS-LAR
$$

Example

```text
LFS = 6

LAR = 3
```

Outstanding Frames

$$
6-3=3
$$

---

# Sender Window Condition

The sender can transmit a new frame only if

$$
LFS-LAR<SWS
$$

If

$$
LFS-LAR=SWS
$$

the sender must stop and wait for an ACK.

---

# Example

Suppose

```text
SWS = 4

LAR = 5

LFS = 7
```

Outstanding Frames

$$
7-5=2
$$

Since

$$
2<4
$$

The sender can still transmit

- Frame 8
- Frame 9

until the window becomes full.

---

# Important Characteristics

- Sender controls transmission.
- Window limits outstanding frames.
- ACKs slide the window.
- Larger window improves utilization.
- Sender cannot exceed its window size.

---

# Advantages

- Better bandwidth utilization.
- Higher throughput.
- Continuous transmission.
- Reduced idle time.

---

# Limitations

- Requires sender buffer.
- More complex than Stop-and-Wait.
- Depends on sequence numbers.

---
