# Sliding Window Protocol

## Introduction

The **Sliding Window Protocol** is a **flow control protocol** that allows the sender to transmit **multiple frames before receiving acknowledgements (ACKs)**.

Unlike Stop-and-Wait, where only one frame can be in transit at a time, Sliding Window keeps multiple frames "on the network" simultaneously, improving communication efficiency and link utilization.

---

# Why Do We Need Sliding Window?

In the Stop-and-Wait protocol,

1. Sender transmits one frame.
2. Sender waits for ACK.
3. Sender sends the next frame.

```text
Sender                     Receiver

Frame 1 ------------->

          <------------ ACK

Frame 2 ------------->

          <------------ ACK
```

During the waiting period, the communication link remains idle.

This leads to:

- Low Utilization
- Low Throughput
- Poor Performance on long-distance links

---

Sliding Window solves this problem by allowing the sender to continue transmitting frames without waiting after every frame.

```text
Sender                     Receiver

F1 ------------->

F2 ------------->

F3 ------------->

F4 ------------->

          <------------ ACKs
```

Thus,

- Waiting time decreases.
- Communication link remains busy.
- More data is transmitted in the same amount of time.

---

# Definition

> **Sliding Window Protocol is a flow control mechanism in which the sender is allowed to transmit multiple frames before receiving acknowledgements, subject to a predefined window size.**

---

# Main Objective

The protocol aims to:

- Increase Link Utilization.
- Increase Throughput.
- Reduce Idle Time.
- Improve Network Efficiency.

---

# Basic Idea

Instead of allowing only one outstanding frame,

Sliding Window allows

```text
Window Size = N
```

This means

```text
Sender

F1
F2
F3
F4
```

can all be transmitted before receiving ACKs, provided they are inside the sender's window.

---

# What Does "Window" Mean?

A **window** is the set of sequence numbers that are currently allowed to be transmitted or accepted.

Think of it as a **moving range**.

Example

```text
Sequence Numbers

0 1 2 3 4 5 6 7
```

Suppose

Window Size = 4

Current Window

```text
[0 1 2 3] 4 5 6 7
```

The sender can transmit only

- Frame 0
- Frame 1
- Frame 2
- Frame 3

---

After ACK(0)

The window slides.

```text
0 [1 2 3 4] 5 6 7
```

Now,

Frame 4 becomes eligible for transmission.

This continuous movement gives the protocol its name:

**Sliding Window**.

---

# Important Terminologies

## Frame

A frame is a unit of data transmitted over the Data Link Layer.

---

## ACK (Acknowledgement)

A message sent by the receiver indicating successful reception of a frame.

---

## Outstanding Frame

A frame that has been transmitted but whose acknowledgement has not yet been received.

Example

```text
Sent

F1
F2
F3

ACK not received
```

All three are outstanding frames.

---

## Window Size

The maximum number of outstanding frames allowed at any instant.

Example

Window Size = 4

Maximum outstanding frames = 4

---

## Sender Window

The set of frames that the sender is currently permitted to transmit.

---

## Receiver Window

The set of frames that the receiver is currently willing to accept.

---

## Sequence Number

A unique number assigned to every frame.

Example

```text
Frame

0
1
2
3
4
```

Sequence numbers help identify:

- Lost frames
- Duplicate frames
- Out-of-order frames

---

# Key Characteristics

- Multiple frames can be transmitted without waiting.
- Frames are identified using sequence numbers.
- ACKs slide the window forward.
- Improves utilization of the communication link.
- Used in reliable data transmission protocols.

---

# Advantages

- High Link Utilization.
- Better Throughput.
- Efficient use of bandwidth.
- Reduced waiting time.
- Suitable for long-delay networks.

---

# Disadvantages

- More complex than Stop-and-Wait.
- Requires sequence numbers.
- Requires sender and receiver windows.
- Buffer management is necessary.

---

# Sliding Window vs Stop-and-Wait

| Stop-and-Wait | Sliding Window |
|---------------|----------------|
| One outstanding frame | Multiple outstanding frames |
| Wait after every frame | Continuous transmission |
| Low Utilization | High Utilization |
| Low Throughput | High Throughput |
| Simple | More Complex |

---

# Applications

Sliding Window is used in:

- Data Link Layer protocols
- TCP Flow Control
- Go-Back-N ARQ
- Selective Repeat ARQ
