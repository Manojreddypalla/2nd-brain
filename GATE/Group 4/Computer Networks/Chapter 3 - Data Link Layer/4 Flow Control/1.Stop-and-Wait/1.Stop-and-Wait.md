# Stop-and-Wait

## Definition

**Stop-and-Wait** is a communication technique in which the sender transmits **one frame at a time** and waits for an **Acknowledgement (ACK)** from the receiver before sending the next frame.

> **Send one frame → Wait for ACK → Send the next frame**

---

# Why is it Called Stop-and-Wait?

After sending one frame, the sender:

- **Stops** transmitting.
- **Waits** for an ACK from the receiver.

Only after receiving the ACK does it send the next frame.

---

# Working

```text
Sender                    Receiver

Frame 1  ------------->

          <----------- ACK

Frame 2  ------------->

          <----------- ACK

Frame 3  ------------->

          <----------- ACK
```

The sender never sends two frames simultaneously.

---

# Step-by-Step Process

1. Sender sends one frame.
2. Receiver receives the frame.
3. Receiver sends an ACK.
4. Sender receives the ACK.
5. Sender transmits the next frame.

This cycle repeats until all frames are transmitted.

---

# Characteristics

- Only **one outstanding frame** at any time.
- Sender waits after every transmission.
- Simple to implement.
- Reliable due to acknowledgements.
- Suitable for low-speed or simple communication systems.

---

# Advantages

- Simple protocol.
- Easy error detection.
- Reliable data delivery.
- Low memory requirement.
- Easy to implement.

---

# Disadvantages

- Low channel utilization.
- High waiting time.
- Poor performance on high-delay networks.
- Sender remains idle while waiting for ACK.

---

# Example

Suppose a sender wants to transmit three frames.

```text
Frame 1 → ACK

Frame 2 → ACK

Frame 3 → ACK
```

Each frame is acknowledged before the next one is sent.

---

# Applications

- Simple communication systems.
- Low-speed networks.
- Basic data transmission protocols.
- Foundation for Stop-and-Wait ARQ.

---

# Important Facts

- Only one frame is in transit at any time.
- Every transmitted frame requires an ACK.
- If the ACK is received, the next frame is sent.
- The sender cannot send another frame until the previous one is acknowledged.

---

# Common Mistakes

❌ Sender sends multiple frames before receiving an ACK.

✔ In Stop-and-Wait, only one frame can be outstanding.

---

❌ ACK is optional.

✔ Every successfully received frame must be acknowledged.

---

❌ Stop-and-Wait provides high throughput.

✔ It generally has low throughput because the sender spends time waiting for ACKs.

---
