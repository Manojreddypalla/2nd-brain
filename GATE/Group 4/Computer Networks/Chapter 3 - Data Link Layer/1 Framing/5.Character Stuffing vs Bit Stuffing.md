# 3.1.4 Character Stuffing vs Bit Stuffing

> [!info] Overview
> **Character Stuffing (Byte Stuffing)** and **Bit Stuffing** are two framing techniques used to distinguish **frame boundaries** from **actual data**.
>
> Both solve the same problem but use different approaches.

---

# Why Do We Need Stuffing?

Suppose the frame delimiter appears inside the actual data.

Example

```
FLAG
```

appears in the message itself.

Receiver cannot determine whether it is

- End of Frame
- Part of Data

Stuffing solves this ambiguity.

---

# Character Stuffing

## Definition

Character Stuffing inserts an **Escape Character (ESC)** before every occurrence of a special control character (such as FLAG or ESC) inside the data.

---

## Frame Format

```
FLAG | DATA | FLAG
```

Suppose

```
FLAG = F

ESC = E
```

Original Data

```
ABFCD
```

Sender

```
F A B E F C D F
```

Receiver

```
EF

↓

Treat F as DATA
```

Recovered Data

```
ABFCD
```

---

# Working

Sender

```
FLAG found

↓

Insert ESC
```

Receiver

```
ESC found

↓

Ignore ESC

↓

Treat next byte as data
```

---

# Characteristics

- Works on **bytes (characters)**
- Uses ESC character
- Suitable for character-oriented protocols

---

# Bit Stuffing

## Definition

Bit Stuffing inserts a **0 bit after every sequence of five consecutive 1s** in the data.

---

## Frame Format

```
FLAG

DATA

FLAG
```

FLAG

```
01111110
```

Original Data

```
111111
```

Sender

```
11111

↓

Insert 0

↓

1111101
```

Receiver

```
111110

↓

Remove 0
```

Recovered Data

```
111111
```

---

# Working

Sender

```
11111

↓

111110
```

Receiver

```
111110

↓

Remove stuffed 0
```

---

# Characteristics

- Works on bits
- No ESC character
- Used in bit-oriented protocols

---

# Side-by-Side Comparison

| Feature | Character Stuffing | Bit Stuffing |
|----------|-------------------|--------------|
| Also Called | Byte Stuffing | Bit Stuffing |
| Works On | Characters / Bytes | Individual Bits |
| Boundary Marker | FLAG Character | FLAG Bit Pattern |
| Escape Mechanism | ESC Character | Stuffed 0 Bit |
| Trigger | FLAG or ESC appears in data | Five consecutive 1s appear |
| Stuffed Item | ESC Byte | One 0 Bit |
| Receiver Action | Remove ESC | Remove Stuffed 0 |
| Overhead | Extra Bytes | Extra Bits |
| Suitable For | Character-Oriented Protocols | Bit-Oriented Protocols |
| Common Protocols | BISYNC, PPP (older implementations) | HDLC, SDLC, CAN |
| Reliability | Good | Better for binary communication |

---

# Advantages of Character Stuffing

- Easy to understand.
- Simple implementation.
- Good for text-based communication.

---

# Disadvantages of Character Stuffing

- Depends on character encoding.
- Cannot efficiently handle arbitrary binary data.
- More byte overhead.

---

# Advantages of Bit Stuffing

- Independent of character encoding.
- Suitable for any binary data.
- Used in modern high-speed protocols.
- More robust for bit-oriented communication.

---

# Disadvantages of Bit Stuffing

- Slight increase in frame size.
- Bit-by-bit processing required.

---

---

# Common Mistakes

> [!warning]
> Character Stuffing inserts **ESC bytes**, **not bits**.

---

> [!warning]
> Bit Stuffing inserts **0 bits**, **not ESC characters**.

---

> [!warning]
> Do **not** confuse **Byte Stuffing** with **Bit Stuffing**.
>
> One works on **bytes**, the other works on **bits**.

# Summary

Character Stuffing

- Works on bytes.
- Uses ESC.
- Suitable for character-oriented protocols.

Bit Stuffing

- Works on bits.
- Inserts a 0 after five consecutive 1s.
- Suitable for bit-oriented protocols.
- Used by protocols like HDLC.

---

# Revision Box

## Character Stuffing

- Uses ESC.
- Works on bytes.
- Character-oriented.
- Escapes FLAG and ESC characters.

---

## Bit Stuffing

- Uses stuffed 0.
- Works on bits.
- Bit-oriented.
- Stuffed after five consecutive 1s.

---

## One-Line Difference

> **Character Stuffing hides special characters using an ESC byte, whereas Bit Stuffing hides the FLAG pattern by inserting a 0 after every five consecutive 1s.**
