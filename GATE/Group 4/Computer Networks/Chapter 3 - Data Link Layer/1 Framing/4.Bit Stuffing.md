# 3.1.3 Bit Stuffing

> [!info] Definition
> **Bit Stuffing** is a framing technique used in **bit-oriented protocols** where the sender inserts a **0 bit after every sequence of five consecutive 1s** in the data. This prevents the receiver from confusing data bits with the frame delimiter (FLAG).

---

# Why Bit Stuffing?

Byte Stuffing works well for **character-oriented protocols**.

However, modern communication protocols (HDLC, CAN, USB, etc.) do not transmit characters—they transmit **bits**.

So instead of looking for special **characters**, they look for a special **bit pattern**.

---

# The Flag Pattern

Most bit-oriented protocols use the following **FLAG**.

```
01111110
```

This 8-bit pattern marks

- Beginning of Frame
- End of Frame

Example

```
01111110

DATA

01111110
```

Receiver simply looks for this pattern.

---

# The Problem

Suppose the data itself contains

```
01111110
```

Example

```
Data

101011111101010
```

Receiver cannot distinguish

- Actual Data
- Frame Boundary

This is exactly the same problem we saw in Byte Stuffing.

---

# Solution

Whenever the sender encounters

```
11111
```

inside the data,

it automatically inserts

```
0
```

This inserted zero is called the **Stuffed Bit**.

---

# Sender Rule

> [!important]
> **After every sequence of five consecutive 1s, insert one 0.**

Rule

```
11111

↓

111110
```

---

# Receiver Rule

Receiver continuously reads bits.

Whenever it sees

```
111110
```

it removes the stuffed

```
0
```

Original data is restored.

---

# Why Exactly Five 1s?

The FLAG is

```
01111110
```

Notice

```
01111110
     ↑
Six consecutive 1s?
```

Actually the FLAG contains

```
111111
```

between surrounding bits.

If the sender never allows **six consecutive 1s** inside the data,

then the FLAG pattern can **never appear accidentally**.

Therefore,

after five consecutive 1s,

the sender inserts a 0.

---

# Advantages

## 1. Highly Reliable

Frame delimiter never appears inside data.

---

## 2. No Reserved Characters

Works for any binary data.

---

## 3. Bit-Oriented

Independent of character encoding.

---

## 4. Used in Modern Protocols

Suitable for high-speed communication.

---

# Disadvantages

## 1. Extra Bits

Stuffed bits increase frame size.

---

## 2. Processing Required

Sender and receiver must examine every transmitted bit.

---

## 3. Variable Frame Length

Stuffing changes the transmitted size.

---

# Applications

Used in

- HDLC
- SDLC
- CAN Bus
- USB (conceptually similar bit-level techniques)
- Various WAN protocols

---

# Byte Stuffing vs Bit Stuffing

| Feature | Byte Stuffing | Bit Stuffing |
|----------|---------------|--------------|
| Unit | Bytes | Bits |
| Used In | Character-Oriented Protocols | Bit-Oriented Protocols |
| Special Marker | FLAG Character | FLAG Bit Pattern |
| Escape Method | ESC Character | Stuffed 0 Bit |
| Processing | Byte-by-Byte | Bit-by-Bit |

---

# Character Count vs Byte Stuffing vs Bit Stuffing

| Feature | Character Count | Byte Stuffing | Bit Stuffing |
|----------|-----------------|---------------|--------------|
| Boundary | Count Field | FLAG Character | FLAG Bit Pattern |
| Stuffing | ❌ No | ESC Byte | Stuffed 0 Bit |
| Reliable | ❌ Low | ✅ Better | ✅ Best |
| Modern Usage | Rare | Limited | Widely Used |

---

# Memory Trick

Think of a security guard.

The password is

```
01111110
```

Whenever someone says

```
11111
```

the guard immediately inserts

```
0
```

Now the complete password

```
01111110
```

can never accidentally occur inside the conversation.

Only the sender intentionally places the FLAG.

---

# Common Mistakes

> [!warning]
> Do **NOT** insert a 0 after **every** five 1s in the transmitted stream.
>
> Stuffing is performed **only on the data field**, not on the FLAG itself.

---

> [!warning]
> The receiver removes **only stuffed zeros**.
>
> It does **not** remove ordinary zeros that are part of the original data.

---

# Summary

- Bit Stuffing is used in **bit-oriented protocols**.
- FLAG pattern is **01111110**.
- Sender inserts **0 after every five consecutive 1s** in the data.
- Receiver removes the stuffed 0.
- Prevents accidental occurrence of the FLAG pattern.
- More reliable than Byte Stuffing for binary communication.
