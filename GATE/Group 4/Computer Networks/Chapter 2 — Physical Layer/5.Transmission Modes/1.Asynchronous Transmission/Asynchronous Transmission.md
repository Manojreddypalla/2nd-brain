
# Asynchronous Transmission (GATE Revision)

## Definition
- Data is transmitted **one character at a time**.
- **No common clock** between sender and receiver.
- Each character is framed independently using **Start** and **Stop** bits.

---

## Character Frame

```
| Start | Data (5–8 bits) | Optional Parity | Stop |
```

Example (8-bit data):

```
0 | 10110010 | 1 | 1
```

---

## Start Bit

- **Value = 0**
- Indicates **beginning of a character**
- Synchronizes the receiver
- Generated by transition **1 → 0**

---

## Stop Bit

- **Value = 1**
- Indicates **end of a character**
- Can be **1, 1.5, or 2 bits**
- Returns line to **Idle State**

---

## Character Framing

Frame consists of:

```
Start Bit
↓

Data Bits
↓

Optional Parity Bit
↓

Stop Bit
```

Purpose:
- Identifies start and end of every character.
- Allows receiver to correctly decode data.

---

## Characteristics

- No shared clock.
- Character-oriented transmission.
- Idle gaps allowed.
- Simple implementation.
- Higher overhead.

---

## Advantages

- Simple and inexpensive.
- No clock synchronization required.
- Good for low-speed/intermittent communication.

---

## Disadvantages

- Lower efficiency due to Start/Stop bits.
- Lower data rate.
- More transmission overhead.

---

## Applications

- UART
- RS-232
- Keyboard & Mouse
- GPS Modules
- Embedded Systems
- Serial Communication

---

## GATE Points ⭐

- **No common clock**
- **Start Bit = 0**
- **Stop Bit = 1**
- **Parity Bit = Optional**
- **Each character has its own frame**
- Idle gaps are allowed.

---

## Memory Trick 🧠

**0 → Start**
**1 → Stop**

"No Clock → Character-wise Transmission"

```
Idle → Start → Data → (Parity) → Stop → Idle
```

---

## One-Line Revision

**Asynchronous transmission sends one character at a time without a shared clock, using Start (0) and Stop (1) bits for framing.**
