# 8B/10B Block Coding

## Why 8B/10B?

Although **4B/5B** improves synchronization, high-speed communication systems also require:

- Better clock recovery
- No DC component
- Balanced number of positive and negative signals
- Limited consecutive identical bits (Run Length)

To achieve all these, **8B/10B Block Coding** was introduced.

It is widely used in high-speed serial communication.

---

# Intuition

Imagine you want to send **8 bits** of data.

Instead of sending them directly, you replace them with a carefully selected **10-bit code** that:

- Produces enough signal transitions
- Maintains nearly equal numbers of **1s** and **0s**
- Prevents long runs of identical bits

This makes transmission much more reliable.

---

# Definition

**8B/10B** is a **block coding technique** in which:

- Every **8-bit data block (1 Byte)** is converted into a **10-bit codeword**.
- The additional **2 bits** improve synchronization and maintain DC balance.

---

# How It Works

### Step 1

Take 8 data bits.

```text
10101100
```

↓

### Step 2

Convert them into a predefined 10-bit codeword.

```text
1001110100
```

↓

### Step 3

Transmit the 10-bit code using a line coding scheme.

---

# Why 10 Bits?

The extra bits help achieve:

- Clock synchronization
- DC balance
- Error detection (limited)
- Control characters
- Limited run length

---

# Running Disparity (Most Important Concept)

## What is Running Disparity?

Running Disparity (RD) is the **difference between the number of 1s and 0s transmitted over time**.

Example:

```text
11110000
```

```
1s = 4

0s = 4

RD = 0
```

Balanced.

---

Example

```text
11111100
```

```
1s = 6

0s = 2

RD = +4
```

Not balanced.

---

8B/10B continuously chooses codewords to keep the **running disparity close to zero**.

This eliminates the **DC component**.

---

# Characteristics

## 1. Block Coding

```
8 bits

↓

10 bits
```

---

## 2. DC Balanced

Almost equal number of **1s** and **0s**.

Average voltage becomes approximately **0 V**.

---

## 3. Better Synchronization

Frequent transitions allow the receiver to recover the clock.

---

## 4. Limited Run Length

Long sequences of identical bits are avoided.

This prevents synchronization loss.

---

## 5. Control Symbols

Besides normal data, 8B/10B also supports **special control characters (K-codes)** used for:

- Start of packet
- End of packet
- Idle symbols
- Link management

---

# Efficiency

Input

```
8 bits
```

Output

```
10 bits
```

Efficiency:

$$
\text{Efficiency}=\frac{8}{10}=0.8=80\%
$$

Overhead:

$$
\text{Overhead}=\frac{2}{8}\times100=25\%
$$

---

# Advantages

- Excellent clock synchronization.
- No DC component.
- Maintains running disparity.
- Reduces transmission errors.
- Supports control characters.
- Very reliable for high-speed links.

---

# Disadvantages

- 25% bandwidth overhead.
- More complex encoder/decoder.
- Lookup tables are required.

---

# Applications

Used in many high-speed communication standards:

- Gigabit Ethernet (1000BASE-X)
- PCI Express (Gen 1 & Gen 2)
- SATA
- Fibre Channel
- DisplayPort (early versions)
- USB 3.x (Gen 1 uses a different encoding, but 8B/10B is a classic reference in serial links)

# Common GATE Traps

❌ "8B/10B is line coding."

**Wrong.** It is **block coding**.

---

❌ "8B/10B provides full error correction."

**Wrong.** It mainly improves synchronization, DC balance, and offers limited error detection.

---

❌ "Running disparity means transmission speed."

**Wrong.** Running disparity is the **difference between transmitted 1s and 0s over time**.
