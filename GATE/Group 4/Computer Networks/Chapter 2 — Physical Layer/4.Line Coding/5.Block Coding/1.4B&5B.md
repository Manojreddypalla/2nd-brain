# 4B/5B Block Coding

## Why 4B/5B?

Some line coding schemes like **NRZ-I** have a major problem:

If there are **long sequences of 0s**, there are **no signal transitions**, making it difficult for the receiver to recover the clock (synchronization problem).

### Example

Data:

```text
0000000000
```

Using NRZ-I:

```text
──────────────
```

No transitions → Receiver may lose synchronization.

To solve this problem, **Block Coding** is used before line coding.

---

# Intuition

Imagine you're sending messages where **some patterns are forbidden** because they are difficult to understand.

Instead of sending the original message directly, you first **replace it with a better code** that guarantees enough transitions.

That's exactly what **4B/5B** does.

- Take **4 bits** of data.
- Convert them into **5 bits**.
- The new 5-bit code is carefully chosen so that there are enough 1s to create transitions.

---

# Definition

**4B/5B** is a **block coding technique** in which:

- Every **4-bit data block** is mapped to a **5-bit codeword**.
- The extra bit is **not for error correction**; it is added to improve synchronization.

---

# How It Works

### Step 1

Take 4 data bits.

```text
1010
```

↓

### Step 2

Replace them with a predefined 5-bit code.

```text
10110
```

↓

### Step 3

Transmit the 5-bit code using a line coding scheme (usually NRZ-I).

---

> **GATE Tip:** You are usually **not expected to memorize the entire table**. Know the concept and purpose.

---

# Why Does It Work?

The selected 5-bit codewords ensure:

- No codeword has **more than one leading 0**.
- No codeword has **more than two trailing 0s**.

Therefore, when transmitted using NRZ-I, frequent transitions occur, maintaining synchronization.

---

# Characteristics

## 1. Block Coding

Groups bits into fixed-size blocks.

```
4 bits

↓

5 bits
```

---

## 2. Improves Synchronization

More transitions are produced after line coding.

---

## 3. Reduces Long Runs of Zeros

The encoded data avoids long sequences without transitions.

---

## 4. Introduces Redundancy

One extra bit is added for every four bits.

---

# Efficiency

Input:

```
4 bits
```

Output:

```
5 bits
```

Efficiency:

$$
\text{Efficiency}=\frac{4}{5}=0.8=80\%
$$

Overhead:

$$
\text{Overhead}=\frac{1}{4}\times100=25\%
$$

---

# Advantages

- Improves synchronization.
- Eliminates long runs of zeros.
- Works well with NRZ-I.
- Some invalid codewords can help detect errors.

---

# Disadvantages

- Requires 25% extra bandwidth.
- Needs encoder and decoder lookup tables.
- Does not provide full error correction.

---

# Applications

- Fast Ethernet (100BASE-TX)
- FDDI (Fiber Distributed Data Interface)

---

# 4B/5B vs Line Coding

| Feature | 4B/5B | Line Coding |
|----------|--------|-------------|
| Type | Block Coding | Signal Encoding |
| Converts | 4 bits → 5 bits | Bits → Voltage Levels |
| Purpose | Improve synchronization | Generate electrical signal |
| Adds Redundancy | Yes | No |

# GATE Corner ⭐

- Improves synchronization by ensuring sufficient transitions.
- Efficiency = **80%**

# Common GATE Traps

❌ "4B/5B is a line coding technique."

**Wrong.** It is **block coding**.

---

❌ "The extra bit is for error correction."

**Wrong.** It is mainly for **better synchronization**.

---

❌ "4B/5B removes all errors."

**Wrong.** It only improves synchronization and allows limited error detection through invalid codewords.
