# What is an Array?

An **array** stores multiple values inside a single variable.

Instead of

```js
let tea1 = "Green Tea";
let tea2 = "Black Tea";
let tea3 = "Oolong Tea";
```

we write

```js
let teas = ["Green Tea", "Black Tea", "Oolong Tea"];
```

Think of an array as a row of numbered boxes.

```
Index

0          1          2
+---------+---------+---------+
| Green   | Black   | Oolong  |
+---------+---------+---------+
```

---

# Why Arrays?

Without arrays

- Hundreds of variables
    
- Difficult loops
    
- Hard searching
    

With arrays

- Store collections
    
- Easy iteration
    
- Easy searching
    
- Dynamic size

# Array Declaration

## Literal Syntax (Preferred)

```js

    "Oolong Tea"
```

Works the same.

Literal syntax is preferred.

# Array Indexing

Arrays start from **0**.

```
0 → First
1 → Second
2 → Third
```

Example

```js
let teas = [
    "Green",
    "Black",
    "Oolong"
];

console.log(teas[0]);
```

Output

```
Green
```

---

## Why start at 0?

Internally,

```
Address of array = 1000

Index 0
Address = 1000 + (0 × size)

Index 1
Address = 1000 + (1 × size)

Index 2
Address = 1000 + (2 × size)
```

Zero means

> "No offset from the beginning."

That makes indexing efficient.


# Soft Copy

```js
let a = [1,2,3];

let b = a;
```

Looks like copy.

Actually

```
a
 \
  ---> [1,2,3]
 /
b
```

Both variables point to the **same memory**.

Now

```js
a.pop();
```

Result

```
a

[1,2]

b

[1,2]
```

Both changed.

---

## Why?

Arrays are **reference types**.

Variables store

```
Reference

↓

Memory Address

↓

Actual Array
```

Not the actual array.

# shift()

Removes first element.

```js
arr.shift();
```

Before

```
A
B
C
```

After

```
B
C
```

Internally

Every remaining element shifts left.

```
A B C

↓

B C
```

Time Complexity

```
O(n)
```

---

# unshift()

Adds at front.

```js
arr.unshift("X");
```

Before

```
A
B
C
```

After

```
X
A
B
C
```

Every element shifts right.

```
A → index 1

B → index 2

C → index 3
```

Time Complexity

```
O(n)
```

# Common Array Methods

|Method|Purpose|Time|
|---|---|---|
|push()|Add at end|O(1)|
|pop()|Remove end|O(1)|
|shift()|Remove front|O(n)|
|unshift()|Add front|O(n)|
|concat()|Merge arrays|O(n)|
|slice()|Copy/Extract|O(n)|
|includes()|Search|O(n)|
|length|Size|O(1)|

# Important Interview Questions

### Q1 Why arrays start at index 0?

Because index is an offset from the starting memory address.

---

### Q2 Difference between push and unshift?

```
push()

Adds at end

O(1)
```

```
unshift()

Adds at beginning

O(n)
```

---

### Q3 Difference between pop and shift?

```
pop()

Removes last

O(1)
```

```
shift()

Removes first

O(n)
```

---

### Q4 Difference between soft copy and hard copy?

Soft copy shares the same reference.

Hard copy creates new memory.

---

### Q5 Why is `includes()` slower than indexing?

- `arr[2]` directly accesses a known position → **O(1)**
    
- `includes()` may scan every element until it finds a match → **O(n)**

## Pattern Recognition (for future DSA)

Even though this is JavaScript, these operations map directly to DSA concepts:

|JavaScript|DSA Concept|
|---|---|
|`push()`|Append to dynamic array (`vector::push_back`)|
|`pop()`|Remove last element|
|`shift()`|Delete first element (requires shifting)|
|`unshift()`|Insert at beginning (requires shifting)|
|`length`|`size()`|
|`includes()`|Linear Search|
|`concat()`|Merge two arrays|
|`[...arr]`|Copy constructor / array copy|

Once you start learning **vectors in C++**, you'll notice almost all of these ideas transfer directly—the syntax changes, but the underlying data structure and complexity remain the same.
