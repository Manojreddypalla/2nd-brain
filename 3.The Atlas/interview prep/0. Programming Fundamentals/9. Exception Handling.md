## Definition

**Exception Handling** is a mechanism to handle **runtime errors** gracefully without crashing the program.

> **Think:** Instead of the program terminating when something goes wrong, exceptions let you detect the problem, handle it, and continue or exit safely.

---

# Why Use Exception Handling?

- Prevents program crashes
    
- Separates normal logic from error handling
    
- Improves code readability
    
- Makes programs more robust
    

Examples:

- Division by zero
    
- File not found
    
- Invalid input
    
- Memory allocation failure
    

---

# Keywords

C++ uses three keywords:

- `try`
    
- `throw`
    
- `catch`
    

---

# Basic Syntax

```cpp
try
{
    // Code that may throw an exception
}
catch(...)
{
    // Handle exception
}
```

---

# Example

```cpp
#include <iostream>
using namespace std;

int main()
{
    try
    {
        throw 10;
    }
    catch(int x)
    {
        cout << "Exception: " << x;
    }
}
```

Output

```text
Exception: 10
```

---

# How Exception Flow Works

```text
try
 │
 │ Problem occurs
 ▼
throw
 │
 ▼
catch
 │
 ▼
Program Continues
```

---

# Example: Division by Zero

```cpp
int divide(int a, int b)
{
    if(b == 0)
        throw "Division by Zero";

    return a / b;
}
```

```cpp
try
{
    cout << divide(10, 0);
}
catch(const char* msg)
{
    cout << msg;
}
```

Output

```text
Division by Zero
```

# Standard Exceptions

C++ provides built-in exception classes.

```cpp
#include <stdexcept>

throw runtime_error("Something went wrong");
```

Catch

```cpp
catch(const exception &e)
{
    cout << e.what();
}
```

Output

```text
Something went wrong
```

Common standard exceptions:

- `runtime_error`
    
- `logic_error`
    
- `out_of_range`
    
- `invalid_argument`
    
- `bad_alloc`

# Stack Unwinding

One of the most important interview concepts.

Example

```cpp
void C()
{
    throw 1;
}

void B()
{
    C();
}

void A()
{
    B();
}
```

```cpp
int main()
{
    try
    {
        A();
    }
    catch(...)
    {
        cout << "Caught";
    }
}
```

Flow

```text
main()

↓

A()

↓

B()

↓

C()

↓

throw

↑

B destroyed

↑

A destroyed

↑

catch
```

During exception propagation, **all intermediate stack frames are destroyed automatically**.

This process is called **Stack Unwinding**.

---

# RAII (Resource Acquisition Is Initialization)

Modern C++ manages resources using objects.

Example

```cpp
void fun()
{
    vector<int> v(100);

    throw 1;
}
```

Even though an exception is thrown,

`vector` automatically frees its memory when leaving scope.

This is the idea behind **RAII**.

Advantages:

- No memory leaks
    
- Automatic cleanup
    
- Exception safe
    

Used heavily by STL and smart pointers.

# Custom Exception

```cpp
class MyException
{
public:
    const char* what() const
    {
        return "Custom Error";
    }
};
```

Throw

```cpp
throw MyException();
```

Catch

```cpp
catch(MyException e)
{
    cout << e.what();
}
```

Better practice:

```cpp
catch(const MyException &e)
```

Avoids unnecessary copying.

# Exception Specification

Old style

```cpp
void fun() throw(int);
```

Deprecated.

Modern C++

```cpp
void fun() noexcept;
```

`noexcept` tells the compiler the function will **not throw exceptions**.

---

# When NOT to Use Exceptions

Avoid exceptions for:

- Normal program flow
    
- Simple conditions
    
- Loop control
    

Good use cases:

- File opening failures
    
- Database errors
    
- Network failures
    
- Invalid operations
    
- Memory allocation failures

# Common Mistakes

## Catching by Value

```cpp
catch(exception e)
```

Creates a copy.

Better

```cpp
catch(const exception &e)
```

---

## Throwing Raw Pointers

Avoid

```cpp
throw new exception();
```

Prefer

```cpp
throw runtime_error("Error");
```

---

## Ignoring Exceptions

```cpp
catch(...)
{
}
```

Never silently ignore exceptions unless you have a good reason.

# Common Interview Questions

### Q1. What is an exception?

An exception is a runtime event that interrupts the normal flow of a program.

---

### Q2. Difference between syntax errors and exceptions?

|Syntax Error|Exception|
|---|---|
|Compile-time|Runtime|
|Prevents compilation|Occurs during execution|

---

### Q3. What is Stack Unwinding?

The process of automatically destroying local objects while propagating an exception up the call stack until a matching `catch` block is found.

---

### Q4. Why catch exceptions by reference?

- Avoids object copying
    
- Preserves polymorphism
    
- More efficient
    

Preferred form:

```cpp
catch(const exception &e)
```

---

### Q5. What is RAII?

A C++ design principle where resources are tied to object lifetime, ensuring automatic cleanup when objects go out of scope.

---

### Q6. What does `noexcept` mean?

It indicates that a function is not expected to throw exceptions, enabling certain compiler optimizations.

---

### Q7. What happens if no `catch` block handles an exception?

The program calls `std::terminate()` and terminates.

---

# Time & Space Complexity

Exception handling has **no extra cost during normal execution** in most modern C++ implementations ("zero-cost" exception model).

When an exception is thrown:

|Operation|Complexity|
|---|---|
|`try` block (normal path)|`O(1)` overhead|
|Throwing an exception|Depends on stack depth|
|Stack unwinding|`O(N)` (N = call stack depth)|

---

# Interview Summary

- Exception handling manages **runtime errors** using `try`, `throw`, and `catch`.
    
- `throw` transfers control to the nearest matching `catch`.
    
- Multiple `catch` blocks can handle different exception types.
    
- **Stack unwinding** automatically destroys local objects during exception propagation.
    
- **RAII** ensures resources are released automatically, making code exception-safe.
    
- Catch exceptions by **`const` reference** to avoid copying and preserve polymorphism.
    
- Prefer standard exception classes like `runtime_error` and use `noexcept` for functions that are guaranteed not to throw.
    
- If an exception isn't caught, the program terminates via `std::terminate()`.
