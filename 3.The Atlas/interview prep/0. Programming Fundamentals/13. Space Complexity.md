## Definition

**Space Complexity** measures **how much memory an algorithm uses as the input size (N) grows.**

> **Think:** Time Complexity asks **"How long does it take?"**  
> Space Complexity asks **"How much memory does it need?"**

---

# Why Space Complexity?

Two algorithms may have the same time complexity but use very different amounts of memory.

Example:

Algorithm A

```text
Time : O(N)

Space : O(1)
```

Algorithm B

```text
Time : O(N)

Space : O(N)
```

Algorithm A is usually preferred because it uses less memory.

---

# Types of Memory Used

Space Complexity includes:

- Variables
    
- Arrays
    
- Objects
    
- Function Call Stack
    
- Dynamic Memory (Heap)
    

It **does not** usually include the memory occupied by the input itself unless specifically asked.

---

# Total Space

```text
Total Space

=

Input Space

+

Auxiliary Space
```

---

# Auxiliary Space

**Auxiliary Space** is the **extra memory used by the algorithm**, excluding the input.

Interviewers often ask for **Auxiliary Space** instead of total space.

Example

```cpp
int sum = 0;

for(int i = 0; i < n; i++)
{
    sum += arr[i];
}
```

Extra memory:

```text
sum

i
```

Only two variables.

Auxiliary Space

```text
O(1)
```

---

# O(1) Space

Constant extra memory.

```cpp
int max = arr[0];

for(int i = 1; i < n; i++)
{
    if(arr[i] > max)
        max = arr[i];
}
```

Extra variables:

```text
max

i
```

Space

```text
O(1)
```

---

# O(N) Space

Extra memory grows with input size.

```cpp
int copy[n];

for(int i = 0; i < n; i++)
{
    copy[i] = arr[i];
}
```

Extra array:

```text
copy

Size = N
```

Space

```text
O(N)
```

---

# O(N²) Space

2D array.

```cpp
int matrix[n][n];
```

Memory

```text
N × N
```

Space

```text
O(N²)
```

---

# Space Used by Recursion

Each recursive call creates a **new stack frame**.

Example

```cpp
void fun(int n)
{
    if(n == 0)
        return;

    fun(n - 1);
}
```

Call Stack

```text
fun(3)

↓

fun(2)

↓

fun(1)

↓

fun(0)
```

Four stack frames.

Space

```text
O(N)
```

# In-Place Algorithms

Modify data without significant extra memory.

Example

Reverse Array

```cpp
for(int i = 0; i < n/2; i++)
{
    swap(arr[i], arr[n-i-1]);
}
```

No extra array.

Space

```text
O(1)
```

---

# Not In-Place

```cpp
int temp[n];

for(...)
```

Creates another array.

Space

```text
O(N)
```

# Time vs Space Trade-Off

Sometimes we use **more memory to make the algorithm faster**.

Example

Without HashMap

```text
Time

O(N²)

Space

O(1)
```

With HashMap

```text
Time

O(N)

Space

O(N)
```

Very common interview optimization.

# Common Mistakes

## Mistake 1

Counting Input Array

```cpp
int arr[n];
```

Usually **not counted** because it's the given input.

Only count **extra memory** unless the question explicitly asks for total space.

---

## Mistake 2

Ignoring Recursion Stack

Recursive algorithms consume stack memory.

```cpp
factorial(n)
```

Space

```text
O(N)
```

Not

```text
O(1)
```

---

## Mistake 3

Thinking Loops Increase Space

```cpp
for(...)
```

Loops increase **time**, not **space**.

Only new memory allocations affect space complexity.

# Common Interview Questions

### Q1. What is Space Complexity?

The amount of memory an algorithm uses as the input size grows.

---

### Q2. Difference between Input Space and Auxiliary Space?

|Input Space|Auxiliary Space|
|---|---|
|Memory occupied by the input|Extra memory used by the algorithm|

---

### Q3. Why does recursion use `O(N)` space?

Each recursive call creates a new stack frame, increasing memory usage linearly with recursion depth.

---

### Q4. What is an In-Place algorithm?

An algorithm that uses **constant (`O(1)`) extra memory** (or only a very small amount independent of input size).

---

### Q5. Why is Merge Sort `O(N)` space?

Because it allocates a temporary array during the merge step.

---

### Q6. Difference between Iterative and Recursive Binary Search?

|Iterative|Recursive|
|---|---|
|Space: `O(1)`|Space: `O(log N)`|
|No call stack|Uses recursion stack|

---

### Q7. Can we improve time by increasing space?

Yes. Many algorithms use additional memory (like hash tables) to reduce running time. This is called a **time-space trade-off**.

# Complexity Cheat Sheet

|Pattern|Space|
|---|---|
|Few variables|`O(1)`|
|Extra array of size N|`O(N)`|
|2D Matrix|`O(N²)`|
|Recursive depth N|`O(N)`|
|Recursive depth log N|`O(log N)`|
|HashMap|`O(N)`|
|Vector|`O(N)`|

---

# Interview Summary

- **Space Complexity** measures how memory usage grows with input size.
    
- Focus on **auxiliary space** unless the question explicitly asks for total space.
    
- Variables consume **`O(1)`** space; arrays, vectors, and hash maps typically consume **`O(N)`**.
    
- Recursive algorithms use additional **call stack memory** proportional to recursion depth.
    
- **In-place algorithms** use constant extra memory and are often preferred.
    
- Be aware of the **time-space trade-off**—using extra memory can significantly improve runtime.
    
- Don't count the input itself unless instructed; count only the **additional memory** your algorithm allocates.
