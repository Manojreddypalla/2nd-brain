## Definition

**Scope** determines **where a variable or function can be accessed** in a program.

> **Think:** Scope is the **visibility** of a variable.

---

# Why is Scope Important?

- Prevents naming conflicts
    
- Controls data access
    
- Improves code organization
    
- Reduces bugs
    
- Supports encapsulation
    

---

# Types of Scope

- Local Scope
    
- Global Scope
    
- Block Scope
    
- Function Scope
    
- Namespace Scope
    

---

# 1. Local Scope

A variable declared **inside a function**.

```cpp
void fun()
{
    int x = 10;

    cout << x;
}
```

✔ Accessible only inside `fun()`.

---

## Memory Visualization

```text
fun()

──────────────
x = 10
──────────────
```

When the function ends:

```text
x is destroyed.
```

---

# 2. Global Scope

Declared **outside all functions**.

```cpp
int x = 100;

int main()
{
    cout << x;
}
```

Output

```text
100
```

Accessible from any function (unless shadowed).

---

## Memory

Global variables are created **before `main()` starts** and destroyed **after the program ends**.

---

# Local vs Global

|Local|Global|
|---|---|
|Inside function|Outside functions|
|Limited access|Accessible everywhere|
|Destroyed after function ends|Lives for entire program|
|Preferred|Use sparingly|

---

# 3. Block Scope

A variable declared inside `{}`.

```cpp
if(true)
{
    int x = 5;
}
```

Outside:

```cpp
cout << x;
```

Compilation Error

Because `x` exists only inside that block.

---

Example

```cpp
for(int i = 0; i < 5; i++)
{
}
```

`i` cannot be used after the loop.

---

# Variable Shadowing

A local variable hides a global variable with the same name.

```cpp
int x = 100;

int main()
{
    int x = 50;

    cout << x;
}
```

Output

```text
50
```

The local `x` shadows the global `x`.

---

# Access Global Variable

Use the **scope resolution operator**.

```cpp
int x = 100;

int main()
{
    int x = 50;

    cout << ::x;
}
```

Output

```text
100
```

`::x` refers to the global variable.

---

# Function Scope

Parameters and variables declared inside a function belong only to that function.

```cpp
void add(int a, int b)
{
    int sum = a + b;
}
```

`a`, `b`, and `sum` cannot be accessed outside `add()`.

---

# Lifetime vs Scope

Many beginners confuse these.

## Scope

Where a variable can be accessed.

## Lifetime

How long the variable exists in memory.

Example

```cpp
void fun()
{
    int x = 10;
}
```

|Property|Value|
|---|---|
|Scope|Inside `fun()`|
|Lifetime|Until `fun()` ends|

---

# Static Local Variable

Normally:

```cpp
void fun()
{
    int x = 0;

    x++;

    cout << x;
}
```

Calling three times:

```text
1
1
1
```

Because `x` is recreated every call.

---

Using `static`

```cpp
void fun()
{
    static int x = 0;

    x++;

    cout << x;
}
```

Output

```text
1
2
3
```

The variable is initialized **only once** and retains its value between function calls.

---

## Memory Visualization

Without `static`

```text
Call 1

x = 0

Destroy

Call 2

x = 0

Destroy
```

---

With `static`

```text
Program Starts

x = 0

↓

Call 1

x = 1

↓

Call 2

x = 2

↓

Call 3

x = 3
```

Destroyed only when the program ends.

---

# Storage Classes (Interview Basics)

|Keyword|Scope|Lifetime|
|---|---|---|
|auto|Local|Function call|
|static|Local/Global|Entire program|
|extern|Global|Entire program|
|register _(deprecated)_|Local|Function call|

---

# Namespace Scope

Namespaces avoid naming conflicts.

```cpp
namespace A
{
    int x = 10;
}

namespace B
{
    int x = 20;
}
```

Access

```cpp
cout << A::x;

cout << B::x;
```

Output

```text
10
20
```

---

# Best Practices

✔ Keep variables in the smallest possible scope.

✔ Avoid unnecessary global variables.

✔ Use `const` for values that should not change.

✔ Use namespaces to organize large projects.

# Common Interview Questions

### Q1. What is scope?

The region of a program where a variable or function can be accessed.

---

### Q2. Difference between Scope and Lifetime?

|Scope|Lifetime|
|---|---|
|Accessibility|Existence in memory|

---

### Q3. What is variable shadowing?

When a local variable hides another variable (typically global) with the same name.

---

### Q4. Difference between Local and Global variables?

|Local|Global|
|---|---|
|Function/Block only|Whole program|
|Short lifetime|Entire program|
|Preferred|Use carefully|

---

### Q5. What is a `static` local variable?

A local variable that is initialized only once and retains its value between function calls.

---

### Q6. What does `::` mean?

The **scope resolution operator**. It is used to access global variables, namespace members, or class members.

---

### Q7. Why avoid global variables?

- Harder to debug
    
- Hidden dependencies
    
- Increased coupling
    
- Higher risk of accidental modification
    

---

# Time & Space Complexity

Scope itself doesn't affect algorithmic complexity.

Accessing any variable:

- **Time:** `O(1)`
    
- **Space:** Depends on the variable's type, not its scope.
    

---

# Interview Summary

- **Scope** determines where a variable is accessible.
    
- **Lifetime** determines how long it exists in memory.
    
- Local variables are temporary; global variables live for the program's lifetime.
    
- Variables declared inside `{}` have **block scope**.
    
- **Variable shadowing** occurs when a local variable hides a global one.
    
- Use `::` to access a shadowed global variable.
    
- `static` local variables preserve their value across function calls.
    
- Prefer local variables and keep scope as small as possible for cleaner, safer code.
