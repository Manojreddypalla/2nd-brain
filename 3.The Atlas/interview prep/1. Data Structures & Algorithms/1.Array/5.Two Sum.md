# Arrays — Two Sum

## Definition

**Two Sum** is the problem of finding **two elements in an array whose sum equals a given target**.

> **Think:** Instead of checking every pair, remember what you've already seen.

---

# Problem Statement

Given

```text
Array = [2, 7, 11, 15]

Target = 9
```

Find two numbers whose sum is **9**.

Answer

```text
2 + 7 = 9
```

Indices

```text
[0, 1]
```

---

# Why Two Sum?

Used in:

- Hashing
    
- Pair Finding
    
- Financial Analysis
    
- Scheduling Problems
    
- Interview Problems
    

It is one of the **most frequently asked interview questions**.

---

# Brute Force Approach

Check every possible pair.

```cpp
#include <iostream>
using namespace std;

pair<int, int> twoSum(int arr[], int n, int target)
{
    for(int i = 0; i < n; i++)
    {
        for(int j = i + 1; j < n; j++)
        {
            if(arr[i] + arr[j] == target)
                return {i, j};
        }
    }

    return {-1, -1};
}
```

### Time Complexity

```text
O(N²)
```

### Space Complexity

```text
O(1)
```

---

# Optimal Approach (HashMap)

### Idea

For every element:

```text
Complement = Target - Current Element
```

If the complement already exists in the HashMap,

```text
Answer Found
```

Otherwise,

```text
Store Current Element
```

---

# Algorithm

```text
Current = 7

↓

Target = 9

↓

Need = 2

↓

Is 2 already seen?

↓

Yes

↓

Return Answer
```

---

# Code

```cpp
#include <iostream>
#include <unordered_map>
using namespace std;

pair<int, int> twoSum(int arr[], int n, int target)
{
    unordered_map<int, int> mp;

    for(int i = 0; i < n; i++)
    {
        int need = target - arr[i];

        if(mp.find(need) != mp.end())
            return {mp[need], i};

        mp[arr[i]] = i;
    }

    return {-1, -1};
}
```

# Sorting Approach

Another approach:

1. Sort array
    
2. Use Two Pointers
    

```text
Left

↓

1 2 3 5 7 8

          ↑

        Right
```

If

```text
Sum < Target

Move Left
```

If

```text
Sum > Target

Move Right
```

Time

```text
O(N log N)
```

Space

```text
O(1)
```

**Note:** Sorting changes the order of elements, so this approach doesn't directly return the original indices unless additional information is stored.

# Common Mistakes

## Using Same Element Twice

Wrong

```cpp
if(arr[i] + arr[i] == target)
```

Always use **two different indices**.

---

## Storing Before Checking

Wrong

```cpp
mp[arr[i]] = i;

if(mp.find(target - arr[i]) != mp.end())
```

This can incorrectly use the current element itself when `target == 2 * arr[i]`.

Correct

```cpp
Check First

↓

Store Later
```

---

## Forgetting Duplicate Values

Example

```text
3 3

Target = 6
```

HashMap solution handles duplicates correctly because it checks before inserting the current element.

# Common Interview Questions

### Q1. What is the optimal solution?

Using a **HashMap**.

Time

```text
O(N)
```

Space

```text
O(N)
```

---

### Q2. Why use a HashMap?

It allows checking whether the required complement exists in **average O(1)** time.

---

### Q3. Why check before inserting?

To avoid matching the current element with itself.

---

### Q4. Can Two Sum be solved without extra space?

Yes.

Sort the array and use the **Two Pointer** technique.

Time

```text
O(N log N)
```

Space

```text
O(1)
```

However, preserving original indices requires additional bookkeeping.

---

### Q5. Which solution is preferred in interviews?

If the array is **unsorted**, the **HashMap solution** is generally expected because it achieves **O(N)** time.

---

### Q6. What if there are multiple valid pairs?

Return whichever pair the problem specifies (usually the first found), or collect all pairs if the problem asks for all solutions.

---

# Time & Space Complexity

|Approach|Time|Space|
|---|---|---|
|Brute Force|`O(N²)`|`O(1)`|
|Sorting + Two Pointers|`O(N log N)`|`O(1)`*|
|HashMap|`O(N)` average|`O(N)`|

> *Ignoring any extra storage needed to preserve original indices.

---

# Interview Summary

- **Two Sum** asks for two numbers whose sum equals a target.
    
- The brute-force solution checks every pair in **`O(N²)`** time.
    
- The optimal solution uses a **HashMap** to store previously seen values and find complements in **average `O(1)`** time.
    
- Always **check for the complement before inserting** the current element.
    
- If only values matter and sorting is allowed, the **Two Pointer** approach after sorting is another common solution.
